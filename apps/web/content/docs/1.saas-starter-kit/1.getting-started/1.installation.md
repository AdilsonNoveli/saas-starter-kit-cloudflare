## 1. Install Bun

```bash
curl -fsSL https://bun.sh/install | bash
```

On Windows without WSL: `npm install -g bun`.

**Prompt for AI agents:**
```text

Check for Bun with bun --version. If it's missing, run
curl -fsSL https://bun.sh/install | bash (Windows without WSL:
npm install -g bun), then confirm the version again before continuing.

```

## 2. Get the codebase and install

Download the Nuxfire monorepo directly from your **Members Area** after purchase, extract it to your preferred workspace directory, and install dependencies:

```bash
cd nuxfire
bun install
```

The first `bun install` takes a few minutes — it hasn't hung. Always run it inside the extracted folder and never copy a `node_modules` folder from another machine or project: the workspace links (`@nuxfire/*`) can break, and the deploy preflight ([Deploy](/docs/saas-starter-kit/getting-started/deploy)) reports it if they do.

*(Optional: Initialize your own private Git repository for version control)*:

```bash
git init
git add .
git commit -m "Initial commit from Nuxfire"
```

Migrations are already versioned in `apps/functions/src/database/migrations/`. You only need to generate new ones if you change `apps/functions/src/database/core-schema.ts` or any layer's `server/database/schema.ts` (`drizzle.config.ts` reads both, not the `schema.ts` barrel — that file only re-exports them):

```bash
cd apps/functions
DATABASE_HOST=... DATABASE_PORT=5432 DATABASE_USER=... DATABASE_PASSWORD=... DATABASE_NAME=... \
  bunx drizzle-kit generate
```

(No `DATABASE_URL` — `drizzle.config.ts` reads host/port/user/password/name separately, so you never have to build or escape a URL containing a password.)

**Prompt for AI agents:**
```text
In the extracted nuxfire project root, run: bun install
Only run bunx drizzle-kit generate (from apps/functions) if
core-schema.ts or a layer's server/database/schema.ts changed — ask
the user for their real DATABASE_HOST/PORT/
USER/PASSWORD/NAME first, never invent placeholder values.
```
