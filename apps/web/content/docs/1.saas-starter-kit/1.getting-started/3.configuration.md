Fill in your domain and feature flags. Set `prodDomain` to your real domain — it is the only line you must edit: `devDomain`, `authEmailDomain` and the sender address all derive from it. The domain must be an active zone in the same Cloudflare account that owns your API token. Also disable in `flags` any integration you won't use (Stripe, Paddle, websockets, queues, whichever email providers you don't need) — this reduces how many secrets you have to configure.

`authEmail.name` is your brand name in the emails Nuxfire sends (subject lines and logo alt text), and the sender's domain must be verified in your email provider. The emails' logo is loaded from `https://<prodDomain>/pwa-192x192.png`, which the `web` app serves.

```typescript [config.ts]
export const prodDomain = "yourdomain.com"; // the only line you must edit
export const devDomain = `dev.${prodDomain}`;
export const authEmailDomain = prodDomain;
export const authEmail = {
  name: "Your Company",
  address: `contact@${authEmailDomain}`,
};

export const flags: {
  stripe?: boolean;
  paddle?: boolean;
  googleAuth?: boolean;
  githubAuth?: boolean;
  resend?: boolean;
  mailgun?: boolean;
  ses?: boolean;
  sparkPost?: boolean;
  smtp?: boolean;
  websockets?: boolean;
  cron?: boolean;
  jobsQueue?: boolean;
} = {
  stripe: true,
  paddle: true,
  githubAuth: true,
  googleAuth: true,
  resend: true,
  websockets: true,
  jobsQueue: true,
};
```

The same file also declares `layers` — separate from `flags`, and about the Nuxt Layers that get compiled into `apps/app` at all, not about which Cloudflare resources get provisioned:

```typescript [config.ts]
export const layers = {
  // Always extended, never toggleable — every tenant needs them.
  core: ["teams", "billing", "notifications", "admin"] as string[],

  // Toggleable per build/deploy. `false` drops the layer's pages, components
  // and Nuxt config from the bundle entirely — it does NOT drop its tables
  // from the database schema (see Database).
  features: {
    kanban: true,
  } satisfies Record<string, boolean>,
};
```

`core` lists the four business-domain layers every deployment ships (multi-tenancy/RBAC, billing, notifications, the platform admin console) — see [Project Structure](/docs/saas-starter-kit/getting-started/project-structure). `features` is where an optional layer like `kanban` gets turned off for a build that doesn't need it.

**Prompt for AI agents:**
```text
Open config.ts. Ask the user for their real domain and which
integrations they want before editing prodDomain (devDomain and
authEmailDomain derive from it — leave those lines as they are),
authEmail, and the flags object — do not guess or invent any of
these values. Only touch layers.features if the user explicitly asks to
disable an optional layer (e.g. kanban) — never touch layers.core.
```
