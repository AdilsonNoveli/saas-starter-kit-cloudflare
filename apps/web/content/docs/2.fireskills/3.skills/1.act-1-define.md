Act I turns an idea into a validated spec and ends with the **Definition Gate**. Each skill has a step-by-step page with the exact prompt to type; this page is the reference.

| Skill | Asks questions | Creates or changes | Step page |
|---|---|---|---|
| `fireskill-01-inbox` | no | `specs/inbox/<AAAA-MM-DD-HHMMSS>-<slug>.md` | [Step 1](/docs/fireskills/getting-started/step-inbox) |
| `fireskill-02-backlog` | yes, one per round, up to 8 per area | `specs/backlog/<NNNN>-<slug>.md` (`BACKLOG-NNNN`) | [Step 2](/docs/fireskills/getting-started/step-backlog) |
| `fireskill-03-specify` | only by going back to the backlog | `specs/draft/<NNNN>-<slug>/spec.md` | [Step 3](/docs/fireskills/getting-started/step-specify) |
| `fireskill-04-validate` | only by going back to the backlog | the header and section 13 of the spec; moves it to `specs/defined/` | [Step 4](/docs/fireskills/getting-started/step-validate) |

## `fireskill-01-inbox`

Preserves your text word for word, with a SHA-256 of the original and a preliminary analysis split into statement, inference and to-review. Refuses to save if it finds credentials, tokens or obvious personal data. Does **not** start the next step by itself. Script: `capturar_inbox.mjs --title --input`.

## `fireskill-02-backlog`

Searches inbox, backlog, specs and `docs/` for duplicates, checks the minimum capture (problem, person, result, context), creates the item with `iniciar_backlog.mjs` and deepens decisions by numbered questions. The inbox file is only referenced, never moved or changed. Statuses: `Captured`, `Refining`, `Ready for specification`, `Promoted`. Screens add an `Interface` area; stored information hands off to `$fireskill-data-discovery`. Ends with a *Brief pronto para especificar* and hands off to `$fireskill-03-specify`.

## `fireskill-03-specify`

Creates the spec from the template (`iniciar_spec.mjs`), fills the three acts and 18 sections, and defines at least three `AC` for the feature and for each `US`, `FR` and `NFR`. Self-checks with `validate_spec.mjs --allow-draft` and hands off to `$fireskill-04-validate`. Structure: [The Canonical Spec](/docs/fireskills/methodology/canonical-spec).

## `fireskill-04-validate`

Runs `validate_spec.mjs`, does a semantic review and returns `READY` or `NOT READY`. On `READY`: `Definition Gate: Passed`, `Status: Defined`, `bun run fireskill transition <id> defined`, hand-off to `$fireskill-05-tasks`. On `NOT READY`: `Definition Gate: Failed`, `Status: Draft`, and back to `$fireskill-02-backlog`, `$fireskill-03-specify` or `$fireskill-update-spec`. It also does the final acceptance in Act III. Its repository check is:

```bash
node fireskills/skills/fireskill-04-validate/scripts/verify_repo.mjs .
```

which validates every spec in the repository and the contract of every `fireskill-*` skill (each needs `SKILL.md` and `agents/openai.yaml`).
