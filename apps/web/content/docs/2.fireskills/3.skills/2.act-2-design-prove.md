Act II turns the defined spec into a plan and proves it with tests that fail for the right reason. It ends with the **Plan Gate**.

| Skill | Creates or changes | Step page |
|---|---|---|
| `fireskill-05-tasks` | sections 14 and 15 of `spec.md`; moves it to `specs/planned/` | [Step 5](/docs/fireskills/getting-started/step-tasks) |
| `fireskill-06-tdd-bdd` | Vitest test files next to the code; the evidence table of the spec | [Step 6](/docs/fireskills/getting-started/step-tdd-bdd) |

## `fireskill-05-tasks`

Requires `Definition Gate: Passed` and `Status: Defined`. Replaces only sections 14 and 15 of the same `spec.md`. Task format:

```markdown
- [ ] T002 [CODE] [US-001] Implementar validação em layers/teams/server/trpc/teams.ts — Refs: FR-002, AC-003 — Depends: T001
```

Tags after the ID: `[P]`, `[TEST]`, `[TDD]`, `[CODE]`, `[DOC]`, `[OPS]`, `[US-NNN]`, and `[MIGRATION]` together with `[CODE]` or `[OPS]`. Every task has the checklist `PREP`, `EXECUTE`, `VERIFY`, `VISUAL`, `EVIDENCE`, `IMPROVE`, in that order. Validators: `validate_tasks.mjs` and, for screens, `validate_interface_tasks.mjs`.

## `fireskill-06-tdd-bdd`

Modes `prepare` (first RED, no production code), `cycle` (RED → GREEN → REFACTOR) and `verify` (suites and traceability). The Gherkin of the spec is the reference; no `.feature` file exists. Every executable case carries its own marker as a comment beside it:

```ts
// SPECSFY: US-001 FR-001 AC-001
```

At least three distinct cases for the feature and for each `US`, `FR` and `NFR`. Tests are Vitest (`bun run test`), and no test runs unless `check_database_safety.mjs` classifies the command as `SAFE`. Traceability: `check_traceability.mjs`.

## Sealing the Plan Gate

`$fireskill-05-tasks` sets `Plan Gate: Passed`, `Status: Planned` and runs `bun run fireskill transition <id> planned`. See [Quality Gates](/docs/fireskills/methodology/three-gates).
