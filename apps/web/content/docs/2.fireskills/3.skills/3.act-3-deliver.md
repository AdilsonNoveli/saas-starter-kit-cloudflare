Act III turns the plan into verified code and ends with the **Delivery Gate**.

| Skill | Creates or changes | Step page |
|---|---|---|
| `fireskill-07-implement` | production code, tests, checklists and evidence in the spec, `.specsfy/*` | [Step 7](/docs/fireskills/getting-started/step-implement) |
| `fireskill-documentator` | `docs/` (repository root) and `.specsfy/PACKAGES.md` | [Step 8](/docs/fireskills/getting-started/step-documentator) |
| `fireskill-progress` | nothing (projects the state) | [Other entry points](/docs/fireskills/getting-started/other-entry-points) |

## `fireskill-07-implement`

Runs one task at a time (`next_task.mjs` picks it), loading the specialist of the area before touching code, and checks each checklist item as its evidence appears. Moves the spec to `in-progress` at the start and to `review` when the Delivery Gate passes; `$fireskill-04-validate` then accepts it into `completed`. Completion check:

```bash
bun run test                       # repository root
cd apps/app
bun run typecheck
bunx vue-tsc --noEmit -p server/tsconfig.json
```

plus the context monitor and `build_documentation.mjs --check`. `bun run typecheck` is a script of `apps/app`; the root has none.

## `fireskill-documentator`

Rebuilds `docs/` and `.specsfy/PACKAGES.md` from the code with `build_documentation.mjs` (`--check` proves it is current). It runs after every `[CODE]` task. It does not write the public docs of this site (`apps/web/content/docs/`).

## `fireskill-progress`

Projects the state; it changes no gate and no checkbox.

```bash
bun run fireskill progress
```

Real output on a project with one spec:

```text
Resumo	1 specs	0/6 tarefas	0/55 itens	0%
0001-convite-de-membros-por-e-mail	Draft	0/6 tarefas	0/55 itens	0%
```

`--json` and `--watch` are available. The skill also offers `progress.mjs` and `analyze_context.mjs` (context cost of one spec, always labeled `estimated` unless measured usage is given).
