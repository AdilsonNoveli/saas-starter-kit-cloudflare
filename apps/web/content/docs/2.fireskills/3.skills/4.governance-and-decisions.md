Beyond the linear flow, these skills keep the context, the milestones and the quality of decisions. The prompts to type are on [Other entry points](/docs/fireskills/getting-started/other-entry-points).

## Setup and change

| Skill | Purpose |
|---|---|
| `fireskill-setup` | Reconciles `.fireskills/*` and the reserved blocks of `AGENTS.md`/`CLAUDE.md`, asks your knowledge level and the still-unanswered subjects, runs the monitor. Every flow skill loads it first. [Step 0](/docs/fireskills/getting-started/step-setup) |
| `fireskill-update-spec` | Incorporates a change into a spec that already passed the Definition Gate and reopens only the affected acts. [Late changes](/docs/fireskills/getting-started/late-changes) |
| `fireskill-interviewer` | Conversation about a spec in `draft`, `defined`, `planned`, `in-progress` or `review`; records confirmed answers and adjusts Effort. Approves no gate and moves no folder. |
| `fireskill-data-discovery` | Asks in everyday language what the product must store and records confirmed answers in `.fireskills/DATABASE.md`. |

## Milestones

| Skill | Purpose |
|---|---|
| `fireskill-mvp-milestone-interviewer` | Imports an `MVP.md` (at the repository root) as milestone `M01` and creates backlog items and `Draft` specs for development requirements. |
| `fireskill-roadmap-milestone-interviewer` | After the MVP is accepted, interviews the evolution and proposes post-MVP milestones without changing the accepted core silently. |
| `fireskill-milestone-governor` | Keeps the derived index (`specs.md`) and milestone links up to date, and only suggests changes. |

## Context maintenance

`fireskill-aux-stack` (`.fireskills/STACK.md`), `fireskill-aux-rules` (`.fireskills/RULES.md`) and `fireskill-aux-database` (`.fireskills/DATABASE.md`) add to those files without deleting what you wrote. See [Project Context](/docs/fireskills/getting-started/project-context).

## Lessons learned: `fireskill-lessons`

Turns a real failure into a preventive rule. State lives in `.fireskills/lessons.json` (owned by the engine) and `.fireskills/LESSONS.md` (playbook read by agents before writing specs or tasks).

| Signal | Meaning |
|---|---|
| `ac_gap` | an acceptance criterion was not covered or failed in production |
| `surviving_mutant` | a test still passed after a logic mutation |
| `spec_precision_gap` | an ambiguity in the spec led to a wrong implementation |
| `spec_deviation` | the implementation diverged from the plan or the conventions |
| `gate_fail` | a gate check failed (typecheck, lint, Vitest) |

A lesson is `candidate` when first recorded, becomes `confirmed` automatically when it recurs in two or more distinct sources, and `quarantined` if it proves a false positive.

```bash
bun run fireskill lesson add --signal gate_fail --summary "Import relativo no schema" --rule "Importar schemas de layers pelo pacote @nuxfire/*" --source "0042-billing"
bun run fireskill lesson list [--all]
bun run fireskill lesson status
bun run fireskill lesson prune
```

## Decisions and review

| Skill | Purpose | How it works |
|---|---|---|
| `fireskill-the-fool` | Adversarial review of a spec, plan or decision. Recommended for Effort 7 or more, or before approving a critical Definition Gate. | Pre-mortem, steelman of the opposite position, second-order effects, audit of unverified assumptions. |
| `fireskill-the-jury` | Collegiate decision on an irreversible or high-impact question. | Spawns a panel of 3 to 5 subagents with orthogonal roles, a blind first round, deliberation, and a binding verdict that keeps the dissent. Needs an agent that can spawn subagents. |
| `fireskill-the-judge` | Review of a diff or pull request. | Local linters, `vue-tsc` and Vitest first; every claim cites `file:line`; at most 5 nits; verdict `APPROVE`, `COMMENT` or `REQUEST_CHANGES` (blocker, should-fix, nit). |
