## 1. Install Bun

```bash
curl -fsSL https://bun.sh/install | bash
```

En Windows sin WSL: `npm install -g bun`.

**Prompt para agentes de IA:**
```text

Check for Bun with bun --version. If it's missing, run
curl -fsSL https://bun.sh/install | bash (Windows without WSL:
npm install -g bun), then confirm the version again before continuing.

```

## 2. Get the codebase and install

Descargue el monorepositorio de Nuxfire directamente desde su **Área de Miembros** después de la compra, extráigalo en su directorio de trabajo preferido e instale las dependencias:

```bash
cd nuxfire
bun install
```

El primer `bun install` tarda unos minutos: no se ha colgado. Ejecútelo siempre dentro de la carpeta extraída y nunca copie una carpeta `node_modules` de otra máquina o proyecto: los enlaces de los workspaces (`@nuxfire/*`) pueden romperse, y la verificación previa del despliegue ([Despliegue](/docs/saas-starter-kit/getting-started/deploy)) lo avisa si ocurre.

*(Opcional: Inicialice su propio repositorio Git privado para control de versiones)*:

```bash
git init
git add .
git commit -m "Initial commit from Nuxfire"
```

Las migraciones ya están versionadas en `apps/functions/src/database/migrations/`. Solo necesita generar nuevas migraciones si modifica `apps/functions/src/database/core-schema.ts` o el `server/database/schema.ts` de cualquier layer (`drizzle.config.ts` lee ambos, no el archivo barril `schema.ts`, que solo los reexporta):

```bash
cd apps/functions
DATABASE_HOST=... DATABASE_PORT=5432 DATABASE_USER=... DATABASE_PASSWORD=... DATABASE_NAME=... \
  bunx drizzle-kit generate
```

(Sin `DATABASE_URL`: `drizzle.config.ts` lee host/port/user/password/name por separado, por lo que nunca tendrá que construir ni escapar una URL con contraseña.)

**Prompt para agentes de IA:**
```text
In the extracted nuxfire project root, run: bun install
Only run bunx drizzle-kit generate (from apps/functions) if
core-schema.ts or a layer's server/database/schema.ts changed — ask
the user for their real DATABASE_HOST/PORT/
USER/PASSWORD/NAME first, never invent placeholder values.
```
