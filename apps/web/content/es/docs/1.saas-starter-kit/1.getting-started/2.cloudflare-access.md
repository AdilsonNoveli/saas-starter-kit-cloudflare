**Dónde crear el token**: en la barra lateral del panel de control de Cloudflare, vaya a **Manage Account → Account API Tokens** → **"+ Create Token"** → **"Create Custom Token"**. (No en `dash.cloudflare.com/profile/api-tokens`: esa es la página de tokens personales del usuario, una lista diferente de la de tokens de la cuenta que utiliza este proyecto).

¿Ya tiene un token de una configuración anterior y solo necesita agregarle el permiso `D1`? Abra **Manage Account → Account API Tokens**, haga clic en el nombre del token para editarlo, haga clic en la fila de directiva asignada a **"Entire Account"** y continúe desde el paso 3 a continuación.
En la pantalla de directivas (el diseño cambia ocasionalmente; use el cuadro **"Search for a permission group..."** si no encuentra algo por categoría):

1. Conserve o cambie el nombre del token y luego haga clic en **Edit Cloudflare Workers**:

   ![Nombre del token](/images/docs/token-name-cloudflare.webp)
   ![Editar Cloudflare Workers](/images/docs/Edit-Cloudflare-Workers.webp)

2. En la primera directiva, haga clic en **"All zones ... Account"** para agregar una segunda directiva asignada a una **zona** (Workers Custom Domains requiere esto por separado de la directiva de la cuenta):
   - Cambie el alcance de esa directiva a **"Specified Domains"** y elija su dominio:

     ![Dominios especificados](/images/docs/pecified-domains.webp)

   - Busque **`Workers Routes`** y marque **Edit** (no `DNS: Edit`). Workers Custom Domains crea el registro DNS automáticamente detrás de este permiso. La etapa `production` lo usa dos veces, para `<su dominio>` y para `www.<su dominio>`, así que no hace falta nada más en esta directiva:

     ![Workers Routes](/images/docs/Workers-Routes.webp)

     No agregue `Page Rules`: la API de Page Rules de Cloudflare no acepta Account API Tokens (error `1011`), por lo que no se puede usar con el token que crea esta guía.

3. En una segunda directiva asignada a **"Entire Account"**, agregue como mínimo (busque cada término y marque **Edit**; no hay problema si vienen más marcados de forma predeterminada):
   - `Workers Scripts`
   - `Workers KV`
   - `Workers R2`
   - `Queues`
   - `Hyperdrive`
   - `D1`: aparece bajo la categoría **Developer Platform** una vez que lo busca (no junto a Workers/KV/R2 en Account), descrito como "Grants write access to D1 configuration and SQL queries". Da soporte a la base de datos de contenido del sitio de documentación (el cuadro de búsqueda de `apps/web`). La falta de este permiso hace que el despliegue falle con `401 Unauthorized` específicamente en el recurso `D1Database`, mientras que todos los demás recursos se despliegan correctamente.

   Confirme que cada permiso esté configurado en Edit:

   ![Editar permisos de cuenta](/images/docs/edit-account.webp)

4. Haga clic en **"Review token"** y luego en **"Create Token"**:

   ![Revisar token](/images/docs/Review-token.webp)
   ![Crear token](/images/docs/create-token.webp)

5. Guarde el token en un lugar seguro. Lo que realmente utilizará en adelante son el **API token** y el **Account ID**:

   ![Tokens](/images/docs/tokens.png)

Copie el valor del token ahora: solo se muestra una vez.

Tenga a mano ambos valores: deben ser una **variable de entorno** real ([siguiente paso](/docs/saas-starter-kit/getting-started/secrets)) *y* deben incluirse en el archivo `.env` que cargue en la bóveda de secrets. Son las dos únicas variables que necesitan ambas cosas.

Un requisito más a nivel de cuenta antes de desplegar: el subdominio `workers.dev` de su cuenta ya debe estar aprovisionado; abra **Workers & Pages** en el panel de Cloudflare una vez (se crea automáticamente la primera vez que se carga esa sección). Si omite esto en una cuenta nueva, el primer despliegue fallará a mitad del proceso con `403: "You need a workers.dev subdomain..."` (código de error 10063); el token y el ID de cuenta son correctos, pero este es un paso único de configuración de cuenta ajeno a ellos.

**Errores de despliegue que provienen del token o de la zona**, y qué significa cada uno:

| Error en la salida del despliegue | Causa | Solución |
| --- | --- | --- |
| `401 Unauthorized` en `D1Database` | El token no tiene `D1` | Agréguelo (paso 3) |
| `409` código `100117` "already has externally managed DNS records" en `WorkersCustomDomain` | No es un permiso: el hostname ya tiene un registro A, AAAA o CNAME | Elimine ese registro en **DNS → Records** (en `production`, tanto el dominio raíz como `www`) y despliegue de nuevo |
**Prompt para agentes de IA:**
```text
This step has no CLI equivalent — token creation only happens in the
Cloudflare dashboard. Stop and ask the user to follow the steps above,
then get their CLOUDFLARE_API_TOKEN and CLOUDFLARE_ACCOUNT_ID before
continuing. Also confirm the user has opened Workers & Pages in the
dashboard at least once (provisions the workers.dev subdomain) — the
first deploy fails with error 10063 otherwise.
```
