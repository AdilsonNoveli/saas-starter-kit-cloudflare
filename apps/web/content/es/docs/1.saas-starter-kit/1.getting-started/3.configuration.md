Complete su dominio y flags de características. Establezca `prodDomain` con su dominio real: es la única línea que debe editar, ya que `devDomain`, `authEmailDomain` y la dirección del remitente se derivan de ella. El dominio debe ser una zona activa en la misma cuenta de Cloudflare propietaria de su token de API. Desactive también en `flags` cualquier integración que no vaya a utilizar (Stripe, Paddle, websockets, colas, proveedores de correo no requeridos); esto reduce la cantidad de secrets que tendrá que configurar.

`authEmail.name` es el nombre de su marca en los correos que envía Nuxfire (asunto y texto alternativo del logotipo), y el dominio del remitente debe estar verificado en su proveedor de correo. El logotipo de los correos se carga desde `https://<prodDomain>/pwa-192x192.png`, servido por la aplicación `web`.

```typescript [config.ts]
export const prodDomain = "yourdomain.com"; // the only line you must edit
export const devDomain = `dev.${prodDomain}`;
export const authEmailDomain = prodDomain;
export const authEmail = {
  name: "Your Company",
  address: `contact@${authEmailDomain}`,
};

export const flags: {
  stripe?: boolean;
  paddle?: boolean;
  googleAuth?: boolean;
  githubAuth?: boolean;
  resend?: boolean;
  mailgun?: boolean;
  ses?: boolean;
  sparkPost?: boolean;
  smtp?: boolean;
  websockets?: boolean;
  cron?: boolean;
  jobsQueue?: boolean;
} = {
  stripe: true,
  paddle: true,
  githubAuth: true,
  googleAuth: true,
  resend: true,
  websockets: true,
  jobsQueue: true,
};
```

El mismo archivo también declara `layers`, que es independiente de `flags` y se refiere a los Nuxt Layers compilados en `apps/app`, no a los recursos que se aprovisionan en Cloudflare:

```typescript [config.ts]
export const layers = {
  // Always extended, never toggleable — every tenant needs them.
  core: ["teams", "billing", "notifications", "admin"] as string[],

  // Toggleable per build/deploy. `false` drops the layer's pages, components
  // and Nuxt config from the bundle entirely — it does NOT drop its tables
  // from the database schema (see Database).
  features: {
    kanban: true,
  } satisfies Record<string, boolean>,
};
```

`core` enumera los cuatro layers de lógica de negocio que cada despliegue incluye (multitenencia/RBAC, facturación, notificaciones, la consola de platform admin); consulte [Estructura del Proyecto](/docs/saas-starter-kit/getting-started/project-structure). `features` es donde un layer opcional como `kanban` se desactiva para una compilación que no lo necesite.

**Prompt para agentes de IA:**
```text
Open config.ts. Ask the user for their real domain and which
integrations they want before editing prodDomain (devDomain and
authEmailDomain derive from it — leave those lines as they are),
authEmail, and the flags object — do not guess or invent any of
these values. Only touch layers.features if the user explicitly asks to
disable an optional layer (e.g. kanban) — never touch layers.core.
```
