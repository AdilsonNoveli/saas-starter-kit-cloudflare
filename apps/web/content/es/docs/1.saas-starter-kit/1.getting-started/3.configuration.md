Elija sus flags de características. Desactive en `flags` cualquier integración que no vaya a utilizar (Stripe, Paddle, websockets, colas, proveedores de correo no requeridos); esto reduce la cantidad de secrets que tendrá que configurar.

Su identidad **no** se define en este archivo: el nombre de la marca, su dominio de producción y el correo completo del remitente son las variables `BRAND_*` de la sección Branding del archivo de env de su etapa, el único lugar donde viven. Complételas junto con sus credenciales en [Secrets](/docs/saas-starter-kit/getting-started/secrets); [Variables de Entorno](/docs/saas-starter-kit/getting-started/environment-variables) explica cada una.

```typescript [config.ts]
export const flags: {
  stripe?: boolean;
  paddle?: boolean;
  googleAuth?: boolean;
  githubAuth?: boolean;
  resend?: boolean;
  mailgun?: boolean;
  ses?: boolean;
  sparkPost?: boolean;
  smtp?: boolean;
  websockets?: boolean;
  cron?: boolean;
  jobsQueue?: boolean;
} = {
  stripe: true,
  paddle: true,
  githubAuth: true,
  googleAuth: true,
  resend: true,
  websockets: true,
  jobsQueue: true,
};
```

El mismo archivo también declara `layers`, que es independiente de `flags` y se refiere a los Nuxt Layers compilados en `apps/app`, no a los recursos que se aprovisionan en Cloudflare:

```typescript [config.ts]
export const layers = {
  // Always extended, never toggleable — every tenant needs them.
  core: ["teams", "billing", "notifications", "admin"] as string[],

  // Toggleable per build/deploy. `false` drops the layer's pages, components
  // and Nuxt config from the bundle entirely — it does NOT drop its tables
  // from the database schema (see Database).
  features: {
    kanban: true,
  } satisfies Record<string, boolean>,
};
```

`core` enumera los cuatro layers de lógica de negocio que cada despliegue incluye (multitenencia/RBAC, facturación, notificaciones, la consola de platform admin); consulte [Estructura del Proyecto](/docs/saas-starter-kit/getting-started/project-structure). `features` es donde un layer opcional como `kanban` se desactiva para una compilación que no lo necesite.

**Prompt para agentes de IA:**
```text
Open config.ts. Ask the user which integrations they want before
editing the flags object — do not guess or invent any of these values.
The domain, sender email and brand name are not in this file: they are
the BRAND_* variables the user fills in their own env file — never
edit or fill those in yourself. Only touch layers.features if the user explicitly asks to
disable an optional layer (e.g. kanban) — never touch layers.core.
```
