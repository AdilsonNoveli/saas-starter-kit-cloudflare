Nuxfire no utiliza un archivo `.env` en producción: los secrets residen exclusivamente en la propia bóveda de SST. La ruta de despliegue actual es 100% Cloudflare/SST; el despliegue automatizado mediante GitHub Actions (o cualquier otro CI) es un trabajo futuro, no una vía alterna existente hoy.

¿No está seguro de dónde procede un valor concreto? [Variables de Entorno](/docs/saas-starter-kit/getting-started/environment-variables) ofrece enlaces directos para cada proveedor: Cloudflare, su host de Postgres, cada proveedor de correo/OAuth/pagos y cómo generar los dos secrets de platform admin localmente. Esta página aborda únicamente la mecánica de *carga*.

## 1. Export the Cloudflare credentials as real environment variables

`CLOUDFLARE_API_TOKEN` y `CLOUDFLARE_ACCOUNT_ID` no pueden almacenarse únicamente como secrets de SST; SST requiere ambos como una **variable de entorno real** en cada comando (`secret load`, `secret set`, `deploy`, `dev`...), ya que es la credencial que autentica a SST frente a Cloudflare antes de poder leer la bóveda.

**PowerShell** (predeterminado en Windows):

```powershell
$env:CLOUDFLARE_API_TOKEN = "your_token"
$env:CLOUDFLARE_ACCOUNT_ID = "your_account_id"
```

Para persistir entre terminales: `[Environment]::SetEnvironmentVariable("CLOUDFLARE_API_TOKEN", "your_token", "User")` (y lo mismo para el account ID); abra una nueva terminal después.

**bash/zsh**:

```bash
export CLOUDFLARE_API_TOKEN=your_token
export CLOUDFLARE_ACCOUNT_ID=your_account_id
```

Para persistir, agregue ambas líneas a `.bashrc`/`.zshrc`.

## 2. Load the rest into SST's vault

**Un archivo por etapa**, nunca un único `.env` reutilizado. `.env.example` es la plantilla (todas las claves, valores en blanco):

```bash
cp .env.example .env.stage
# fill in .env.stage with your dev environment's values
bunx sst secret load .env.stage --fallback
```

`.env.stage`/`.env.production` se excluyen de los commits automáticamente (el `.gitignore` cubre `.env*`); manténgalos localmente, no los elimine después de cargarlos. Los necesitará nuevamente cada vez que cambie un secret.

**Prompt para agentes de IA:**
```text
Ask the user to export CLOUDFLARE_API_TOKEN and CLOUDFLARE_ACCOUNT_ID in
their own shell first — never request, type, or store these values
yourself. Then: cp .env.example .env.stage, ask the user to fill it in
themselves (never fill in a credential on their behalf), then run
bunx sst secret load .env.stage --fallback.
```
