title: "Estructura del Proyecto"
description: "Un vistazo bajo el capó a la base de código del monorepositorio de Nuxfire."
---

Nuxfire es un monorepositorio basado en workspaces de Bun (`apps/*`, `packages/*`, `layers/*`), todos bajo el espacio de nombres `@nuxfire/*`. `apps/` contiene todo lo que tiene su propio despliegue; `packages/` aloja bibliotecas compartidas sin despliegue propio; `layers/` alberga Nuxt Layers acoplables de lógica de negocio, cada uno extendido en `apps/app` y activado o desactivado en el archivo raíz `config.ts`.

- **`apps/app`** — la Raíz de Composición (Composition Root): el armazón de la aplicación (diseño del panel, configuración de la cuenta, composición tRPC), extendiendo cada capa activa. La lógica de negocio en sí (gestión de equipos, facturación, notificaciones, consola de platform admin) reside en `layers/`, no aquí.
- **`apps/web`** — el sitio público: página de inicio (landing page), blog y esta documentación, creada con Nuxt Content.
- **`apps/login`** — la interfaz de usuario para inicio de sesión, registro y olvido de contraseña, compilada estáticamente y servida como recursos estáticos del Worker de autenticación.
- **`apps/functions`** — código de Cloudflare Workers ajeno a la aplicación principal: el emisor de autenticación OpenAuth, el Worker de correos electrónicos, el Worker de WebSockets, los consumidores de colas de trabajo/dead-letter y el Worker de Cron horario. También alberga `database/`: el agregador de esquemas de Drizzle, migraciones y scripts de seed.
- **`layers/teams`, `layers/billing`, `layers/notifications`, `layers/admin`** — los domínios de negocio principales (multitenencia/RBAC, suscripciones, notificaciones, la consola de platform admin), cada uno como un Nuxt Layer autónomo con sus propias páginas, componentes, enrutador tRPC y fragmento de esquema de base de datos.
- **`layers/kanban`** — un ejemplo de capa de funcionalidad opcional, configurable independientemente de las cuatro capas principales.
- **`packages/emails`** — `packages/emails/templates`, plantillas de correo creadas con React Email, más `packages/emails/mailer`, el motor de envío agnóstico del proveedor (un fork propio de AdonisJS Mail); consulte [Correos Electrónicos](/docs/saas-starter-kit/features/emails).
- **`packages/tokens`** — `@nuxfire/tokens`, la fuente única de verdad para la tematización (colores de marca, radio de esquinas, mapeo de superficies en modo oscuro, anulaciones de componentes de Nuxt UI), consumida por todas las aplicaciones y capas por igual; consulte [Sistema de Diseño y Marca](/docs/saas-starter-kit/concepts/design-system).
- **`packages/manifest`** — `@nuxfire/manifest`, el contrato compartido `defineLayerManifest()` que utiliza cada `layer.manifest.ts`.

Todo lo que está fuera de `apps/`, `packages/` y `layers/` que no sea código de aplicación es infraestructura: `infra/*.ts` define cada recurso de Cloudflare mediante SST; consulte [SST.dev](/docs/saas-starter-kit/concepts/sst) para ver cómo se cargan estos archivos y qué es una etapa.
