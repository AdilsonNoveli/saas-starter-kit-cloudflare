Nuxfire es un monorepositorio basado en workspaces de Bun (`apps/*`, `packages/*`, `layers/*`), todos bajo el espacio de nombres `@nuxfire/*`. `apps/` contiene aplicaciones con despliegue propio; `packages/` aloja bibliotecas compartidas sin despliegue propio; `layers/` alberga Nuxt Layers acoplables de lógica de negocio, cada uno extendido en `apps/app` y configurado en el archivo raíz `config.ts`.

## Monorepo Breakdown

### Applications (`apps/`)

- **`apps/app`** — la Raíz de Composición (Composition Root): el armazón de la aplicación (diseño del panel, navegación, composición tRPC), extendiendo cada capa activa. La lógica de negocio en sí reside en `layers/`, no aquí.
- **`apps/web`** — el sitio público: página de inicio (landing page), blog y esta documentación, creada con Nuxt Content.
- **`apps/login`** — la interfaz de usuario para inicio de sesión, registro y olvido de contraseña, compilada estáticamente y servida como recursos estáticos del Worker de autenticación.
- **`apps/functions`** — código de Cloudflare Workers: el emisor de autenticación OpenAuth, el Worker de correos electrónicos, el Worker de WebSockets, los consumidores de colas de trabajo/dead-letter y el Worker de Cron horario. También alberga `src/database/`: el esquema base de Drizzle y migraciones.

### Domain Layers (`layers/`)

Los dominios de negocio residen en `layers/` como Nuxt Layers modulares. Cada capa con estado persistente tiene su propio `drizzle.config.ts`, directorio `migrations/` y `layer.manifest.ts`:

- **Capas Principales (`layers.core`)**: Siempre compiladas y activas para todos los inquilinos:
  - **`layers/account`** (`@nuxfire/layer-account`) — perfil de usuario, carga de avatar, preferencias de apariencia, sesiones activas, eliminación de cuenta, MFA de usuario (TOTP con registro, desafío y códigos de recuperación) y flujo de bienvenida (`/onboarding`).
  - **`layers/teams`** (`@nuxfire/layer-teams`) — multitenencia, espacios de equipo, miembros, invitaciones, roles y permisos RBAC (`nuxt-authorization`), selector de equipo y modelos de colas/DLQ (`Job`, `DeadLetterRecord`).
  - **`layers/notifications`** (`@nuxfire/layer-notifications`) — notificaciones en tiempo real en la aplicación mediante WebSockets, panel deslizante de notificaciones y seguimiento de estado de lectura.
  - **`layers/admin`** (`@nuxfire/layer-admin`) — consola de platform admin (`/admin`), MFA obligatorio para administradores, registros de auditoría, gestión de DLQ y supervisión de empresas.
- **Capas de Funcionalidad (`layers.features`)**: Configurables independientemente en `config.ts`:
  - **`layers/billing`** (`@nuxfire/layer-billing`) — suscripciones de Stripe y Paddle, proceso de pago, portal de facturación, webhooks, planes y beneficios, y pestaña de facturación en ajustes de equipo.
  - **`layers/kanban`** (`@nuxfire/layer-kanban`) — tableros kanban opcionales, columnas, tarjetas/tareas, arrastrar y soltar, y elemento en la barra lateral de navegación de equipo.

### Shared Packages (`packages/`)

- **`packages/crypto`** (`@nuxfire/crypto`) — primitivas de seguridad puras con Web Crypto: cifrado/descifrado AES-GCM, HMAC-SHA256, comparación en tiempo constante `secretsMatch`, códigos de recuperación MFA y tickets firmados de WebSocket. Cero dependencias en tiempo de ejecución.
- **`packages/rate-limit`** (`@nuxfire/rate-limit`) — algoritmo puro de limitación de tasa de ventana fija (`core.ts`) y adaptadores (`adapters.ts`) para Cloudflare KV (`kvNamespaceStore`) y NuxtHub KV (`hubKvStore`).
- **`packages/emails`** (`@nuxfire/emails`) — `packages/emails/templates` (plantillas de correo creadas con React Email) más `packages/emails/mailer` (motor de envío agnóstico del proveedor para Resend, SES, Mailgun, SparkPost, SMTP); consulte [Correos Electrónicos](/docs/saas-starter-kit/features/emails).
- **`packages/tokens`** (`@nuxfire/tokens`) — `@nuxfire/tokens`, la fuente única de verdad para la tematización (colores de marca, radio de esquinas, mapeo de superficies en modo oscuro, anulaciones de componentes de Nuxt UI), consumida por todas las aplicaciones y capas por igual; consulte [Sistema de Diseño y Marca](/docs/saas-starter-kit/concepts/design-system).
- **`packages/manifest`** (`@nuxfire/manifest`) — `@nuxfire/manifest`, el contrato compartido `defineLayerManifest()` que utiliza cada `layer.manifest.ts`.

Todo lo que está fuera de `apps/`, `packages/` y `layers/` que no sea código de aplicación es infraestructura: `infra/*.ts` define cada recurso de Cloudflare mediante SST; consulte [SST.dev](/docs/saas-starter-kit/concepts/sst).

## Architecture Tree

```text
nuxfire/
├── apps/
│   ├── app/           # Composition Root: UI shell & tRPC composition
│   ├── functions/     # Cloudflare Workers: Auth issuer, Mailer, WebSockets, Cron, Queues
│   ├── login/         # Static Nuxt auth UI: Login, Signup, Forgot Password
│   └── web/           # Public site: Landing page, Blog, Docs (Nuxt Content)
├── layers/
│   ├── account/       # Core: Profile, preferences, sessions, user MFA, onboarding
│   ├── admin/         # Core: Platform admin console, admin MFA, audit logs, DLQ
│   ├── billing/       # Feature: Stripe & Paddle billing, checkouts, plans
│   ├── kanban/        # Feature: Boards, lists, task cards, drag-and-drop
│   ├── notifications/ # Core: In-app notifications, WebSocket delivery, slideover
│   └── teams/         # Core: Multi-tenancy, memberships, invitations, RBAC
├── packages/
│   ├── crypto/        # Pure Web Crypto: AES-GCM, HMAC, constant-time compare, tickets
│   ├── emails/        # React Email templates & provider-agnostic mailer engine
│   ├── manifest/      # Layer manifest contracts & defineLayerManifest schema
│   ├── rate-limit/    # Fixed-window rate limiting core & KV adapters
│   └── tokens/        # Design tokens, color themes, CSS variables & theme.css
└── infra/             # SST infrastructure definitions (Cloudflare resources)
```
