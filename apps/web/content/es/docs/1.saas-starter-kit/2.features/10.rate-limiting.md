title: "Límite de Tasa (Rate Limiting)"
description: "Rate limiting de ventana fija respaldado por Cloudflare KV, protegiendo inicios de sesión, MFA y endpoints de webhooks de pagos."
---

Un limitador de tasa de ventana fija respaldado por Cloudflare KV, implementado dos veces (una por entorno de ejecución de Worker, con la misma estructura y semántica en ambos):

- `apps/app/server/utils/rate-limit.ts`: utiliza `hubKV()` dentro del entorno Nitro del Worker App.
- `apps/functions/src/rate-limit.ts`: toma un `KVNamespace` directo (`AuthKV`), ya que el Worker de autenticación carece de Nitro/NuxtHub para invocar `hubKV()`.

```typescript [apps/app/server/utils/rate-limit.ts]
export async function rateLimit(key: string, { limit, windowSeconds }) {
  // Cloudflare KV rejects a TTL under 60s, so the window can't be shorter.
  const window = Math.max(windowSeconds, 60);
  const kv = hubKV();
  const windowId = Math.floor(Date.now() / 1000 / window);
  const kvKey = `ratelimit:${key}:${windowId}`;
  const count = ((await kv.get<number>(kvKey)) ?? 0) + 1;
  await kv.set(kvKey, count, { ttl: window });
  return { allowed: count <= limit, count, limit };
}
```

`assertNotRateLimited(event, routeKey, options)` envuelve esta función para rutas HTTP en el Worker App: utiliza la clave `<routeKey>:<ip>` y arroja `429 Too Many Requests` directamente cuando se sobrepasa el límite.

## What's currently protected

| Where | Keyed by | Purpose |
|---|---|---|
| `apps/functions/src/auth.ts` (`enforceCredentialRateLimit`) | path + IP + email | Inicio de sesión con contraseña/código en el Worker de autenticación |
| `layers/admin/server/api/admin/mfa/verify.post.ts` | platform admin id | Intentos de inscripción en MFA |
| `layers/admin/server/api/admin/mfa/challenge.post.ts` | platform admin id | Intentos de reautenticación en MFA |
| `layers/billing/server/api/webhooks/stripe.post.ts` | IP | Webhook de Stripe, sumado a la validación de firma |
| `layers/billing/server/api/webhooks/paddle.post.ts` | IP | Webhook de Paddle, sumado a la validación de firma |

Esto no es una limitación general de la API: se aplica concretamente donde la validación de credenciales o firmas no detiene ataques de repetición masiva: intentos de autenticación y endpoints de webhooks no autenticados. No hay límite de tasa en procedimientos tRPC comunes hoy en día.
