---
title: "WebSockets"
description: "Una implementación pub/sub de WebSockets basada en Cloudflare Durable Objects, bajo el flag websockets."
---

Las actualizaciones en tiempo real se ejecutan en Cloudflare Workers y Durable Objects, bajo el flag `websockets` en `config.ts`.

## Architecture

- Cliente WebSocket frontend: `apps/app/app/plugins/websockets.client.ts` (un plugin complementario, `ws-notifications.client.ts`, lo conecta con la función de notificaciones)
- Servidor WebSocket backend: `apps/functions/src/websockets.js`
- Infraestructura: `infra/websockets.ts`

## Usage

### Frontend

El cliente WebSocket es un plugin de Nuxt, disponible en los componentes mediante `$ws`:

```ts
// In your component
const { $ws } = useNuxtApp();

// Subscribe to topics
$ws.on("user.123", (data) => {
  // Handle topic payload
  console.log("Got update:", data);
});

// Cleanup when done
onUnmounted(() => {
  $ws.off("user.123");
});
```

El cliente automáticamente:

- Se autentica mediante un ticket de WebSocket de corta duración (`/api/auth/ws-ticket`) en lugar del token de sesión de larga duración; la cabecera `sec-websocket-protocol` es el único medio para autenticar una conexión WebSocket de navegador y puede ser leída por JS de la página, por lo que el token de acceso real nunca se expone allí.
- Se reconecta ante caídas de conexión.
- Se vuelve a suscribir a los temas tras la reconexión.

### Backend

Publique mensajes en temas desde un procedimiento tRPC mediante `ctx.sendWebsocketsEvent`:

```typescript
async ({ ctx: { user, sendWebsocketsEvent }, input }) => {
  // ...create notification in database...
  await sendWebsocketsEvent(
    user.id, // topic
    { type: "notification", payload: notification },
  );
};
```

## Security

- La autenticación utiliza un ticket de corta duración, firmado con un secreto compartido únicamente entre el Worker App y el Worker Websockets (`WsTicketSecret`, `infra/websockets.ts`), nunca el token de sesión de OpenAuth.
- La autorización de temas está determinada por lo que la aplicación decide publicar en un tema determinado; no existe un ACL integrado por tema, por lo que debe delimitar los nombres de temas (por ejemplo, `user.<id>`) a quienes deban recibirlos legítimamente.

## Configuration

Habilite WebSockets activando el flag `websockets`:

```ts [config.ts]
export const flags = {
  // ...
  websockets: true,
};
```

Esto despliega el Worker de WebSockets (respaldado por un Durable Object) y lo enlaza a la aplicación.
