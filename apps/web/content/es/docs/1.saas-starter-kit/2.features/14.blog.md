Nuxfire incluye un blog construido con [Nuxt Content](https://content.nuxt.com/). Agregue archivos markdown para comenzar a publicar: el build valida cada artículo y genera sus metadatos de búsqueda y de redes sociales.

## What's Included

- Páginas de índice y de artículo, con un único `<h1>` por artículo
- Integración con búsqueda en todo el sitio
- SEO completo por artículo: título, descripción, canonical, etiquetas Open Graph y Twitter, datos estructurados `BlogPosting`, idioma, hreflang y `lastmod` en el sitemap
- Artículos en varios idiomas, enlazados entre sí como traducciones
- Una verificación `bun run check:seo` que detecta regresiones
- Diseño responsivo y soporte para modo oscuro

## File Structure

Los artículos del blog residen en `apps/web/content/blog`, como una colección propia de Nuxt Content (`apps/web/content.config.ts`). Cada artículo es un archivo markdown cuyo frontmatter se valida en el build:

```yaml
---
title: "Specific title without the brand"
description: "One or two sentences that describe this post."
date: "2026-09-25"
author: "Your Name"
lang: en
ogImage: "/images/blog/my-cover.png"
---
```

## Frontmatter

| Campo | Obligatorio | Significado |
| --- | --- | --- |
| `title` | Sí | El título de la página y el único `<h1>`. La marca se agrega automáticamente: no la escriba. |
| `description` | Sí | Descripción del artículo para buscadores y redes sociales, nunca la descripción por defecto del sitio. |
| `date` | Sí | `YYYY-MM-DD` o un datetime ISO 8601 con zona horaria. Una fecha sin hora significa medianoche UTC. |
| `updated` | No | Mismo formato, nunca anterior a `date`. Alimenta `article:modified_time` y el `lastmod` del sitemap. |
| `author` | Sí | El nombre del autor mostrado en la página y en los datos estructurados. |
| `authorType` | No | `Person` u `Organization` (por defecto `Organization`). |
| `lang` | Sí | `en`, `pt-br` o `es`. No tiene valor por defecto: define `<html lang>`, `og:locale` y hreflang. |
| `translations` | No | Idioma a slug de cada versión del artículo, incluida la propia. |
| `category` | No | Se muestra en la tarjeta y se usa como `article:section`. |
| `readTime` | No | Se muestra en la tarjeta, por ejemplo `8 min`. |
| `tags` | No | Se usan como `article:tag` y como `keywords` en los datos estructurados. |
| `image` | No | La portada mostrada en la página del artículo. Puede ser un SVG. |
| `ogImage` | No | La imagen que leen las redes sociales: una ruta `.png` o `.jpg` en `apps/web/public`. Usa la imagen por defecto del sitio si falta. |

## Traducciones

El blog tiene un artículo por idioma. Enlace las versiones de un artículo repitiendo el mismo bloque `translations` en todas ellas; cada clave es el idioma del artículo al que apunta:

```yaml
translations:
  en: my-post-english-slug
  pt-br: my-post-portuguese-slug
  es: my-post-spanish-slug
```

El head y el sitemap pasan a listar todas las versiones de forma recíproca, con `x-default` apuntando a la versión en inglés. `bun run check:seo` falla si falta una versión, está escrita en otro idioma o no apunta de vuelta.

## Imágenes de portada

Diseñe la portada como un SVG 16:9 en `apps/web/public/images/blog` y luego genere el PNG que leen las redes sociales. La documentación de uso compartido de Facebook lista JPEG, GIF y PNG para `og:image`; SVG no figura entre ellos.

```bash
bun run generate:og
```

El comando escribe un PNG de 1200x675 junto a cada portada SVG y junto a la imagen por defecto del sitio (`apps/web/public/images/og/default.svg`), y ejecutarlo dos veces no cambia nada. Se ejecuta en su máquina con `sharp`, así que abra cada PNG y haga el commit.

## Verifique antes de publicar

Compile el sitio con su dirección real y ejecute la verificación sobre las páginas generadas:

```bash
SITE_URL=https://your-domain bun run --cwd apps/web build
bun run check:seo
```

- Cada artículo tiene idioma, fechas válidas, un `ogImage` raster que existe y un conjunto de traducciones consistente.
- Cada página tiene su propio título y descripción, un `<h1>`, canonical absoluto, imagen social y, en los artículos, datos estructurados `BlogPosting` en el idioma correcto.
- El sitemap lista cada artículo con `lastmod` y el mismo hreflang que el head de la página, y no lista nada que pida no ser indexado.

Sin un build, el comando igualmente valida el frontmatter de todos los artículos e informa que la auditoría de páginas se omitió. Para escribir artículos con un agente de IA, cargue el especialista de contenido descrito en [Nuxfire Stack Specialists](/docs/fireskills/specialists/nuxfire-stack).
