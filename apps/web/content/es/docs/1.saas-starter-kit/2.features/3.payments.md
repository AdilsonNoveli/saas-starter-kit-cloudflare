## Supported Payment Providers

- Stripe
- Paddle

Ambos proveedores están configurados para operar en paralelo, lo que le permite elegir uno o utilizar ambos.

## Core Components

### Database Schema

```typescript [layers/billing/server/database/schema.ts]
export const plans = pgTable("Plan", {
  id: text("id").$default(() => cuid()).primaryKey().notNull(),
  name: text("name").notNull(),
  description: text("description").notNull(),
  tier: text("tier").default("FREE").notNull(),
  price: text("price").notNull(),
  period: text("period").notNull(),
  provider: text("provider"),
  providerPriceId: text("providerPriceId"),
  providerProductId: text("providerProductId"), // the Stripe Product behind providerPriceId — Prices are immutable, so a changed amount creates a new Price under the same Product
  unitAmount: integer("unitAmount"), // minor units (e.g. cents); null for plans not managed by Stripe's catalog
  currency: text("currency"), // lowercase ISO 4217; null alongside unitAmount
  maxSeats: integer("maxSeats"), // null = unlimited
  limits: jsonb("limits"), // open-ended bag for future quotas
  isArchived: boolean("isArchived").notNull().default(false), // soft delete
  // ...timestamps
});

export const subscriptions = pgTable("Subscription", {
  id: text("id").$default(() => cuid()).primaryKey().notNull(),
  teamId: text("teamId").notNull().references(() => teams.id),
  status: text("status").default("ACTIVE").notNull(),
  provider: text("provider").notNull(),
  providerSubscriptionId: text("providerSubscriptionId").notNull(),
  planId: text("planId").notNull().references(() => plans.id),
  currentPeriodStart: timestamp("currentPeriodStart", { withTimezone: true }),
  currentPeriodEnd: timestamp("currentPeriodEnd", { withTimezone: true }),
  cancelAtPeriodEnd: boolean("cancelAtPeriodEnd").default(false).notNull(),
  providerMetadata: jsonb("providerMetadata"),
  customerEmail: text("customerEmail"),
  lastPaymentDate: timestamp("lastPaymentDate", { withTimezone: true }),
  nextPaymentDate: timestamp("nextPaymentDate", { withTimezone: true }),
  // ...timestamps
});
```

Una fila de `Plan` pertenece exactamente a un proveedor (`provider`/`providerPriceId`); ofrecer el mismo plan en Stripe y Paddle requiere dos filas de `Plan`, una para cada proveedor.

### Webhook Handlers

Ubicados en `layers/billing/server/api/webhooks/`:

- `stripe.post.ts`: gestiona eventos de suscripción de Stripe
- `paddle.post.ts`: gestiona eventos de suscripción de Paddle

### Client Integration

El composable `usePayments()` (`layers/billing/app/composables/use-payments.ts`) gestiona el checkout del cliente, con una estructura adaptada a cada proveedor:

```typescript
// Paddle — items with a Paddle price id, opens Paddle's own checkout overlay
const paddle = usePayments("PADDLE");
await paddle?.checkout([{ priceId: "pri_123" }], { data: { teamId: team.id } });

// Stripe — returns a hosted Checkout Session URL to redirect to
const stripe = usePayments("STRIPE");
const sessionUrl = await stripe?.checkout("price_123", team.id);
if (sessionUrl) navigateTo(sessionUrl, { external: true });
```

El checkout de Paddle requiere que `NUXT_PUBLIC_PADDLE_CLIENT_TOKEN` esté configurado; genera un error explícito si dicho valor está vacío, en lugar de fallar silenciosamente al abrirse.

## Setup Steps

1. Configure los secrets necesarios utilizando la CLI de SST:

   ```bash
   # Stripe
   sst secret set STRIPE_SECRET_KEY sk_test_xxx
   sst secret set STRIPE_WEBHOOK_SECRET_KEY whsec_xxx

   # Paddle
   sst secret set PADDLE_API_KEY xxx
   sst secret set PADDLE_WEBHOOK_SECRET xxx
   sst secret set PADDLE_CLIENT_TOKEN xxx
   ```

2. Cree los planes en `/admin/plans`: consulte [Consola de Platform Admin](/docs/saas-starter-kit/features/platform-admin). Esta es una acción del propietario de la plataforma, no un script de seed: los planes no están prefijados en código, por lo que los IDs de precios se mantienen por entorno (pruebas vs. producción).

   **Para un plan gestionado por Stripe, no se pega ningún ID de precio manualmente.** El formulario de administración toma un monto decimal, moneda y período de facturación; `syncStripePlanCatalog()` en `layers/billing/server/utils/stripe-catalog.ts` crea (o actualiza) el Producto de Stripe y crea un nuevo Precio mediante la API de Stripe cada vez que el monto, la moneda o el período cambian. Los Precios son inmutables en Stripe, por lo que un cambio siempre genera un nuevo Precio y archiva el anterior bajo el mismo Producto. `providerPriceId`/`providerProductId` continúan siendo campos manuales para planes con proveedor Paddle (su catálogo no se gestiona desde aquí) o para planes de Stripe anteriores a esta sincronización.

3. Configure los endpoints de webhook en los paneles de sus proveedores:
   - Stripe: `/api/webhooks/stripe`
   - Paddle: `/api/webhooks/paddle`

### The Free plan

Exactamente un plan es creado automáticamente por `apps/functions/src/database/seed/index.ts` en cada despliegue (de manera idempotente: comprueba primero si existe una fila con `tier: "FREE"`):

```typescript [apps/functions/src/database/seed/data.ts]
export const FREE_PLAN: InsertPlan = {
  name: "Free Tier",
  tier: "FREE",
  // ...
};
```

Todos los planes de pago se excluyen deliberadamente del seed: los IDs de precios de Stripe/Paddle son específicos del entorno, por lo que se crean en `/admin/plans` en lugar de estar fijados en un script.
