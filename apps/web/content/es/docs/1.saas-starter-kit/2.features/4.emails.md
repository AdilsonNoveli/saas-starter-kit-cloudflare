---
title: "Correos Electrónicos"
description: "Envíe correos electrónicos con React Email y un worker agnóstico del proveedor. Alterne entre Resend, SES, Mailgun, SparkPost o SMTP personalizado."
---

Nuxfire incluye un sistema de correo electrónico que se ejecuta íntegramente en Cloudflare Workers, basado en un fork propio de [AdonisJS Mail](https://adonisjs.com) adaptado para funcionar sin el framework AdonisJS: `@nuxfire/emails/mailer` (`packages/emails/mailer`), código propio y mantenido en lugar de una dependencia externa.

## Architecture

- **Plantillas de Correo** (`packages/emails/templates`): plantillas con seguridad de tipos mediante [React Email](https://react.email)
- **Motor de Envío (Mailer Engine)** (`packages/emails/mailer`): motor agnóstico de proveedor, fork de AdonisJS Mail
- **Worker de Correos** (`apps/functions/src/emails.ts`): un Worker Entrypoint de Cloudflare que gestiona envíos independientes del proveedor
- **Infraestructura** (`infra/emails.ts`): configuración de infraestructura para el Worker

## Email Templates

Las plantillas se crean con [React Email](https://react.email) y Tailwind. Por ejemplo:

```tsx [packages/emails/templates/Welcome.tsx]
import { Body, Container, Html, Text } from "@react-email/components";

export const WelcomeEmail = ({ username }: { username: string }) => (
  <Html>
    <Body>
      <Tailwind>
        <Container class="p-4 border border-solid border-[#eaeaea] rounded my-[40px] mx-auto max-w-[465px]">
          <Text>Welcome {username}!</Text>
        </Container>
      </Tailwind>
    </Body>
  </Html>
);
```

Cada plantilla real también recibe el `brand` de la instalación (`name` y `logoUrl`) como segundo argumento, construido a partir de su Branding: así el asunto y el logotipo siguen su `BRAND_NAME` y su `BRAND_DOMAIN`, sin nada que editar en las plantillas.

## Provider Configuration

Quién envía el correo no se configura aquí, y quien llama nunca lo indica: el remitente es su `BRAND_EMAIL` (mostrado como `BRAND_NAME`), definido en la sección Branding del archivo de env de la etapa y entregado al Worker de correos en el despliegue (`infra/emails.ts`). El dominio de esa dirección debe estar verificado en su proveedor de correo.

Los proveedores de correo electrónico se habilitan en `flags` dentro de `config.ts` y se configuran en el propio Worker de correos. Solo Resend viene descomentado por defecto; los demás transportes están listos para activarse con las líneas de importación/configuración marcadas con `TODO`:

```typescript [config.ts]
export const flags: {
  // ...
  resend?: boolean;
  mailgun?: boolean;
  ses?: boolean;
  sparkPost?: boolean;
  smtp?: boolean;
} = {
  // ...
  resend: true,
};
```

```typescript [apps/functions/src/emails.ts]
// TODO: import and set up email providers that you want to use
import { ResendTransport } from "@nuxfire/emails/mailer/transports/resend";
// import { MailgunTransport } from "@nuxfire/emails/mailer/transports/mailgun";
// ...

const config: Parameters<typeof generateMailer>[0] = {
  default: "resend",
  mailers: {
    ...(flags.resend && {
      resend: () =>
        new ResendTransport({
          key: Resource.RESEND_API_KEY.value || "",
          baseUrl: "https://api.resend.com",
        }),
    }),
    // ...(flags.mailgun && { mailgun: () => new MailgunTransport({ ... }) }),
  },
};
```

`Resource.RESEND_API_KEY` coincide exactamente con el nombre del secret (`RESEND_API_KEY` en `.env.example`/`infra/secret.ts`): todos los secrets de proveedores siguen esta nomenclatura `SCREAMING_SNAKE_CASE`, resuelta mediante el enlace `sst/resource` de SST en lugar de `process.env`.

## Setting Up Secrets

```bash
# Resend
sst secret set RESEND_API_KEY re_123...
# Mailgun
sst secret set MAILGUN_API_KEY key-123...
```

## Sending Emails

Utilice la función `sendEmail` del contexto de tRPC para enviar correos electrónicos:

```typescript
async ({ ctx: { user, origin, authorize, sendEmail }, input }) => {
  // ...
  await sendEmail(invite.email, "Invitation", {
    teamName: team.name,
    invitedBy: user.name,
    inviteLink,
  });
  // ...
};
```

El Worker de correos también se puede invocar directamente desde cualquier paquete a través del ayudante `sender`:

```typescript
import { sender } from "@nuxfire/functions/sender";
const sendEmail = sender(event.context?.cloudflare?.env?.Emails); // pass the Emails binding
```
