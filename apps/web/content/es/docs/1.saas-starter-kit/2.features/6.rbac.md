El RBAC de Nuxfire está construido sobre [`nuxt-authorization`](https://www.npmjs.com/package/nuxt-authorization) (un sistema de habilidades al estilo Bouncer) con Drizzle y tRPC. No hay rastro de Prisma en toda esta arquitectura; cada consulta, en esta función y en cualquier otra, se realiza mediante Drizzle.

## What's Included

- Permisos asignados por equipo: un rol solo otorga acceso dentro de un equipo específico.
- Roles de sistema (`isSystemRole`) compartidos entre todos los equipos, junto con los roles propios personalizados de cada equipo.
- Un rol predeterminado (`isDefault`) asignado automáticamente a los nuevos miembros.
- Autorización en el servidor en tRPC, replicada en el cliente con un componente `<Can>`.

## Schema

```typescript [layers/teams/server/database/schema.ts]
export const roles = pgTable("Role", {
  id: text("id").$default(() => cuid()).primaryKey().notNull(),
  teamId: text("teamId"), // null = system role, shared across every team
  name: text("name").notNull(),
  description: text("description"),
  isSystemRole: boolean("isSystemRole").default(false).notNull(),
  isDefault: boolean("isDefault").default(false).notNull(),
  // ...timestamps
});

export const permissions = pgTable(
  "Permission",
  {
    title: text("title").notNull(),
    description: text("description"),
    action: text("action").notNull(),
    roleId: text("roleId").notNull().references(() => roles.id),
    // ...timestamps
  },
  (table) => [primaryKey({ columns: [table.action, table.roleId] })],
);

export const teamMemberships = pgTable(
  "TeamMembership",
  {
    id: text("id").$default(() => cuid()).primaryKey().notNull(),
    teamId: text("teamId").notNull(),
    userId: text("userId").notNull(),
    roleId: text("roleId").notNull().references(() => roles.id),
    // ...timestamps
  },
  (table) => [unique().on(table.teamId, table.userId)],
);
```

## Defining Abilities

Las habilidades (abilities) se ubican en `layers/teams/shared/utils/abilities.ts`, compartidas entre cliente y servidor al encontrarse bajo `shared/`, y definidas con `defineAbility` de `nuxt-authorization`. Cada nombre lleva el prefijo de la capa propietaria (`teams*`, `kanban*`): Nuxt importa automáticamente `shared/utils/` de todas las capas en un espacio de nombres plano, por lo que dos capas exportando el mismo identificador colisionarían de forma silenciosa.

```typescript [layers/teams/shared/utils/abilities.ts]
import { PERMISSIONS } from "./permissions";

const hasTeamPermission = (user: User | null, teamId: string, permission: string) =>
  !!user?.teams?.includes(teamId) &&
  (user?.permissions?.[teamId] || []).includes(permission);

export const teamsUpdateTeamDetails = defineAbility(
  (user: User | null, teamId: string) =>
    hasTeamPermission(user, teamId, PERMISSIONS.TEAMS.UPDATE),
);

export const teamsRemoveMember = defineAbility(
  (user: User | null, teamId: string, memberId?: string) =>
    hasTeamPermission(user, teamId, PERMISSIONS.TEAMS.MEMBERS.REMOVE) &&
    (!memberId || memberId !== user?.id), // can't remove yourself
);
```

## Using in Components

El componente `<Can>` condiciona el renderizado del mismo modo en que la habilidad protege la petición:

```vue
<template>
  <Can :ability="sendInviteAbility" :args="[team?.id || '']">
    <UForm :schema="inviteSchema" :state="inviteForm" @submit="sendInvite">
      <!-- invite form -->
    </UForm>
  </Can>
</template>

<script setup lang="ts">
import { teamsSendInvite as sendInviteAbility } from "@nuxfire/layer-teams/shared/utils/abilities";
</script>
```

## API Authorization

`abilityProcedure` (construido sobre `protectedProcedure` en `apps/app/server/trpc/trpc.ts`) incorpora `authorize`/`allows`/`denies` al contexto de tRPC, respaldado por las funciones de `nuxt-authorization`. La llamada a `authorize` lanza una excepción: un rechazo se convierte en un TRPCError `FORBIDDEN` y queda registrado (`console.warn("authz denied", ...)`, visible en los registros de Cloudflare Workers) antes de llegar al cliente:

```typescript [layers/teams/server/trpc/teams.ts]
export default router({
  list: abilityProcedure.query(async ({ ctx: { authorize, user } }) => {
    await authorize(teamsListTeams);

    const teams = await useDB().query.teams.findMany({
      with: { memberships: { where: eq(teamMemberships.userId, user.id) } },
      columns: { id: true, name: true, slug: true, description: true, logo: true },
    });

    return teams.filter((team) => team.memberships.length > 0);
  }),
});
```

Este es deliberadamente un procedimiento independiente de `platformAdminProcedure`; consulte [Consola de Platform Admin](/docs/saas-starter-kit/features/platform-admin). La autoridad del propietario de la plataforma nunca se canaliza mediante la capa de habilidades de los inquilinos, impidiendo que un permiso de equipo otorgue accesos a nivel de plataforma.
