## Architecture

Nuxfire procesa el trabajo en segundo plano con dos primitivas independientes de Cloudflare:

1. **Trabajos basados en colas**: Cloudflare Queues, condicionado al flag `jobsQueue` en `config.ts`.
2. **Cron**: un Cloudflare Cron Trigger, desplegado incondicionalmente hoy; `infra/cron.ts` actualmente no comprueba el flag `cron` tipificado en `flags` de `config.ts`.

### Queue consumer

`apps/functions/src/jobs-consumer.ts` procesa mensajes por lotes. Si tiene éxito, marca el trabajo como `completed` y escribe una línea de log `job completed`; si falla, lo marca como `failed`, escribe el texto del error en el log y ejecuta `message.retry()`:

```typescript [apps/functions/src/jobs-consumer.ts]
for (const message of batch.messages) {
  const job = message.body as typeof schema.jobs.$inferSelect;
  try {
    await db.update(schema.jobs).set({ status: "completed" }).where(eq(schema.jobs.id, job.id));
    await db.insert(schema.logs).values({ jobId: job.id, message: "job completed" });
    message.ack();
  } catch (err) {
    await db.update(schema.jobs).set({ status: "failed" }).where(eq(schema.jobs.id, job.id));
    await db.insert(schema.logs).values({
      jobId: job.id,
      message: `job failed: ${err instanceof Error ? err.message : String(err)}`,
    });
    message.retry(); // governed by infra/jobs.ts's retry_delay/max_retries
  }
}
```

### Dead-letter queue

Cuando Cloudflare Queues agota los reintentos configurados en `infra/jobs.ts`, el mensaje pasa a `JobDLQ`. `apps/functions/src/dlq-consumer.ts` lee la línea de registro más reciente del trabajo (escrita por el consumidor anterior) como causa del error, inserta un registro `DeadLetterRecord` con el objeto `Job` original idéntico y lo confirma (ack); nunca reintenta por sí mismo. Reproducir un mensaje de dead-letter es una acción humana deliberada, no automática.

### Cron

`apps/functions/src/cron.ts` se ejecuta según el cronograma configurado en `infra/cron.ts` (`0 * * * *`, cada hora) y escribe una fila `Log`; `jobId` se establece por defecto en `"cron"` para estas ejecuciones, diferenciándolas de los registros de trabajos en cola.

## Configuration

```typescript [infra/jobs.ts]
export const jobsDeadLetterQueue = flags.jobsQueue
  ? new sst.cloudflare.Queue("JobDLQ")
  : undefined;

export const jobsQueue = flags.jobsQueue
  ? new sst.cloudflare.Queue("JobQueue", {
      maxConcurrency: 5,
      dlq: { queue: jobsDeadLetterQueue!.nodes.queue.queueName, retry: 3, retryDelay: "60 seconds" },
    })
  : undefined;
```

```typescript [infra/cron.ts]
export const emails = new sst.cloudflare.Cron("Cron", {
  schedules: ["0 * * * *"],
  job: { handler: "apps/functions/src/cron.ts", link: [database] },
});
```

## Admin operations

El estado de la cola, los mensajes de dead-letter y las líneas recientes del registro de cron se muestran en `/admin/queue`; consulte [Consola de Platform Admin](/docs/saas-starter-kit/features/platform-admin). Reproducir un mensaje fallido reenvía el objeto `Job` original a `JobQueue` y marca `replayedAt` (nunca se borra, por lo que un mensaje solo puede repetirse una vez desde la consola sin editar la base de datos directamente).

## Database Schema

- **`Job`** — `id`, `message`, `status` (`pending` / `processing` / `completed` / `failed`), `teamId`, marcas de tiempo.
- **`Log`** — `id`, `message`, `jobId` (por defecto `"cron"` en ejecuciones programadas), `createdAt`.
- **`DeadLetterRecord`** — `id`, `message` (jsonb: el objeto `Job` original completo para reproducirse tal cual), `error`, `teamId` (opcional, para capturar mensajes malformados), `createdAt`, `replayedAt` (`null` = nunca reproducido).

## Current scope

La creación de trabajos no está disponible para los inquilinos hoy. `jobsQueue.send()` solo se invoca desde la acción de repetición del administrador (`admin.queue.replayDeadLetter`); no existe interfaz de usuario ni procedimiento tRPC para que un inquilino encole un trabajo. La infraestructura de colas y cron es real y procesa mensajes genuinos de Workers; una cola de autoservicio para inquilinos se excluyó intencionalmente de la versión actual.
