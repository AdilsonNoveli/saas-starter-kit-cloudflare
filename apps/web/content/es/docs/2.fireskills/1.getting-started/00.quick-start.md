Fireskills viene dentro del repositorio de Nuxfire. No hay nada que instalar: las skills (`fireskills/skills/`), los especialistas técnicos (`fireskills/specialists/`), la CLI (`fireskills/cli/`) y el contexto del proyecto (`.specsfy/`) ya están en el código que descargaste.

Esta página te dice **qué escribir en el agente de tu IDE** para cada cosa que puedas querer hacer. Cada paso del flujo tiene su propia página en esta sección; la tabla de abajo enlaza a ellas.

---

## Cómo hablas con Fireskills

No ejecutas el flujo desde una terminal. **Escribes un prompt en el chat de tu agente de IA** (el panel del agente de tu IDE, abierto en la raíz del repositorio). El prompt nombra una skill con un `$` delante:

```text
Use $fireskill-01-inbox para registrar este texto imediatamente, sem perguntas, em specs/inbox/.
```

- `$fireskill-…` es una **convención de texto, no un comando de la IDE**. Este repositorio no registra las skills como slash commands: son archivos normales en `fireskills/skills/<name>/SKILL.md`. El agente resuelve el nombre a ese archivo.
- El repositorio incluye `AGENTS.md` y `CLAUDE.md` (que importa `AGENTS.md`). Un agente que lee cualquiera de los dos es dirigido a `fireskills/SKILL.md`, que asigna cada petición a la skill y al especialista correctos. Si tu agente no lee esos archivos, indícale la skill directamente: `Leia fireskills/skills/fireskill-01-inbox/SKILL.md e siga.`
- **Los prompts y las respuestas del agente están en portugués de Brasil.** Los prompts oficiales (`fireskills/skills/<skill>/agents/openai.yaml`) están en portugués, y el contrato de `fireskills/skills/Spec.md` exige que toda pregunta, opción y artefacto esté en Português do Brasil. Los prompts de esta página se citan literalmente.
- Después de tu prompt, añade tu propio contenido en las líneas siguientes (tu idea, la ruta de la spec, el diff). El prompt oficial es el texto inicial.
- Las skills se pasan el turno entre sí solas ("Transição automática: $fireskill-02-backlog → $fireskill-03-specify …"). Sigues respondiendo en la misma conversación; no vuelves a escribir comandos.

## Antes del primer prompt: mira el estado de la app

Dos comandos que puedes ejecutar tú mismo, desde la raíz del repositorio:

```bash
bun run fireskill progress
node fireskills/skills/fireskill-setup/scripts/monitor_context.mjs --project . --check
```

- `progress` lista cada spec con su estado, el recuento de tareas y los gates. En una copia nueva, sin specs, imprime `Resumo	0 specs	0/0 tarefas	0/0 itens	0%`.
- El monitor compara tus archivos **sin commit y sin seguimiento** con los archivos de contexto e imprime `Context monitor: CURRENT`, o lista qué documento de `.specsfy/*` necesita actualización. Después del commit vuelve a informar `CURRENT`.

Para entender qué es la aplicación y cómo está construida, lee (o pide al agente que lea) estos archivos, en este orden: `AGENTS.md` → `fireskills/SKILL.md` → `.specsfy/PROJECT.md` → `.specsfy/STACK.md` → `.specsfy/RULES.md`. Es el mismo camino que sigue un agente nuevo, así que un ingeniero nuevo y un agente empiezan con la misma visión. Consulta [Contexto del proyecto](/docs/fireskills/getting-started/project-context).

## El primer prompt (una vez)

Escribe esto la primera vez, o siempre que el contexto parezca desactualizado:

```text
Use $fireskill-setup para detectar o stack, consultar respostas confirmadas, adaptar as perguntas ao nível de conhecimento e monitorar pendências documentais.
```

Todas las demás skills de flujo ejecutan el setup por ti antes de empezar, así que no necesitas repetirlo. Detalles: [Paso 0: Setup](/docs/fireskills/getting-started/step-setup).

| Escribir la spec normativa | `Use $fireskill-03-specify para iniciar uma spec numerada no diretório atual e consolidar seus requisitos. …` | [Paso 3: Specify](/docs/fireskills/getting-started/step-specify) |

| Implementar la siguiente tarea | `Use $fireskill-07-implement para executar o próximo item do checklist em specs/<estado>/<NNNN>-<slug>/spec.md com BDD, TDD e evidência. …` | [Paso 7: Implement](/docs/fireskills/getting-started/step-implement) |

| Ver el progreso de todas las specs | `Use $fireskill-progress para mostrar o progresso geral de todas as especificações. …` (o `bun run fireskill progress`) | [Otros puntos de entrada](/docs/fireskills/getting-started/other-entry-points) |
| Conversar sobre una spec, o decidir qué guardar en la base de datos | `Use $fireskill-interviewer …` / `Use $fireskill-data-discovery …` | [Otros puntos de entrada](/docs/fireskills/getting-started/other-entry-points) |

Las líneas que terminan en `…` continúan, en el prompt oficial, con la frase `Orquestre transições automáticas com anúncio, execução e retomada na mesma conversa.` (el texto completo está en la página de cada paso).

## El flujo de un vistazo

```text
idea → inbox → backlog → spec → validate → tasks → TDD/BDD → implement → documentator → progress
        (1)      (2)      (3)      (4)       (5)      (6)        (7)          (8)
```

Tres actos, tres gates:

| Acto | Pasos | Gate | Carpeta de la spec después |
|---|---|---|---|
| I — Definir | 1 inbox, 2 backlog, 3 specify, 4 validate | Definition Gate | `specs/draft/` → `specs/defined/` |
| II — Diseñar y Probar | 5 tasks, 6 TDD/BDD | Plan Gate | `specs/planned/` |
| III — Entregar | 7 implement, 8 documentator | Delivery Gate | `specs/in-progress/` → `specs/review/` → `specs/completed/` |

Las skills mueven la spec entre carpetas por ti ejecutando `bun run fireskill transition <NNNN>-<slug> <folder>`. El identificador es el número de la spec (`0001`) o el nombre completo del directorio (`0001-convite-de-membros-por-e-mail`).

## Reglas que debes conocer antes de empezar

- Una pregunta por ronda, siempre numerada, siempre terminando con `Escrever outra resposta`, `Gere outras opções` y `Avançar`. Consulta [Flujo y gobierno](/docs/fireskills/getting-started/workflow).
- Una spec vive en un único archivo: `specs/<state>/<NNNN>-<slug>/spec.md`. No existen `plan.md` ni `tasks.md`.
- El agente carga el especialista del área (UI, tRPC, Drizzle…) **antes** de tocar código. Consulta [Especialistas técnicos](/docs/fireskills/specialists/overview).
- El deploy, el borrado de datos y otras acciones irreversibles siempre necesitan tu aprobación explícita. El flujo nunca ejecuta `bun run deploy` por su cuenta.
- Cuando el código y la documentación no coinciden, gana el código.
