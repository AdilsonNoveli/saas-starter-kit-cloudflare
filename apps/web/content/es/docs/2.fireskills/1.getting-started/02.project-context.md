El directorio `.fireskills/` es la memoria a largo plazo del proyecto. Los agentes lo leen antes de preguntarte nada, así que las decisiones se apoyan en hechos con commit y no en el historial del chat. El directorio conserva el nombre `.fireskills/` porque los scripts de las skills leen y escriben esa ruta.

---

## Los archivos

| Archivo | Qué guarda | Lo actualiza |
|---|---|---|
| `.fireskills/PROJECT.md` | Propósito, historia, capacidades y límites de la aplicación. | Tú y `$fireskill-setup` |
| `.fireskills/STACK.md` | Tecnologías estructurales, cada una con evidencia en archivo. | `$fireskill-aux-stack` |
| `.fireskills/RULES.md` | Reglas confirmadas por el equipo. | `$fireskill-aux-rules` |
| `.fireskills/DATABASE.md` | Tablas, columnas y relaciones de la base de datos. | `$fireskill-aux-database` |
| `.fireskills/INTERFACE.md` | Mapa de pantallas y componentes (`@nuxt/ui` v4 y Vue SFC), con archivos fuente y consumidores. | El flujo, en cada tarea de UI |
| `.fireskills/DESIGNSYSTEM.MD` | Dónde vive la personalización (`packages/tokens`) y las reglas para usarla. | Tú |
| `.fireskills/PACKAGES.md` | Inventario de paquetes derivado de los manifests y lockfiles. | `$fireskill-documentator` |
| `.fireskills/USER-PROFILE.md` | Tu nivel de conocimiento confirmado y las respuestas ya dadas en el setup, para que nadie pregunte dos veces. Creado por el setup. | `$fireskill-setup` |
| `.fireskills/LESSONS.md` y `lessons.json` | Lecciones aprendidas; consulta [Gobierno y decisiones](/docs/fireskills/skills/governance-and-decisions). Creado por el primer `lesson add`. | `bun run fireskill lesson …` |
| `.fireskills/SPECKIT.md` | Solo cuando el proyecto tiene `.specify/memory/constitution.md` (GitHub Spec Kit). No existe en Nuxfire. | `sync_speckit_context.mjs` |

El texto que escribes fuera de los bloques reservados del framework (`<!-- specsfy:…:start -->` … `<!-- specsfy:…:end -->`) nunca se sobrescribe.

## El monitor de contexto

```bash
node fireskills/skills/fireskill-setup/scripts/monitor_context.mjs --project . --check
```

El monitor mira los archivos que **cambiaste y aún no has confirmado con commit** (`git diff`, staged y sin seguimiento) e imprime qué documento de contexto exige cada cambio. Ignora `_docs/`, `fireskills/`, los propios archivos de contexto y los archivos de prueba.

| Si cambiaste… | Pide |
|---|---|
| `package.json`, `bun.lock` y otros manifests/lockfiles | `.fireskills/STACK.md` (`$fireskill-aux-stack`) |
| `package.json` | `.fireskills/PACKAGES.md` (`$fireskill-documentator`) |
| una ruta con `db`, `database`, `migrations`, `.sql` o `drizzle.config.*` | `.fireskills/DATABASE.md` (`$fireskill-aux-database`) |
| `AGENTS.md`, `CLAUDE.md`, `.editorconfig`, configuración de ESLint/Biome | `.fireskills/RULES.md` (`$fireskill-aux-rules`) |
| código fuente (`.ts`, `.vue`, `.js`…) en una carpeta llamada `app`, `api`, `components`, `lib`, `pages`, `routes`, `server` o `src` | revisión de `.fireskills/PROJECT.md` y reconstrucción de `docs/` (`$fireskill-documentator`) |

La salida es `Context monitor: CURRENT` cuando no se exige nada, o `Context monitor: PENDING` seguido de una línea por documento. Opciones: `--json`, `--paths <files…>` (verifica una lista dada en lugar de git), `--acknowledge-project-no-change` y `--acknowledge-rules-no-change` (registran que una revisión no encontró impacto).

El flujo ejecuta el monitor al inicio, después de cada tarea de implementación y antes del Delivery Gate. Una línea `PENDING` bloquea el cierre de la tarea.

## Mantén el contexto vivo

Rara vez editas estos archivos a mano. Cuando cambie algo estructural, pide al agente la skill correspondiente:

```text
Use $fireskill-aux-stack para monitorar o stack e atualizar .fireskills/STACK.md sem perder dados existentes.
Use $fireskill-aux-rules para revisar mudanças e registrar regras em .fireskills/RULES.md preservando o conteúdo atual.
Use $fireskill-aux-database para monitorar persistência e atualizar .fireskills/DATABASE.md após mudanças de dados.
```

Añaden al texto existente y no borran reglas ni filas que ya hayas escrito.
