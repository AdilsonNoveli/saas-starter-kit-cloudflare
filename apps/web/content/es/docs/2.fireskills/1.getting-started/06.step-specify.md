**Skill:** `fireskill-03-specify` · **Hace preguntas:** solo cuando el brief no basta (devuelve al backlog) · **Crea:** `specs/draft/<NNNN>-<slug>/spec.md`

## Cuándo usarlo

El brief del Paso 2 está listo, o ya sabes exactamente lo que quieres y quieres escribir la spec directamente.

## Qué escribir

```text
Use $fireskill-03-specify para iniciar uma spec numerada no diretório atual e consolidar seus requisitos. Orquestre transições automáticas com anúncio, execução e retomada na mesma conversa.
```

Añade debajo el ítem de backlog o una descripción breve.

## Qué hace el agente

1. Ejecuta `fireskills/skills/fireskill-03-specify/scripts/iniciar_spec.mjs --title "<name>"`. El script asigna el siguiente número y crea solo `specs/draft/<NNNN>-<slug>/spec.md` a partir de la plantilla.
2. Lee la captura del inbox, el ítem de backlog, tu petición y archivos reales del repositorio que revelen restricciones. Si no puede identificar problema, actor y resultado, vuelve a `$fireskill-02-backlog` y retoma después.
3. Rellena la plantilla. Mantiene la tabla de cabecera, los tres actos y las 18 secciones, numera los ítems nuevos sin reutilizar IDs (`US-001`, `FR-001`, `NFR-001`, `AC-001`, `DEC-001`) y escribe cada requisito como un comportamiento verificable.
4. Define **al menos tres `AC` distintos** para la funcionalidad completa y para cada `US`, `FR` y `NFR`. Un `AC` solo cuenta cuando declara el ID en su línea `**Cobre**`.
5. Para una entrega con pantalla (`Interface para pessoas: Sim`), rellena la sección 10 con stack, pantallas, flujo de información, menús, formularios y acciones, composición, los componentes Vue y `@nuxt/ui`, estados y accesibilidad. No se acepta un CRUD descrito solo como API y base de datos. Carga `$fireskill-specialist-ux-design`, `-ui-design` y el especialista de interfaz de la stack.
6. Si se consultó una fuente fuera del repositorio, guarda la evidencia permitida en `research/` y la indexa en la spec.
7. Se autoverifica mientras está en `Draft`:

   ```bash
   node fireskills/skills/fireskill-04-validate/scripts/validate_spec.mjs specs/draft/<NNNN>-<slug>/spec.md --allow-draft
   ```

8. Informa la ruta, el estado, los recuentos de `US`/`FR`/`NFR`/`AC`, los supuestos, y pasa el turno a `$fireskill-04-validate`.

## La cabecera de la spec (salida real)

```markdown
# Especificação integrada: Convite de membros por e-mail

| Campo | Valor |
| --- | --- |
| Formato | Specsfy/2.0 |
| ID | SPEC-0001 |
| Slug | 0001-convite-de-membros-por-e-mail |
| Status | Draft |
| Effort | 1 |
| Effort updated at | 2026-09-18 |
| Effort rationale | Estimativa inicial; revisar durante a descoberta. |
| Definition Gate | Pending |
| Plan Gate | Pending |
| Delivery Gate | Pending |
| Interface para pessoas | A definir |
```

La cabecera debe seguir siendo una tabla de dos columnas (`Campo` / `Valor`). El slug es igual al nombre del directorio.

## Las 18 secciones

| Acto | Secciones |
|---|---|
| I — Definir | 1 Problema e resultado · 2 Research e esclarecimentos · 3 Escopo e atores · 4 Princípios e restrições · 5 Histórias de usuário · 6 Cenários BDD de aceite · 7 Requisitos |
| II — Diseñar y probar | 8 Plano técnico · 9 Modelo de dados · 10 Interfaces e contratos · 11 Estratégia TDD · 12 Plano de testes e rastreabilidade · 13 Validações · 14 Tarefas · 15 Ordem de execução |
| III — Entregar y validar | 16 Dependências, riscos e suposições · 17 Decisões · 18 Definition of Done |

## Effort

Da a la spec una nota de dificultad de 1 a 10 (razonamiento y ejecución necesarios, no tiempo):

```bash
bun run fireskill effort 0001 4 --reason "tabela + e-mail + mutation tRPC"
```

Salida: `0001-convite-de-membros-por-e-mail	Effort 4/10`. El identificador es el número de la spec (`0001`) o el `<NNNN>-<slug>` completo; un número desconocido falla con `spec não encontrada`. Consulta la [escala de Effort](/docs/fireskills/methodology/effort-scale).
