**Skill:** `fireskill-07-implement` · **Hace preguntas:** no (va a `$fireskill-update-spec` si cambia el alcance) · **Modifica:** código de producción, pruebas, los checklists y la evidencia del `spec.md`, `.fireskills/*`

## Cuándo usarlo

La spec está en `specs/planned/` con `Plan Gate: Passed` y existen las pruebas que fallan. Escribe el prompt de nuevo para cada tarea siguiente, o deja que el agente continúe.

## Qué escribir

```text
Use $fireskill-07-implement para executar o próximo item do checklist em specs/<estado>/<NNNN>-<slug>/spec.md com BDD, TDD e evidência. Orquestre transições automáticas com anúncio, execução e retomada na mesma conversa.
```

## Qué hace el agente

**Antes del primer cambio**

1. Exige `Status: Planned` o `Implementing`, `Definition Gate: Passed` y `Plan Gate: Passed`. Si falta un gate o un RED, vuelve a `$fireskill-05-tasks` y no toca producción.
2. Si hay una pantalla, comprueba que el plan tenga tareas para pantallas, menús, formularios, acciones y componentes `@nuxt/ui`, y carga `$fireskill-specialist-nuxt-ui` antes de escribir cualquier `.vue` con componentes `U*`.
3. Comprueba el comando de prueba base con `check_database_safety.mjs`; sin una base de datos de prueba separada, no ejecuta ninguna prueba que toque la base de datos.
4. Define `Status: Implementing`, `Delivery Gate: In Progress` y ejecuta `bun run fireskill transition <id> in-progress`.
5. Elige la siguiente tarea lista:

   ```bash
   node fireskills/skills/fireskill-07-implement/scripts/next_task.mjs specs/in-progress/<NNNN>-<slug>/spec.md
   ```

**Para cada tarea** (marcada ítem por ítem, nunca en lote al final)

1. `PREP`: confirma ID, tipo, referencias, dependencias, archivos.
2. Carga el **especialista del área** antes de tocar código: `nuxt-ui` para `.vue`, `nuxt` para páginas y middleware, `trpc` para routers, `drizzle` para schema y migraciones, `nuxt-authorization` para permisos, `openauth` para el login, `cloudflare-workers` para Workers, `sst` para `infra/`. La tabla está en `fireskills/SKILL.md`.
3. `EXECUTE`: el cambio más pequeño que pone en verde la prueba TDD. Una tarea `[CODE]` sin su predecesor RED se detiene. Para `[MIGRATION]`, crea primero el archivo versionado, lo aplica en la base de **prueba** y consulta el estado.
4. Ejecuta el monitor de contexto; `PENDING` bloquea la tarea. Revisa `.fireskills/PROJECT.md` ante cualquier cambio de aplicación.
5. Después de cada tarea `[CODE]`, pasa el turno a `$fireskill-documentator` (consulta el [Paso 8](/docs/fireskills/getting-started/step-documentator)).
6. `VERIFY`: prueba focal, suite relacionada y comprobaciones estáticas, solo después de que el comando sea `SAFE`.
7. `VISUAL`: para una pantalla, compara el resultado renderizado con `.fireskills/DESIGNSYSTEM.MD` y `.fireskills/INTERFACE.md`: bordes, espaciado, márgenes, padding, tipografía, alineación, overflow, foco, contenido corto y largo, en los viewports relevantes. Sin pantalla, escribe `Não aplicável` y el motivo concreto.
8. `EVIDENCE`: registra comando, resultado e IDs en las secciones 11–13 (y el comentario JSON `specsfy:evidence` cuando `Evidence Contract: 1`, comprobado por `verify_evidence.mjs`).
9. `IMPROVE`: una mejora segura, o "nenhuma melhoria necessária" con el motivo.

**Si cambia el alcance** (comportamiento fuera de la spec, contradicción de un `AC`, interfaz pública, datos o seguridad): se detiene, lo anuncia y carga `$fireskill-update-spec`. Consulta [Cambios tardíos](/docs/fireskills/getting-started/late-changes).

## El gate de cierre

Cuando todas las tareas de la sección 14 están marcadas, el agente ejecuta, y tú puedes ejecutar lo mismo:

```bash
# tests of the whole repository (from the repository root)
bun run test

# types (from apps/app)
cd apps/app
bun run typecheck
bunx vue-tsc --noEmit -p server/tsconfig.json
cd ../..

# copy of the context and documentation checks
node fireskills/skills/fireskill-setup/scripts/monitor_context.mjs --project . --check
node fireskills/skills/fireskill-documentator/scripts/build_documentation.mjs --project . --check
```

`bun run typecheck` no existe en la raíz del repositorio: es un script de `apps/app`.

Después compara cada `AC`, `FR`, `NFR` e ítem de la Definition of Done con la evidencia actual, busca tareas abiertas, placeholders y pruebas omitidas, y solo entonces:

1. `Delivery Gate: Passed`, `Status: Reviewing` y `bun run fireskill transition <id> review`.
2. `$fireskill-04-validate` hace la aceptación final y mueve la spec a `specs/completed/`.
3. `$fireskill-progress` muestra el panorama global.

Para obtener un resumen que puedas pegar en un PR (solo imprime, no escribe ningún archivo):

```bash
node fireskills/skills/fireskill-07-implement/scripts/render_delivery.mjs specs/review/<NNNN>-<slug>/spec.md --format markdown
```

## Lo que no hará solo

- `bun run deploy`. Para cambios en `apps/functions` o `layers`, un `sst deploy` real es la comprobación que importa, y necesita tu autorización explícita.
- Ejecutar una prueba contra la base de datos de desarrollo, ni ningún comando destructivo en la base de datos.
