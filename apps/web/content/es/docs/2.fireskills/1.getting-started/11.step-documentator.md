**Skill:** `fireskill-documentator` · **Hace preguntas:** no · **Modifica:** `docs/` en la raíz del repositorio y `.specsfy/PACKAGES.md`

## Cuándo usarlo

- Después de cada tarea `[CODE]`: `$fireskill-07-implement` la llama por ti.
- Siempre que el [monitor](/docs/fireskills/getting-started/project-context) indique que hay que reconstruir `docs/` o `PACKAGES.md`.
- Bajo demanda, sin ninguna spec.

## Qué escribir

```text
Use $fireskill-documentator para reconstruir a documentação técnica em docs/ e o inventário .specsfy/PACKAGES.md.
```

## Qué hace el agente

1. Lee las instrucciones locales, `.specsfy/*`, manifests, lockfiles, metadatos instalados y el código existente.
2. Reconstruye la documentación:

   ```bash
   node fireskills/skills/fireskill-documentator/scripts/build_documentation.mjs --project .
   ```

3. Inspecciona los archivos generados y corrige a mano solo lo que el código no respalda.
4. Demuestra que el resultado coincide con el estado actual:

   ```bash
   node fireskills/skills/fireskill-documentator/scripts/build_documentation.mjs --project . --check
   ```

5. Registra el comando, el resultado y los archivos actualizados en la evidencia de la tarea.

No pregunta nada: lo que las fuentes no respaldan se escribe como no identificado.

## Qué escribe

| Dónde | Contenido |
|---|---|
| `docs/` (raíz del repositorio) | portal y orden de lectura, arquitectura, inventario de la aplicación, base de datos y entidades, flujos, pruebas, frontend (páginas, componentes Vue, `@nuxt/ui`), paquetes y librerías, integraciones y variables de configuración (sin valores secretos), decisiones |
| `.specsfy/PACKAGES.md` | todo paquete npm/Bun de los manifests y lockfiles, con gestor, alcance, nombre, versión y fuente |

El texto que escribiste fuera de los bloques marcados `specsfy:documentator` se conserva.

## Qué **no** escribe

La documentación pública de este sitio (`apps/web/content/docs/`) no la toca esta skill. Esas páginas se editan a mano.

`docs/` es un **inventario construido con heurísticas** a partir del código. Sirve para ver qué existe, pero no es prosa de arquitectura, y la propia skill prohíbe presentar una heurística como decisión confirmada. Para las tablas de la base de datos, la referencia es `.specsfy/DATABASE.md`.
