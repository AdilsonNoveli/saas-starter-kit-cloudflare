No todo empieza en el inbox. Cada bloque de abajo es un objetivo: el prompt que escribir y lo que ocurre realmente. Los prompts marcados como *oficiales* son el `default_prompt` de la skill (`agents/openai.yaml`).

---

## Ver cómo están las cosas

**Escribe** (*oficial*):

```text
Use $fireskill-progress para mostrar o progresso geral de todas as especificações. Orquestre transições automáticas com anúncio, execução e retomada na mesma conversa.
```

O ejecútalo tú mismo:

```bash
bun run fireskill progress
```

Cada spec se imprime con su estado y los recuentos de tareas e ítems. `--json` da la salida para máquinas, `--watch` vuelve a imprimir cuando cambia una spec. La skill también ofrece `node fireskills/skills/fireskill-progress/scripts/progress.mjs .` (con `--slug <slug>` para una sola spec) y lee el monitor de contexto y `build_documentation.mjs --check` para mostrar la documentación pendiente. No cambia ningún gate ni checkbox. Una cifra de tokens siempre se etiqueta `estimated`, salvo que proporciones el uso medido.

## Conversar sobre una spec

**Escribe** (*oficial*):

```text
Use $fireskill-interviewer para conversar sobre a spec no estado atual e registrar apenas respostas confirmadas.
```

Funciona con specs en `draft`, `defined`, `planned`, `in-progress` y `review`, y orienta la conversación según la carpeta (por ejemplo, en `defined` busca ambigüedad que afecte al plan, los datos, la seguridad o las pruebas). Registra las respuestas confirmadas en la sección correcta y ajusta el Effort. No aprueba gates, no ejecuta tareas y no mueve la spec. No entrevista para cambiar una spec `completed`.

## Decidir qué debe guardar el producto

**Escribe** (*oficial*):

```text
Use $fireskill-data-discovery para conversar em linguagem simples sobre o que o sistema precisa guardar e registrar apenas respostas confirmadas em DATABASE.md.
```

Pregunta en lenguaje cotidiano ("O que você precisa lembrar sobre cada pedido, pessoa ou atendimento?", "Quem pode ver ou mudar essa informação?"), propone una forma sencilla de registrar cada ítem y te pide que lo confirmes, y escribe en `.specsfy/DATABASE.md` solo las respuestas confirmadas. No elige tecnología. El backlog la llama automáticamente cuando la idea necesita datos guardados.

## Empezar desde un documento de MVP

**Escribe** (*oficial*):

```text
Use $fireskill-mvp-milestone-interviewer para importar o MVP como M01 e gerar backlogs e specs Draft somente para requisitos de desenvolvimento, sem criar Inboxes nem copiar o contexto de negócio.
```

**Requiere un `MVP.md` en la raíz del repositorio** (no hay ninguno en Nuxfire de serie). La skill ejecuta `importar_mvp.mjs --root <raiz>` una vez: crea `specs/milestones/M01.md` y, por cada ítem que es una entrega de software, un ítem de backlog y una spec `Draft` con `Definition Gate: Pending`. Visión, público, principios y métricas quedan solo en `MVP.md`. Después entrevista cada ítem de backlog, preguntando solo lo que el MVP no respondió.

Cuando el MVP esté aceptado:

```text
Use $fireskill-roadmap-milestone-interviewer para entrevistar a evolução pós-MVP e propor milestones sem alterar o núcleo aceito sem confirmação.
Use $fireskill-milestone-governor para analisar milestones, manter o índice derivado de specs e backlog e sugerir ajustes confirmáveis.
```

También puedes actualizar el índice tú mismo: `bun run fireskill milestones sync` actualiza `specs.md` y el progreso de cada milestone.

## Mantener el contexto del proyecto al día

**Escribe** (*oficial*, uno por archivo):

```text
Use $fireskill-aux-stack para monitorar o stack e atualizar .specsfy/STACK.md sem perder dados existentes.
Use $fireskill-aux-rules para revisar mudanças e registrar regras em .specsfy/RULES.md preservando o conteúdo atual.
Use $fireskill-aux-database para monitorar persistência e atualizar .specsfy/DATABASE.md após mudanças de dados.
```

El flujo las llama cuando el monitor lo pide. Consulta [Contexto del proyecto](/docs/fireskills/getting-started/project-context).

## Registrar y reutilizar lecciones aprendidas

**Escribe** (*oficial*):

```text
Use $fireskill-lessons para registrar uma lição aprendida com sinal, resumo, regra preventiva e origem em .specsfy/LESSONS.md, ou para consultar as lições confirmadas antes de planejar uma fatia.
```

Los comandos que usa (puedes ejecutarlos):

```bash
bun run fireskill lesson add --signal gate_fail --summary "Import relativo no schema" --rule "Importar schemas de layers pelo pacote @nuxfire/*" --source "0042-billing"
bun run fireskill lesson list          # confirmed lessons
bun run fireskill lesson list --all    # plus candidates and quarantined
bun run fireskill lesson status
bun run fireskill lesson prune         # removes expired candidates
```

`--signal` es uno de `ac_gap`, `surviving_mutant`, `spec_precision_gap`, `spec_deviation`, `gate_fail`; `--summary`, `--rule`, `--source` son todos obligatorios. Una lección empieza como `candidate` y se promueve a `confirmed` automáticamente cuando se repite en dos o más fuentes distintas.

## Atacar una spec, decidir algo arriesgado, revisar un cambio

Los prompts de abajo son los oficiales (`agents/openai.yaml` de cada skill).

| Objetivo | Escribe | Qué ocurre |
|---|---|---|
| Encontrar supuestos frágiles en una spec (recomendado para Effort 7 o más, o antes de aprobar un Definition Gate crítico) | `Use $fireskill-the-fool para atacar a spec specs/<estado>/<NNNN>-<slug>/spec.md com pre-mortem, steelman da posição oposta e auditoria de premissas não verificadas.` | Pre-mortem, el argumento más fuerte contra la decisión, efectos de segundo orden, auditoría de supuestos no verificados. Devuelve un informe ordenado por severidad y probabilidad. |
| Decidir una cuestión irreversible o de alto impacto | `Use $fireskill-the-jury para decidir esta questão de alto impacto com um painel de 3 a 5 subagentes, rodada cega, rubrica explícita e veredito com divergência registrada.` | Formula una pregunta decidible y una rúbrica de 2–4 criterios, crea un panel con roles ortogonales (proponente, escéptico, integrador), una **ronda ciega**, deliberación, y luego un veredicto vinculante con la disidencia registrada. Requiere un agente que pueda crear subagentes. |
| Revisar un diff o PR | `Use $fireskill-the-judge para revisar este diff ou PR com citações arquivo:linha, checagens locais primeiro, no máximo 5 nits e veredito APPROVE, COMMENT ou REQUEST_CHANGES.` | Ejecuta primero los linters locales, `vue-tsc` y Vitest, cita `file:line` en cada afirmación, como máximo 5 nits, y devuelve `APPROVE`, `COMMENT` o `REQUEST_CHANGES`. |
