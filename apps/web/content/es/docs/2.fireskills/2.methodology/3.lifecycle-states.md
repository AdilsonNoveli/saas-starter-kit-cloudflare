El estado de una spec se expresa dos veces: por la carpeta en la que está y por el campo `Status` de su cabecera. La CLI mantiene ambos sincronizados.

---

## Correspondencia de estados

| Carpeta | `Status` | Acto | Lo define |
|---|---|---|---|
| `specs/draft/` | `Draft` | I | `iniciar_spec.mjs` |
| `specs/defined/` | `Defined` | I → II | `$fireskill-04-validate` cuando el Definition Gate pasa |
| `specs/planned/` | `Planned` | II | `$fireskill-05-tasks` cuando el Plan Gate pasa |
| `specs/in-progress/` | `Implementing` | III | `$fireskill-07-implement` antes del primer cambio en producción |
| `specs/review/` | `Reviewing` | III | `$fireskill-07-implement` cuando el Delivery Gate pasa |
| `specs/completed/` | `Complete` | III | `$fireskill-04-validate`, en la aceptación final |

---

## El comando de transición

```bash
bun run fireskill transition <NNNN>-<slug> <folder>
```

Por ejemplo:

```bash
bun run fireskill transition 0001 defined
```

Salida real: `0001-convite-de-membros-por-e-mail	draft → defined	Defined`.

Qué hace:

1. Encuentra la spec por su número (`0001`) o por el nombre completo del directorio (`<NNNN>-<slug>`); un identificador desconocido falla con `spec not found`.
2. Acepta solo los movimientos de la tabla de abajo; cualquier otro falla con `invalid transition: <from> to <to>`.
3. Reescribe la línea `Status` del `spec.md` y mueve el paquete entero (con `research/`) a la carpeta de destino.
4. Se niega a sobrescribir un destino existente.
5. Actualiza después el índice de milestones (igual que `milestones sync`).

Lo que **no** hace: **no lee ni comprueba los gates.** Una spec cuyo `Definition Gate` está `Pending` puede moverse a `defined`. Los gates son responsabilidad de las skills, que solo mueven la spec después de que su gate ha pasado.

| Desde | Destinos permitidos |
|---|---|
| `draft` | `defined` |
| `defined` | `draft`, `planned` |
| `planned` | `defined`, `in-progress` |
| `in-progress` | `planned`, `review` |
| `review` | `in-progress`, `completed` |
| `completed` | `review` |

`bun run fireskill migrate` mueve las specs del diseño anterior (`specs/specs/`) a estas carpetas, una sola vez.

---

## Qué significa cada estado

- **Draft**: la spec se está escribiendo. Problema, actores, requisitos y escenarios aún se están definiendo.
- **Defined**: el Definition Gate pasó. El alcance queda fijado para la planificación.
- **Planned**: el Plan Gate pasó. Las tareas existen y las pruebas fallan por el motivo correcto (RED).
- **In progress**: implementación. Se cargan los especialistas, se escribe código hasta poner las pruebas en verde (GREEN), se hacen las revisiones visuales.
- **Review**: el Delivery Gate pasó; la aceptación final está pendiente. Aquí puedes ejecutar `$fireskill-the-judge` sobre el diff.
- **Completed**: aceptada. La evidencia, la documentación y la Definition of Done están registradas.

---

## Volver atrás

Volver atrás ocurre mediante `$fireskill-update-spec`, que define el estado y los gates que el cambio invalida (consulta [Gates de calidad](/docs/fireskills/methodology/three-gates)) y luego usa los movimientos hacia atrás permitidos arriba.
