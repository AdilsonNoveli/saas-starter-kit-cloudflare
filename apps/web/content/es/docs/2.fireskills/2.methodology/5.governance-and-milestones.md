Las especificaciones individuales no existen aisladas. Fireskills ofrece herramientas de gobierno de alto nivel para organizar porciones de funcionalidad en releases coherentes, productos mínimos viables (MVP) y roadmaps evolutivos a largo plazo.

---

## La jerarquía de milestones

```text
Product Vision
  └── Milestone (e.g., MVP v1.0)
        ├── Spec 0001: Authentication & Workspace Setup
        ├── Spec 0002: Core Domain Resource Management
        └── Spec 0003: Stripe Subscription Billing
```

---

## Skills de gobierno de milestones

Fireskills ofrece tres skills especializadas de gobierno para definir y mantener releases:

### 1. `fireskill-mvp-milestone-interviewer`
Se centra en definir el Producto Mínimo Viable inicial mediante estados de usuario demostrables y comprobables. Evita el crecimiento descontrolado del alcance indagando con rigor qué es esencial para que el producto funcione.

### 2. `fireskill-roadmap-milestone-interviewer`
Se usa para la evolución posterior al MVP. Una vez aceptada la milestone del MVP, esta skill organiza las siguientes peticiones de funcionalidad en milestones por etapas, con un impacto de negocio claro.

### 3. `fireskill-milestone-governor`
Mantiene la integridad relacional entre especificaciones, milestones y la proyección de roadmap `specs.md` generada, sin alterar las notas escritas por humanos.

## Sincronizar milestones desde la CLI

Para regenerar y sincronizar la vista macro del roadmap entre todas las especificaciones, ejecuta:

```bash
bun run fireskill milestones sync
```

Este comando:
1. Lee las specs (todas las carpetas de estado) y los ítems de backlog.
2. Actualiza los bloques derivados de `specs.md` (en la raíz del repositorio) y de `specs/milestones/<ID>.md`, con el progreso de cada milestone.
3. Deja intacto el texto escrito por humanos fuera de esos bloques.

## Integración con un rastreador de issues externo (ClickUp)

Al gestionar tareas entre equipos distribuidos, las especificaciones pueden vincularse directamente a herramientas externas de gestión de proyectos como ClickUp:

```markdown
| Campo | Valor |
| --- | --- |
| ClickUp Task | https://app.clickup.com/t/86a1b2c3d |
```

El campo de la cabecera forma parte de la plantilla. Las skills `clickupfy-*` que sincronizarían estado y Effort con ClickUp **no** forman parte de este repositorio; sin ellas el campo es solo un enlace, y la spec local es siempre la fuente de verdad.
