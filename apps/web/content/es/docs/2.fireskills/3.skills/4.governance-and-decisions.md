Más allá del flujo lineal, estas skills cuidan el contexto, las milestones y la calidad de las decisiones. Los prompts que escribir están en [Otros puntos de entrada](/docs/fireskills/getting-started/other-entry-points).

## Setup y cambio

| Skill | Finalidad |
|---|---|
| `fireskill-setup` | Reconcilia `.specsfy/*` y los bloques reservados de `AGENTS.md`/`CLAUDE.md`, pregunta tu nivel de conocimiento y los temas aún sin respuesta, ejecuta el monitor. Toda skill de flujo lo carga primero. [Paso 0](/docs/fireskills/getting-started/step-setup) |
| `fireskill-update-spec` | Incorpora un cambio a una spec que ya pasó el Definition Gate y reabre solo los actos afectados. [Cambios tardíos](/docs/fireskills/getting-started/late-changes) |
| `fireskill-interviewer` | Conversación sobre una spec en `draft`, `defined`, `planned`, `in-progress` o `review`; registra las respuestas confirmadas y ajusta el Effort. No aprueba gates ni mueve carpetas. |
| `fireskill-data-discovery` | Pregunta en lenguaje cotidiano qué debe guardar el producto y registra las respuestas confirmadas en `.specsfy/DATABASE.md`. |

## Milestones

| Skill | Finalidad |
|---|---|
| `fireskill-mvp-milestone-interviewer` | Importa un `MVP.md` (en la raíz del repositorio) como milestone `M01` y crea ítems de backlog y specs `Draft` para los requisitos de desarrollo. |
| `fireskill-roadmap-milestone-interviewer` | Una vez aceptado el MVP, entrevista la evolución y propone milestones posteriores al MVP sin cambiar en silencio el núcleo aceptado. |
| `fireskill-milestone-governor` | Mantiene al día el índice derivado (`specs.md`) y los vínculos de las milestones, y solo sugiere cambios. |

## Mantenimiento del contexto

`fireskill-aux-stack` (`.specsfy/STACK.md`), `fireskill-aux-rules` (`.specsfy/RULES.md`) y `fireskill-aux-database` (`.specsfy/DATABASE.md`) añaden a esos archivos sin borrar lo que escribiste. Consulta [Contexto del proyecto](/docs/fireskills/getting-started/project-context).

## Lecciones aprendidas: `fireskill-lessons`

Convierte un fallo real en una regla preventiva. El estado vive en `.specsfy/lessons.json` (propiedad del motor) y `.specsfy/LESSONS.md` (playbook que leen los agentes antes de escribir specs o tareas).

| Señal | Significado |
|---|---|
| `ac_gap` | un criterio de aceptación no se cubrió o falló en producción |
| `surviving_mutant` | una prueba siguió pasando tras una mutación de lógica |
| `spec_precision_gap` | una ambigüedad en la spec llevó a una implementación errónea |
| `spec_deviation` | la implementación se desvió del plan o de las convenciones |
| `gate_fail` | falló una comprobación de gate (typecheck, lint, Vitest) |

Una lección es `candidate` cuando se registra por primera vez, pasa a `confirmed` automáticamente cuando se repite en dos o más fuentes distintas, y a `quarantined` si resulta ser un falso positivo.

```bash
bun run fireskill lesson add --signal gate_fail --summary "Import relativo no schema" --rule "Importar schemas de layers pelo pacote @nuxfire/*" --source "0042-billing"
bun run fireskill lesson list [--all]
bun run fireskill lesson status
bun run fireskill lesson prune
```

## Decisiones y revisión

| Skill | Finalidad | Cómo funciona |
|---|---|---|
| `fireskill-the-fool` | Revisión adversarial de una spec, plan o decisión. Recomendada para Effort 7 o más, o antes de aprobar un Definition Gate crítico. | Pre-mortem, el argumento más fuerte de la posición opuesta, efectos de segundo orden, auditoría de supuestos no verificados. |
| `fireskill-the-jury` | Decisión colegiada sobre una cuestión irreversible o de alto impacto. | Crea un panel de 3 a 5 subagentes con roles ortogonales, una primera ronda ciega, deliberación, y un veredicto vinculante que conserva la disidencia. Requiere un agente que pueda crear subagentes. |
| `fireskill-the-judge` | Revisión de un diff o pull request. | Primero los linters locales, `vue-tsc` y Vitest; toda afirmación cita `file:line`; como máximo 5 nits; veredicto `APPROVE`, `COMMENT` o `REQUEST_CHANGES` (blocker, should-fix, nit). |
