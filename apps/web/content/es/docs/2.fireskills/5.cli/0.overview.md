La **CLI Fireskill** hace las partes mecánicas del flujo: mueve specs entre estados, registra la nota de esfuerzo, ejecuta un linter rápido de specs, muestra el progreso, sincroniza milestones y gestiona lecciones aprendidas. Su código está en `fireskills/cli/` y la llamas desde la raíz del repositorio:

```bash
bun run fireskill <command> [arguments] [options]
bun run fireskill --help
```

El `package.json` de la raíz asigna `fireskill` a `bun fireskills/cli/src/main.ts`. La CLI deriva de la CLI de Specsfy (licencia MIT), reducida al motor de flujo: no tiene instalador, catálogo ni actualizador, porque las skills y los especialistas ya están en el repositorio.

## Qué debes saber

- **En el flujo, las skills llaman a la CLI por ti.** La ejecutas tú para mirar el estado o para corregir algo a mano.
- Todo comando acepta `--project <path>` (por defecto: el directorio actual) y la mayoría acepta `--json`.
- Los comandos de spec identifican una spec por su número (`0001`) o por el nombre completo del directorio (`0001-convite-de-membros-por-e-mail`).
- La CLI está escrita en TypeScript con `commander` y necesita `bun`. En una copia limpia, `bun install --cwd fireskills/cli` instala su propia dependencia.
- Los cambios de estado se escriben de forma atómica (un archivo temporal y luego un rename).
