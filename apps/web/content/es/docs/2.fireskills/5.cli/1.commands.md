Todos los comandos se ejecutan desde la raíz del repositorio como `bun run fireskill <command>`. Opción común: `--project <path>` (raíz del proyecto; por defecto es el directorio actual). La mayoría de los comandos también acepta `--json`.

| Comando | Finalidad |
|---|---|
| `transition <id> <folder>` | mover una spec un paso |
| `effort <id> <1-10> --reason "…"` | definir la nota de esfuerzo |
| `validate <id> [--strict]` | linter rápido del `spec.md` |
| `progress [--json] [--watch] [--interval <s>]` | progreso de las specs |
| `milestones sync` | actualizar `specs.md` y el progreso de las milestones |
| `test` | ejecutar las pruebas del proyecto |
| `lesson add / list / status / prune` | lecciones aprendidas |
| `migrate` | mover specs del diseño antiguo |
| `config show / set` | configuración por proyecto |

`<id>` es el número de la spec (`0001`) o el nombre completo del directorio (`<NNNN>-<slug>`).

---

## `transition`

```bash
bun run fireskill transition <id> <draft|defined|planned|in-progress|review|completed>
```

Mueve el paquete de la spec un paso y reescribe `Status` (`Draft`, `Defined`, `Planned`, `Implementing`, `Reviewing`, `Complete`). Movimientos permitidos: `draft`→`defined`; `defined`→`draft`/`planned`; `planned`→`defined`/`in-progress`; `in-progress`→`planned`/`review`; `review`→`in-progress`/`completed`; `completed`→`review`. Los demás movimientos fallan con `transição inválida`.

Después del movimiento actualiza el índice de milestones (como `milestones sync`). **No comprueba los gates**: las skills solo mueven una spec después de que su gate pasa.

```text
0001-convite-de-membros-por-e-mail	draft → defined	Defined
```

## `effort`

```bash
bun run fireskill effort <id> <1-10> --reason "<rationale>"
```

Define `Effort`, `Effort updated at` (marca de tiempo ISO) y `Effort rationale`. Una nota fuera de 1–10 o una justificación vacía se rechaza. Salida: `0001-convite-de-membros-por-e-mail	Effort 4/10`.

## `validate`

```bash
bun run fireskill validate <id> [--strict] [--json]
```

Un **linter rápido**, no el Definition Gate. Informa error para: `Effort` ausente o fuera de 1–10, `Effort rationale` ausente o demasiado corto, `Status` ausente, y cualquiera de cinco secciones no encontradas por título (contexto/problema, actores/historias/requisitos/alcance, escenarios/BDD/aceptación, tareas/fases, pruebas/evidencia/validación). Avisa de la falta de un escenario BDD, la falta de una lista de tareas y los placeholders `[TODO]`, `[TBD]`, `[preencher]`, `[em aberto]`, `[descrever]`. `--strict` convierte los avisos en errores. El exit code es 1 cuando no es válida.

No cuenta criterios de aceptación, no comprueba el contrato de interfaz, no cambia gates ni mueve la spec. El gate es `node fireskills/skills/fireskill-04-validate/scripts/validate_spec.mjs <spec.md>`.

```text
Status: VÁLIDO (Aprovado no linter de specs)
Erros: 0 | Avisos: 0
```

## `progress`

```bash
bun run fireskill progress [--json] [--watch] [--interval <seconds>]
```

Una línea de resumen y una línea por spec, con los recuentos de tareas e ítems:

```text
Resumo	1 specs	0/6 tarefas	0/55 itens	0%
0001-convite-de-membros-por-e-mail	Draft	0/6 tarefas	0/55 itens	0%
```

`--watch` vuelve a imprimir cuando cambia una spec; el intervalo por defecto lo muestra `config show` (0,75 s).

## `milestones sync`

```bash
bun run fireskill milestones sync
```

Actualiza los bloques derivados de `specs.md` (raíz del repositorio) y de `specs/milestones/<ID>.md`. El texto fuera de los bloques se conserva.

## `test`

```bash
bun run fireskill test
```

Ejecuta `bun run test` desde la raíz del proyecto (el agregador de Vitest `vitest.config.mts`) y devuelve su exit code. No elige una base de datos: consulta el [guard de seguridad](/docs/fireskills/cli/governance-scripts).

## `lesson`

```bash
bun run fireskill lesson add --signal <signal> --summary "<text>" --rule "<text>" --source "<spec or PR>"
bun run fireskill lesson list [--all]
bun run fireskill lesson status
bun run fireskill lesson prune
```

`--signal` es `ac_gap`, `surviving_mutant`, `spec_precision_gap`, `spec_deviation` o `gate_fail`; `--signal`, `--summary`, `--rule` y `--source` son todos obligatorios. `list` muestra las lecciones confirmadas; `--all` añade las candidatas y las en cuarentena. `status` imprime los recuentos (`0 confirmadas, 1 candidatas, 0 em quarentena`). `prune` elimina las candidatas caducadas. Archivos: `.specsfy/lessons.json` y `.specsfy/LESSONS.md`. Consulta [Gobierno y decisiones](/docs/fireskills/skills/governance-and-decisions).

## `migrate`

```bash
bun run fireskill migrate
```

Una vez, mueve las specs del diseño anterior (`specs/specs/`) a las carpetas de estado.

## `config`

```bash
bun run fireskill config show
bun run fireskill config set --watch-interval <seconds>
```

`show` imprime `project` y `watch_interval` (por defecto `0.75`). `set` cambia el intervalo del watch.
