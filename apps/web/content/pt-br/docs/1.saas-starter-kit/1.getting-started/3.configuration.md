Preencha seu domínio e flags de recursos. Defina `prodDomain` para seu domínio real — é a única linha que você precisa editar: `devDomain`, `authEmailDomain` e o endereço remetente derivam dela. O domínio precisa ser uma zona ativa na mesma conta da Cloudflare dona do seu token de API. Desative também em `flags` qualquer integração que você não for usar (Stripe, Paddle, websockets, filas, provedores de e-mail desnecessários) — isso reduz a quantidade de secrets que você precisará configurar.

`authEmail.name` é o nome da sua marca nos e-mails que o Nuxfire envia (assunto e texto alternativo do logo), e o domínio do remetente precisa estar verificado no seu provedor de e-mail. O logo dos e-mails é carregado de `https://<prodDomain>/pwa-192x192.png`, servido pelo app `web`.

```typescript [config.ts]
export const prodDomain = "yourdomain.com"; // the only line you must edit
export const devDomain = `dev.${prodDomain}`;
export const authEmailDomain = prodDomain;
export const authEmail = {
  name: "Your Company",
  address: `contact@${authEmailDomain}`,
};

export const flags: {
  stripe?: boolean;
  paddle?: boolean;
  googleAuth?: boolean;
  githubAuth?: boolean;
  resend?: boolean;
  mailgun?: boolean;
  ses?: boolean;
  sparkPost?: boolean;
  smtp?: boolean;
  websockets?: boolean;
  cron?: boolean;
  jobsQueue?: boolean;
} = {
  stripe: true,
  paddle: true,
  githubAuth: true,
  googleAuth: true,
  resend: true,
  websockets: true,
  jobsQueue: true,
};
```

O mesmo arquivo também declara `layers` — independente de `flags`, diz respeito aos Nuxt Layers compilados dentro de `apps/app`, e não aos recursos provisionados na Cloudflare:

```typescript [config.ts]
export const layers = {
  // Always extended, never toggleable — every tenant needs them.
  core: ["teams", "billing", "notifications", "admin"] as string[],

  // Toggleable per build/deploy. `false` drops the layer's pages, components
  // and Nuxt config from the bundle entirely — it does NOT drop its tables
  // from the database schema (see Database).
  features: {
    kanban: true,
  } satisfies Record<string, boolean>,
};
```

`core` lista os quatro layers de domínio de negócios que todo deploy entrega (multilocação/RBAC, cobrança, notificações, o console de platform admin) — consulte [Estrutura do Projeto](/docs/saas-starter-kit/getting-started/project-structure). `features` é onde um layer opcional como `kanban` pode ser desativado para um build que não precise dele.

**Prompt para agentes de IA:**
```text
Open config.ts. Ask the user for their real domain and which
integrations they want before editing prodDomain (devDomain and
authEmailDomain derive from it — leave those lines as they are),
authEmail, and the flags object — do not guess or invent any of
these values. Only touch layers.features if the user explicitly asks to
disable an optional layer (e.g. kanban) — never touch layers.core.
```
