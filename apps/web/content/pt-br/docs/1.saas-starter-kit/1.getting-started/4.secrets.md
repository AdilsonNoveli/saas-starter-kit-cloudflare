O Nuxfire não usa arquivo `.env` em produção — os secrets vivem apenas no próprio cofre do SST. O caminho de deploy atual é 100% Cloudflare/SST; deploy automatizado via GitHub Actions (ou qualquer outro CI) é trabalho futuro, não um caminho alternativo existente hoje.

Não tem certeza de onde vem um valor específico? [Variáveis de Ambiente](/docs/saas-starter-kit/getting-started/environment-variables) traz links diretos para cada provedor — Cloudflare, seu host Postgres, cada provedor de e-mail/OAuth/pagamento e instruções de como gerar os dois secrets de platform admin localmente. Esta página cobre apenas a mecânica de *carregamento*.

## 1. Export the Cloudflare credentials as real environment variables

`CLOUDFLARE_API_TOKEN` e `CLOUDFLARE_ACCOUNT_ID` não podem ficar armazenados apenas como um secret do SST — o SST exige ambos como uma **variável de ambiente real** em todos os comandos (`secret load`, `secret set`, `deploy`, `dev`...), pois essa é a credencial que autentica o SST na Cloudflare antes mesmo de conseguir ler o cofre.

**PowerShell** (padrão no Windows):

```powershell
$env:CLOUDFLARE_API_TOKEN = "your_token"
$env:CLOUDFLARE_ACCOUNT_ID = "your_account_id"
```

Para persistir entre terminais: `[Environment]::SetEnvironmentVariable("CLOUDFLARE_API_TOKEN", "your_token", "User")` (e o mesmo para o account ID) — abra um novo terminal em seguida.

**bash/zsh**:

```bash
export CLOUDFLARE_API_TOKEN=your_token
export CLOUDFLARE_ACCOUNT_ID=your_account_id
```

Para persistir, adicione as duas linhas ao `.bashrc`/`.zshrc`.

## 2. Load the rest into SST's vault

**Um arquivo por estágio**, nunca um único `.env` reaproveitado. O `.env.example` é o modelo (todas as chaves, valores em branco):

```bash
cp .env.example .env.stage
# fill in .env.stage with your dev environment's values
bunx sst secret load .env.stage --fallback
```

Preencha primeiro a seção **Branding** — `BRAND_NAME`, `BRAND_DOMAIN` e `BRAND_EMAIL` (o endereço completo do remetente, ex.: `contato@acme.io`). É o único lugar onde seu domínio e seu e-mail de envio são definidos e, diferente das credenciais abaixo, estes valores não são secrets: o deploy os lê direto deste arquivo e, se algum faltar ou estiver malformado, para informando o nome da variável a corrigir. Cada estágio lê o seu próprio arquivo, então o `.env.production` também precisa da sua própria seção Branding.

`.env.stage`/`.env.production` são ignorados nos commits automaticamente (o `.gitignore` cobre `.env*`) — mantenha-os localmente, não os apague após o carregamento. Você precisará deles novamente sempre que um secret for alterado.

**Prompt para agentes de IA:**
```text
Ask the user to export CLOUDFLARE_API_TOKEN and CLOUDFLARE_ACCOUNT_ID in
their own shell first — never request, type, or store these values
yourself. Then: cp .env.example .env.stage, ask the user to fill it in
themselves (never fill in a credential on their behalf), then run
bunx sst secret load .env.stage --fallback.
```
