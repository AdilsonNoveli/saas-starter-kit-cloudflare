## Your first deploy

```bash
bun run deploy
```

Faz o deploy para o seu estágio de desenvolvimento pessoal (o SST usa o nome do usuário do seu sistema como nome do estágio por padrão).

**Prompt para agentes de IA:**
```text
Run bun run deploy. If it fails, check the error against AGENTS.md's
Infra / SST gotchas and Database sections before proposing a fix —
several documented failures (Supabase pooler/direct mismatch, missing
workers.dev subdomain, unenv version conflicts) read like a different
problem than they actually are.
```

## What happens automatically

`apps/functions/src/database/seed/index.ts` executa a cada deploy, logo após as migrações, e cria o plano Free juntamente com as funções/permissões do sistema — de forma idempotente, portanto executar novamente nunca duplica nada. Os planos pagos são deliberadamente deixados de fora (os IDs de preço do Stripe/Paddle variam por ambiente) — eles são criados em `/admin/plans` pelo proprietário da plataforma.

A conta do proprietário da plataforma e o console `/admin` protegido por MFA são um passo manual deliberado — consulte [Console de Platform Admin](/docs/saas-starter-kit/features/platform-admin).

## Deploying to other stages

- **Desenvolvimento**: usa o nome de usuário do seu sistema como nome do estágio por padrão — é o que `bun run deploy` executa sem flags adicionais.
- **Produção**: preencha `.env.production` com valores de produção reais, carregue-o e faça o deploy:
  ```bash
  bunx sst secret load .env.production --stage production
  bun run deploy -- --stage production
  ```
- **Estágios customizados**: `bun run deploy -- --stage custom-name` (o `--` é obrigatório para repassar a flag pelo wrapper do `bun run`).

**Prompt para agentes de IA:**
```text
For production: confirm .env.production is filled with real production
values (never copy .env.stage's values into it), then run
bunx sst secret load .env.production --stage production (no --fallback)
followed by bun run deploy -- --stage production. If the user needs a
platform-owner account, that's a separate step — see the Platform Admin
Console doc, and never seed a known owner password on a real environment.
```
