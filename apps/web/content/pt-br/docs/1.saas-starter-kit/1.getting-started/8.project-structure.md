title: "Estrutura do Projeto"
description: "Uma visão detalhada da estrutura da base de código monorepo do Nuxfire."
---

O Nuxfire é um monorepo baseado em workspaces do Bun (`apps/*`, `packages/*`, `layers/*`), todos sob o namespace `@nuxfire/*`. A pasta `apps/` abriga tudo o que possui seu próprio deploy; `packages/` guarda bibliotecas compartilhadas sem deploy próprio; `layers/` abriga Nuxt Layers plugáveis de regras de negócio, cada um estendido para dentro de `apps/app` e ativado/desativado no `config.ts` raiz.

- **`apps/app`** — a Raiz de Composição (Composition Root): a casca da aplicação (layout de dashboard, configurações de conta, composição tRPC), estendendo cada camada ativa. A lógica de negócios em si — gerenciamento de equipes, faturamento, notificações, console de platform admin — reside em `layers/`, e não aqui.
- **`apps/web`** — o site público: landing page, blog e esta documentação, construídos com Nuxt Content.
- **`apps/login`** — a interface de login/cadastro/recuperação de senha, gerada estaticamente e servida como assets estáticos do Worker de autenticação.
- **`apps/functions`** — código de Cloudflare Workers que não faz parte do app principal: o emissor de autenticação OpenAuth, o Worker de e-mails, o Worker de WebSockets, os consumidores de filas de trabalho/dead-letter e o Cron Worker horário. Também abriga `database/` — o agregador de schemas do Drizzle, migrações e scripts de seed.
- **`layers/teams`, `layers/billing`, `layers/notifications`, `layers/admin`** — os domínios de negócio centrais (multilocação/RBAC, assinaturas, notificações, console de platform admin), cada um sendo um Nuxt Layer autocontido com suas próprias páginas, componentes, roteador tRPC e fatia do schema do banco de dados.
- **`layers/kanban`** — um exemplo de camada de funcionalidade opcional, alternável independentemente das quatro camadas centrais.
- **`packages/emails`** — `packages/emails/templates`, templates de e-mail construídos com React Email, mais `packages/emails/mailer`, o motor de envio agnóstico de provedor (um fork vendored do AdonisJS Mail) — consulte [E-mails](/docs/saas-starter-kit/features/emails).
- **`packages/tokens`** — `@nuxfire/tokens`, a fonte única da verdade para temas (cores da marca, raio de borda, mapeamento de superfícies para modo escuro, overrides de componentes Nuxt UI), consumida igualmente por todos os apps e layers — consulte [Design System e Marca](/docs/saas-starter-kit/concepts/design-system).
- **`packages/manifest`** — `@nuxfire/manifest`, o contrato compartilhado `defineLayerManifest()` que o `layer.manifest.ts` de cada camada utiliza.

Tudo fora de `apps/`, `packages/` e `layers/` que não seja código de aplicação é infraestrutura: `infra/*.ts` define cada recurso da Cloudflare com SST — consulte [SST.dev](/docs/saas-starter-kit/concepts/sst) para entender como esses arquivos carregam e o que é um estágio.
