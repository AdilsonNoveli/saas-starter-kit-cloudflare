O Nuxfire é um monorepo baseado em workspaces do Bun (`apps/*`, `packages/*`, `layers/*`), todos sob o namespace `@nuxfire/*`. A pasta `apps/` abriga aplicações com deploy próprio; `packages/` guarda bibliotecas compartilhadas sem deploy próprio; `layers/` abriga Nuxt Layers plugáveis de domínio de negócio, cada um estendido para dentro de `apps/app` e configurado no `config.ts` raiz.

## Monorepo Breakdown

### Applications (`apps/`)

- **`apps/app`** — a Raiz de Composição (Composition Root): a casca da aplicação (layout de dashboard, navegação, composição tRPC), estendendo cada camada ativa. A lógica de negócios em si reside em `layers/`, e não aqui.
- **`apps/web`** — o site público: landing page, blog e esta documentação, construídos com Nuxt Content.
- **`apps/login`** — a interface de login/cadastro/recuperação de senha, gerada estaticamente e servida como assets estáticos do Worker de autenticação.
- **`apps/functions`** — código de Cloudflare Workers: o emissor de autenticação OpenAuth, o Worker de e-mails, o Worker de WebSockets, os consumidores de filas de trabalho/dead-letter e o Cron Worker horário. Também abriga `src/database/` — o schema base do Drizzle e migrações.

### Domain Layers (`layers/`)

Os domínios de negócio residem em `layers/` como Nuxt Layers modulares. Cada camada com estado persistente possui seu próprio `drizzle.config.ts`, diretório `migrations/` e `layer.manifest.ts`:

- **Camadas Centrais (`layers.core`)**: Sempre compiladas e ativas para todos os tenants:
  - **`layers/account`** (`@nuxfire/layer-account`) — perfil de usuário, upload de avatar, preferências de aparência, sessões ativas, exclusão de conta, MFA do usuário (TOTP com registro, desafio e códigos de recuperação) e fluxo de onboarding (`/onboarding`).
  - **`layers/teams`** (`@nuxfire/layer-teams`) — multilocação, workspaces de equipe, membros, convites, papéis e permissões RBAC (`nuxt-authorization`), seletor de equipes e modelos de filas/DLQ (`Job`, `DeadLetterRecord`).
  - **`layers/notifications`** (`@nuxfire/layer-notifications`) — notificações em tempo real no app via WebSockets, slideover de notificações e rastreamento de leitura.
  - **`layers/admin`** (`@nuxfire/layer-admin`) — console de platform admin (`/admin`), MFA obrigatório para administradores, logs de auditoria, gerenciamento de DLQ e visão geral de empresas.
- **Camadas de Funcionalidade (`layers.features`)**: Alternáveis de forma independente no `config.ts`:
  - **`layers/billing`** (`@nuxfire/layer-billing`) — assinaturas Stripe e Paddle, checkouts, portal de faturamento, webhooks, planos e benefícios, e aba de faturamento nas configurações de equipe.
  - **`layers/kanban`** (`@nuxfire/layer-kanban`) — quadros kanban opcionais, colunas, cartões/tarefas, drag-and-drop e item na barra lateral de navegação da equipe.

### Shared Packages (`packages/`)

- **`packages/crypto`** (`@nuxfire/crypto`) — primitivas de segurança puras com Web Crypto: criptografia/descriptografia AES-GCM, HMAC-SHA256, comparação em tempo constante `secretsMatch`, códigos de recuperação MFA e tickets assinados de WebSocket. Zero dependências em tempo de execução.
- **`packages/rate-limit`** (`@nuxfire/rate-limit`) — algoritmo puro de rate limiting de janela fixa (`core.ts`) e adaptadores (`adapters.ts`) para Cloudflare KV (`kvNamespaceStore`) e NuxtHub KV (`hubKvStore`).
- **`packages/emails`** (`@nuxfire/emails`) — `packages/emails/templates` (templates de e-mail construídos com React Email) mais `packages/emails/mailer` (motor de envio agnóstico para Resend, SES, Mailgun, SparkPost, SMTP) — consulte [E-mails](/docs/saas-starter-kit/features/emails).
- **`packages/tokens`** (`@nuxfire/tokens`) — `@nuxfire/tokens`, a fonte única da verdade para temas (cores da marca, raio de borda, mapeamento de superfícies para modo escuro, overrides de componentes Nuxt UI), consumida igualmente por todos os apps e layers — consulte [Design System e Marca](/docs/saas-starter-kit/concepts/design-system).
- **`packages/manifest`** (`@nuxfire/manifest`) — `@nuxfire/manifest`, o contrato compartilhado `defineLayerManifest()` que o `layer.manifest.ts` de cada camada utiliza.

Tudo fora de `apps/`, `packages/` e `layers/` que não seja código de aplicação é infraestrutura: `infra/*.ts` define cada recurso da Cloudflare com SST — consulte [SST.dev](/docs/saas-starter-kit/concepts/sst).

## Architecture Tree

```text
nuxfire/
├── apps/
│   ├── app/           # Composition Root: UI shell & tRPC composition
│   ├── functions/     # Cloudflare Workers: Auth issuer, Mailer, WebSockets, Cron, Queues
│   ├── login/         # Static Nuxt auth UI: Login, Signup, Forgot Password
│   └── web/           # Public site: Landing page, Blog, Docs (Nuxt Content)
├── layers/
│   ├── account/       # Core: Profile, preferences, sessions, user MFA, onboarding
│   ├── admin/         # Core: Platform admin console, admin MFA, audit logs, DLQ
│   ├── billing/       # Feature: Stripe & Paddle billing, checkouts, plans
│   ├── kanban/        # Feature: Boards, lists, task cards, drag-and-drop
│   ├── notifications/ # Core: In-app notifications, WebSocket delivery, slideover
│   └── teams/         # Core: Multi-tenancy, memberships, invitations, RBAC
├── packages/
│   ├── crypto/        # Pure Web Crypto: AES-GCM, HMAC, constant-time compare, tickets
│   ├── emails/        # React Email templates & provider-agnostic mailer engine
│   ├── manifest/      # Layer manifest contracts & defineLayerManifest schema
│   ├── rate-limit/    # Fixed-window rate limiting core & KV adapters
│   └── tokens/        # Design tokens, color themes, CSS variables & theme.css
└── infra/             # SST infrastructure definitions (Cloudflare resources)
```
