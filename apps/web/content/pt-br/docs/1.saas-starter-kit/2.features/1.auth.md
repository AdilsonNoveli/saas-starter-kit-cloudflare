## Nuxfire Auth

O Nuxfire vem com o **Nuxfire Auth**, um servidor de autenticação independente construído sobre o [OpenAuth.js](https://github.com/openauthjs/openauth). Ele pode proteger qualquer frontend ou backend e é implantado em `auth.SEU-DOMINIO.com`.

### Infrastructure

- **Cloudflare Worker:**
  - Configurado em `infra/auth.ts` com um binding de Assets servindo a compilação estática do frontend.
  - Gerencia a lógica de autenticação em `apps/functions/src/auth.ts` usando o OpenAuth.js.
  - Credenciais para contas baseadas em senha residem unicamente em um namespace de Cloudflare KV dedicado, o `AuthKV`, vinculado com exclusividade a este Worker — nunca no banco de dados Postgres.
- **Frontend Nuxt:**

  Localizado no pacote `apps/login` (construído estaticamente com `nuxt generate`, servido como assets estáticos do Worker de autenticação), ele inclui interface de usuário para:

  - Login
  - Cadastro
  - Esqueci minha senha

### Key Features

- **Logins Sociais:** Google e GitHub, cada um controlado de forma independente pelas flags `githubAuth`/`googleAuth` em `config.ts` — a interface de login só exibe o botão do provedor quando a flag estiver ativa e seu client id/secret estiverem realmente carregados como secrets.
- Login baseado em código
- Login com e-mail/senha
- Recuperação de senha
- Verificação de e-mail
- **Extensível:** Adicione novos métodos de autenticação facilmente conforme necessário.

## Two-Factor Authentication (optional, self-service)

Qualquer usuário pode ativar a autenticação de dois fatores via TOTP em **Configurações da Conta → Segurança** — independente e arquiteturalmente separada do MFA do proprietário da plataforma abordado em [Console de Platform Admin](/docs/saas-starter-kit/features/platform-admin). Exige que `USER_MFA_SESSION_SECRET` e `USER_MFA_ENCRYPTION_KEY` estejam configurados (consulte [Variáveis de Ambiente](/docs/saas-starter-kit/getting-started/environment-variables)) — sem eles, ativar o 2FA falha com um erro claro em vez de prosseguir silenciosamente de modo inseguro; nada mais na aplicação é afetado se ficarem indefinidos.

- A **ativação** acontece em um modal (`components/account/MfaSetupModal.vue`), e não em uma página inteira: clique em **Ativar 2FA**, escaneie o QR code com um aplicativo autenticador e digite o código de seis dígitos exibido.
- **Verificado uma vez por login**, não por timer. Após o cadastro, na próxima vez que essa conta fizer login em um navegador ainda não verificado, `layouts/dashboard.vue` abre o mesmo modal — desta vez solicitando apenas um código, sem QR — antes que qualquer página abaixo possa carregar dados. Essa checagem é um atalho de UX; a imposição real é no servidor, no `protectedProcedure` (`server/trpc/trpc.ts`), pelo qual todo procedimento tRPC da aplicação passa.
- A **desativação** é uma confirmação única nas configurações de Segurança — acessível apenas porque chegar até lá já exigiu aprovação na checagem acima.
- **Limitação conhecida**, idêntica à do console de platform admin: sem recuperação self-service para autenticador perdido. Restaurar o acesso requer limpar o campo `mfaEnabledAt` desse usuário diretamente no banco de dados, da mesma forma como um platform admin bloqueado é recuperado hoje.

## Team Authentication

A autenticação de equipes é gerenciada dentro do pacote do aplicativo: `apps/app`. Inclui:

- **Criação de Equipes** – Usuários podem criar equipes e gerenciar membros.
- **Seletor de Equipes** – Usuários podem alternar entre múltiplas equipes.
- **Convites e Gestão de Usuários** – Convide usuários, gerencie funções e remova membros. A autorização no lado do servidor para essas ações é abordada em [Controle de Acesso Baseado em Funções](/docs/saas-starter-kit/features/rbac).
