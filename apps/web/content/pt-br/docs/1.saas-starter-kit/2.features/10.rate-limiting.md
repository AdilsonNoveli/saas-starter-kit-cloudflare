---
title: "Limite de Taxa (Rate Limiting)"
description: "Rate limiting de janela fixa apoiado por Cloudflare KV, protegendo endpoints de login, MFA e webhooks de pagamento."
---

Um limitador de taxa de janela fixa baseado em Cloudflare KV, implementado duas vezes — uma por runtime de Worker, com a mesma estrutura e semântica em ambos:

- `apps/app/server/utils/rate-limit.ts` — usa `hubKV()` dentro do runtime Nitro do Worker App.
- `apps/functions/src/rate-limit.ts` — recebe diretamente um `KVNamespace` bruto (`AuthKV`), já que o Worker de autenticação não possui Nitro/NuxtHub para chamar `hubKV()`.

```typescript [apps/app/server/utils/rate-limit.ts]
export async function rateLimit(key: string, { limit, windowSeconds }) {
  // Cloudflare KV rejects a TTL under 60s, so the window can't be shorter.
  const window = Math.max(windowSeconds, 60);
  const kv = hubKV();
  const windowId = Math.floor(Date.now() / 1000 / window);
  const kvKey = `ratelimit:${key}:${windowId}`;
  const count = ((await kv.get<number>(kvKey)) ?? 0) + 1;
  await kv.set(kvKey, count, { ttl: window });
  return { allowed: count <= limit, count, limit };
}
```

`assertNotRateLimited(event, routeKey, options)` encapsula isso para rotas HTTP no Worker App: ele usa como chave `<routeKey>:<ip>` e lança diretamente `429 Too Many Requests` quando o limite é excedido.

## What's currently protected

| Where | Keyed by | Purpose |
|---|---|---|
| `apps/functions/src/auth.ts` (`enforceCredentialRateLimit`) | path + IP + email | Login por senha/código no Worker de autenticação |
| `layers/admin/server/api/admin/mfa/verify.post.ts` | platform admin id | Tentativas de cadastro de MFA |
| `layers/admin/server/api/admin/mfa/challenge.post.ts` | platform admin id | Tentativas de reautenticação de MFA |
| `layers/billing/server/api/webhooks/stripe.post.ts` | IP | Webhook do Stripe, sobreposto à validação de assinatura |
| `layers/billing/server/api/webhooks/paddle.post.ts` | IP | Webhook do Paddle, sobreposto à validação de assinatura |

Isto não é um controle genérico de requisições de API — é aplicado especificamente onde a validação de credenciais ou assinaturas não impede repetições em alto volume: tentativas de autenticação e endpoints de webhook não autenticados. Não há rate limiting em procedimentos comuns de tRPC hoje.
