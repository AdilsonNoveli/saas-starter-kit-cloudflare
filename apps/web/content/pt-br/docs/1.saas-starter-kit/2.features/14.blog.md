O Nuxfire vem com um blog construído com o [Nuxt Content](https://content.nuxt.com/). Adicione arquivos markdown para começar a publicar: o build valida cada post e gera seus metadados de busca e de redes sociais.

## What's Included

- Páginas de índice e de post, com um único `<h1>` por post
- Integração com busca em todo o site
- SEO completo por post: título, descrição, canonical, tags Open Graph e Twitter, dados estruturados `BlogPosting`, idioma, hreflang e `lastmod` no sitemap
- Posts em vários idiomas, ligados entre si como traduções
- Uma verificação `bun run check:seo` que detecta regressões
- Design responsivo e suporte a modo escuro

## File Structure

Os artigos do blog residem em `apps/web/content/blog`, como uma coleção própria do Nuxt Content (`apps/web/content.config.ts`). Cada post é um arquivo markdown cujo frontmatter é validado no build:

```yaml
---
title: "Specific title without the brand"
description: "One or two sentences that describe this post."
date: "2026-09-25"
author: "Your Name"
lang: en
ogImage: "/images/blog/my-cover.png"
---
```

## Frontmatter

| Campo | Obrigatório | Significado |
| --- | --- | --- |
| `title` | Sim | O título da página e o único `<h1>`. A marca é adicionada automaticamente: não a escreva. |
| `description` | Sim | Descrição do post para buscadores e redes sociais, nunca a descrição padrão do site. |
| `date` | Sim | `YYYY-MM-DD` ou um datetime ISO 8601 com fuso horário. Uma data sem hora significa meia-noite UTC. |
| `updated` | Não | Mesmo formato, nunca anterior a `date`. Alimenta `article:modified_time` e o `lastmod` do sitemap. |
| `author` | Sim | O nome do autor exibido na página e nos dados estruturados. |
| `authorType` | Não | `Person` ou `Organization` (padrão `Organization`). |
| `lang` | Sim | `en`, `pt-br` ou `es`. Não tem valor padrão: define `<html lang>`, `og:locale` e hreflang. |
| `translations` | Não | Idioma para slug de cada versão do post, incluindo a própria. |
| `category` | Não | Exibida no card e usada como `article:section`. |
| `readTime` | Não | Exibido no card, por exemplo `8 min`. |
| `tags` | Não | Usadas como `article:tag` e como `keywords` nos dados estruturados. |
| `image` | Não | A capa exibida na página do post. Pode ser um SVG. |
| `ogImage` | Não | A imagem que as redes sociais leem: um caminho `.png` ou `.jpg` em `apps/web/public`. Usa a imagem padrão do site quando ausente. |

## Traduções

O blog tem um post por idioma. Ligue as versões de um post repetindo o mesmo bloco `translations` em todas elas; cada chave é o idioma do post para o qual aponta:

```yaml
translations:
  en: my-post-english-slug
  pt-br: my-post-portuguese-slug
  es: my-post-spanish-slug
```

O head e o sitemap passam a listar todas as versões de forma recíproca, com `x-default` apontando para a versão em inglês. O `bun run check:seo` falha se uma versão estiver ausente, estiver escrita em outro idioma ou não apontar de volta.

## Imagens de capa

Desenhe a capa como um SVG 16:9 em `apps/web/public/images/blog` e depois gere o PNG que as redes sociais leem. A documentação de compartilhamento do Facebook lista JPEG, GIF e PNG para `og:image`; SVG não está entre eles.

```bash
bun run generate:og
```

O comando grava um PNG de 1200x675 ao lado de cada capa SVG e da imagem padrão do site (`apps/web/public/images/og/default.svg`), e executá-lo duas vezes não altera nada. Ele roda na sua máquina com `sharp`, então abra cada PNG e faça o commit.

## Verifique antes de publicar

Compile o site com o endereço real e execute a verificação sobre as páginas geradas:

```bash
SITE_URL=https://your-domain bun run --cwd apps/web build
bun run check:seo
```

- Todo post tem idioma, datas válidas, um `ogImage` raster que existe e um conjunto de traduções consistente.
- Toda página tem título e descrição próprios, um `<h1>`, canonical absoluto, imagem social e, nos posts, dados estruturados `BlogPosting` no idioma correto.
- O sitemap lista todo post com `lastmod` e o mesmo hreflang do head da página, e não lista nada que peça para não ser indexado.

Sem um build, o comando ainda valida o frontmatter de todos os posts e informa que a auditoria das páginas foi ignorada. Para escrever posts com um agente de IA, carregue o especialista de conteúdo descrito em [Nuxfire Stack Specialists](/docs/fireskills/specialists/nuxfire-stack).
