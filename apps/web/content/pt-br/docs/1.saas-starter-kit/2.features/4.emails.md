title: "E-mails"

O Nuxfire inclui um sistema de envio de e-mails executado integralmente em Cloudflare Workers, baseado em um fork vendored do [AdonisJS Mail](https://adonisjs.com) adaptado para rodar sem o framework AdonisJS — `@nuxfire/emails/mailer` (`packages/emails/mailer`), código próprio mantido no repositório em vez de uma dependência externa.

## Architecture

- **Templates de E-mail** (`packages/emails/templates`) — templates fortemente tipados usando [React Email](https://react.email)
- **Motor de Envio (Mailer Engine)** (`packages/emails/mailer`) — motor agnóstico de provedor, baseado no AdonisJS Mail
- **Worker de E-mails** (`apps/functions/src/emails.ts`) — um Worker Entrypoint da Cloudflare que gerencia o envio independente de provedor
- **Infraestrutura** (`infra/emails.ts`) — configuração de infraestrutura do Worker

## Email Templates

Os templates são construídos com [React Email](https://react.email) e Tailwind. Por exemplo:

```tsx [packages/emails/templates/Welcome.tsx]
import { Body, Container, Html, Text } from "@react-email/components";

export const WelcomeEmail = ({ username }: { username: string }) => (
  <Html>
    <Body>
      <Tailwind>
        <Container class="p-4 border border-solid border-[#eaeaea] rounded my-[40px] mx-auto max-w-[465px]">
          <Text>Welcome {username}!</Text>
        </Container>
      </Tailwind>
    </Body>
  </Html>
);
```

## Provider Configuration

Os provedores de e-mail são ativados em `flags` no arquivo `config.ts` e conectados no próprio Worker de e-mails. Apenas o Resend vem descomentado por padrão — os outros transportes estão prontos para ativação com linhas de importação/configuração marcadas com `TODO`:

```typescript [config.ts]
export const authEmail = {
  name: "Your Company",
  address: "auth@yourdomain.com",
};
export const authEmailDomain = "yourdomain.com";
export const flags: {
  // ...
  resend?: boolean;
  mailgun?: boolean;
  ses?: boolean;
  sparkPost?: boolean;
  smtp?: boolean;
} = {
  // ...
  resend: true,
};
```

```typescript [apps/functions/src/emails.ts]
// TODO: import and set up email providers that you want to use
import { ResendTransport } from "@nuxfire/emails/mailer/transports/resend";
// import { MailgunTransport } from "@nuxfire/emails/mailer/transports/mailgun";
// ...

const config: Parameters<typeof generateMailer>[0] = {
  default: "resend",
  mailers: {
    ...(flags.resend && {
      resend: () =>
        new ResendTransport({
          key: Resource.RESEND_API_KEY.value || "",
          baseUrl: "https://api.resend.com",
        }),
    }),
    // ...(flags.mailgun && { mailgun: () => new MailgunTransport({ ... }) }),
  },
};
```

`Resource.RESEND_API_KEY` coincide com o nome do secret (`RESEND_API_KEY` em `.env.example`/`infra/secret.ts`) — todos os secrets de provedores seguem este padrão `SCREAMING_SNAKE_CASE`, resolvidos através do binding `sst/resource` do SST em vez de `process.env`.

## Setting Up Secrets

```bash
# Resend
sst secret set RESEND_API_KEY re_123...
# Mailgun
sst secret set MAILGUN_API_KEY key-123...
```

## Sending Emails

Use a função `sendEmail` do contexto do tRPC para enviar e-mails:

```typescript
async ({ ctx: { user, origin, authorize, sendEmail }, input }) => {
  // ...
  await sendEmail(authEmail, invite.email, "Invitation", {
    teamName: team.name,
    invitedBy: user.name,
    inviteLink,
  });
  // ...
};
```

O Worker de e-mails também pode ser acionado diretamente a partir de qualquer pacote através do utilitário `sender`:

```typescript
import { sender } from "@nuxfire/functions/sender";
const sendEmail = sender(event.context?.cloudflare?.env?.Emails); // pass the Emails binding
```
