## Architecture

O Nuxfire processa trabalho em segundo plano com duas primitivas independentes da Cloudflare:

1. **Tarefas baseadas em fila** — Cloudflare Queues, controladas pela flag `jobsQueue` em `config.ts`.
2. **Cron** — um Cloudflare Cron Trigger, implantado incondicionalmente hoje; `infra/cron.ts` atualmente não checa a flag `cron` tipada em `flags` de `config.ts`.

### Queue consumer

`apps/functions/src/jobs-consumer.ts` processa mensagens em lotes. Em caso de sucesso, marca o trabalho como `completed` e registra uma linha de log `job completed`; em caso de falha, marca como `failed`, grava o texto do erro no log e chama `message.retry()`:

```typescript [apps/functions/src/jobs-consumer.ts]
for (const message of batch.messages) {
  const job = message.body as typeof schema.jobs.$inferSelect;
  try {
    await db.update(schema.jobs).set({ status: "completed" }).where(eq(schema.jobs.id, job.id));
    await db.insert(schema.logs).values({ jobId: job.id, message: "job completed" });
    message.ack();
  } catch (err) {
    await db.update(schema.jobs).set({ status: "failed" }).where(eq(schema.jobs.id, job.id));
    await db.insert(schema.logs).values({
      jobId: job.id,
      message: `job failed: ${err instanceof Error ? err.message : String(err)}`,
    });
    message.retry(); // governed by infra/jobs.ts's retry_delay/max_retries
  }
}
```

### Dead-letter queue

Quando o Cloudflare Queues esgota as tentativas configuradas em `infra/jobs.ts`, a mensagem é encaminhada para `JobDLQ`. O arquivo `apps/functions/src/dlq-consumer.ts` lê a linha de log mais recente da tarefa (escrita pelo consumidor acima) como o motivo da falha, insere um `DeadLetterRecord` contendo o objeto original `Job` verbatim e confirma (ack) — ele nunca tenta novamente por conta própria. Reprocessar uma mensagem em dead-letter é uma ação humana deliberada, não automática.

### Cron

`apps/functions/src/cron.ts` roda no agendamento definido em `infra/cron.ts` (`0 * * * *` — a cada hora) e grava uma linha na tabela `Log`; `jobId` assume o padrão `"cron"` para essas execuções agendadas, diferenciando-as dos logs de tarefas de fila.

## Configuration

```typescript [infra/jobs.ts]
export const jobsDeadLetterQueue = flags.jobsQueue
  ? new sst.cloudflare.Queue("JobDLQ")
  : undefined;

export const jobsQueue = flags.jobsQueue
  ? new sst.cloudflare.Queue("JobQueue", {
      maxConcurrency: 5,
      dlq: { queue: jobsDeadLetterQueue!.nodes.queue.queueName, retry: 3, retryDelay: "60 seconds" },
    })
  : undefined;
```

```typescript [infra/cron.ts]
export const emails = new sst.cloudflare.Cron("Cron", {
  schedules: ["0 * * * *"],
  job: { handler: "apps/functions/src/cron.ts", link: [database] },
});
```

## Admin operations

A integridade das filas, mensagens em dead-letter e logs recentes do cron são exibidos em `/admin/queue` — consulte [Console de Platform Admin](/docs/saas-starter-kit/features/platform-admin). Reprocessar uma mensagem da dead-letter reenvia o objeto `Job` original para `JobQueue` e preenche `replayedAt` (nunca apagado, para que uma mensagem só possa ser reenviada uma vez pelo console sem intervenção direta no banco de dados).

## Database Schema

- **`Job`** — `id`, `message`, `status` (`pending` / `processing` / `completed` / `failed`), `teamId`, timestamps.
- **`Log`** — `id`, `message`, `jobId` (padrão `"cron"` para execuções agendadas), `createdAt`.
- **`DeadLetterRecord`** — `id`, `message` (jsonb — o objeto original `Job` inteiro, para que possa ser reprocessado como está), `error`, `teamId` (anulável — uma mensagem malformada ainda pode ser registrada), `createdAt`, `replayedAt` (`null` = nunca reprocessado).

## Current scope

A criação de tarefas não está exposta aos locatários (tenants) hoje. `jobsQueue.send()` é chamado apenas pela ação de replay do admin (`admin.queue.replayDeadLetter`) — não há interface de usuário nem procedimento tRPC voltado para o tenant enfileirar novos trabalhos ainda. A infraestrutura de filas e cron é real e processa mensagens genuínas de Workers; uma fila de trabalhos self-service para tenants foi intencionalmente deixada fora do escopo desta versão.
