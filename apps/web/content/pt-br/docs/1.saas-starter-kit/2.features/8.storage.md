O Nuxfire usa o Cloudflare R2 para armazenamento de blobs — imagens de perfil e logos de equipes hoje.

Ele utiliza especificamente os utilitários do módulo `@nuxt-hub/core` para isso, embora o banco de dados seja Postgres via Hyperdrive em vez de um armazenamento gerenciado pelo NuxtHub (consulte [Banco de Dados](/docs/saas-starter-kit/features/database)): o modo self-hosted do NuxtHub espera um binding literalmente chamado `BLOB` (definido pelo próprio NuxtHub), de modo que o bucket R2 é nomeado para corresponder a essa exigência em vez de ser implantado através da plataforma do NuxtHub.

## Configuration

O R2 é configurado em dois lugares:

```typescript [apps/app/nuxt.config.ts]
export default defineNuxtConfig({
  hub: {
    blob: true, // enables R2 storage using NuxtHub's utilities
    kv: true,
    cache: true,
  },
});
```

Infraestrutura como código:

```typescript [infra/utils/nuxt.ts]
// NuxtHub's self-hosted mode expects this binding named exactly BLOB —
// that's fixed by NuxtHub itself, not something `link` can rename.
link.push(
  database,
  new sst.cloudflare.Bucket("BLOB"),
  new sst.cloudflare.Kv("KV"),
  new sst.cloudflare.Kv("CACHE"),
  emails,
);
```

## Usage

```typescript
// Get the blob client
const blob = hubBlob();

// Upload a file
await blob.put("path/to/file.jpg", fileContent);

// Download a file
const file = await blob.get("path/to/file.jpg");

// Delete a file
await blob.del("path/to/file.jpg");
```

### Real-world example: profile pictures

```typescript
// Delete the old profile picture before storing the new one
const previousKey = user.image.slice(baseUrl.length);
if (previousKey.startsWith("profile/")) {
  try {
    await hubBlob().del(previousKey);
  } catch {
    // didn't exist
  }
}
```
