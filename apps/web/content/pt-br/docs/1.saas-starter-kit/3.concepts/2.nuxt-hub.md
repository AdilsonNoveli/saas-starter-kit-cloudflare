O [NuxtHub](https://hub.nuxt.com) é normalmente tanto um módulo Nuxt (`@nuxt-hub/core`) *quanto* uma plataforma de hospedagem — você escreve código contra os utilitários `hubBlob()`/`hubKV()`/`hubDatabase()` e depois faz o deploy via CLI própria do NuxtHub, que provisiona e fatura os recursos da Cloudflare para você.

O Nuxfire usa apenas a metade referente ao módulo. A implantação é feita 100% via [SST](/docs/saas-starter-kit/concepts/sst) — nada é provisionado ou faturado pela plataforma do NuxtHub.

## Why use it at all, then

Os utilitários do `@nuxt-hub/core` são convenientes o suficiente para manter mesmo sem a rota de deploy do NuxtHub, e um detalhe reforça essa conexão: o modo self-hosted do NuxtHub espera seus bindings nomeados **exatamente** como `BLOB`, `KV`, `CACHE` — essa nomenclatura é fixada pelo próprio NuxtHub, não algo que o `link` do SST possa renomear. Por isso, `infra/utils/nuxt.ts` provisiona recursos reais da Cloudflare com esses nomes exatos:

```typescript [infra/utils/nuxt.ts]
link.push(
  database,
  new sst.cloudflare.Bucket("BLOB"),
  new sst.cloudflare.Kv("KV"),
  new sst.cloudflare.Kv("CACHE"),
  emails,
);
```

```typescript [apps/app/nuxt.config.ts]
export default defineNuxtConfig({
  hub: {
    blob: true,
    kv: true,
    cache: true,
  },
});
```

## What's actually used

- **`hubBlob()`** — Armazenamento de arquivos R2. Usado hoje para imagens de perfil e logos de equipes (consulte [Armazenamento](/docs/saas-starter-kit/features/storage)).
- **`hubKV()`** — Cloudflare KV. Usado para janelas de rate limiting (`apps/app/server/utils/rate-limit.ts`) e pequenos valores em cache, como o ID de configuração do fluxo de cancelamento do Stripe.
- **`CACHE`** — Provisionado (`hub: { cache: true }`), mas nada na aplicação invoca `hubCache()` hoje. Fica disponível para quando uma rota necessitar da camada de cache do Nitro, sem ser crítico para o funcionamento atual.

**Não utilizado de forma alguma:** `hubDatabase()`. O banco de dados do Nuxfire é Postgres via Cloudflare Hyperdrive (consulte [Banco de Dados](/docs/saas-starter-kit/features/database)) — uma escolha deliberada em relação ao módulo D1 do NuxtHub, permitindo apontar a aplicação para qualquer Postgres padrão em vez de prendê-la ao D1.

## Local development

Como o aplicativo é construído sobre o módulo Nuxt do `@nuxt-hub/core`, o painel do NuxtHub Dev Tools funciona localmente durante `bun run app` (que usa wrangler/miniflare para emular os bindings da Cloudflare) — sem exigir uma conta no NuxtHub ou fazer deploy por ele.
