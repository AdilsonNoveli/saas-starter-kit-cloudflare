Cada token de design — cores da marca, raio de canto (border-radius), mapeamento de superfícies para modo escuro e personalizações de componentes do Nuxt UI — vive em um único pacote no workspace: `@nuxfire/tokens`, consumido por `apps/app`, `apps/web` e `apps/login` igualmente. Antes desse pacote existir, cada aplicativo duplicava seu próprio `app.config.ts` e `main.css` — gerando o risco de um app divergir silenciosamente dos demais. Reformular a marca agora significa editar um arquivo, não três.

## The package

```
packages/tokens/
├── theme.css   # Tailwind @theme tokens, dark-mode mapping, corner radius
└── index.ts    # sharedUiConfig (Nuxt UI app.config.ts fragment) + enterpriseTableUi
```

Uma aplicação consumidora conecta o pacote em três lugares:

```json [package.json]
{ "dependencies": { "@nuxfire/tokens": "workspace:*" } }
```

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";
@import "@nuxfire/tokens/theme.css"; /* after @nuxt/ui, so it wins over its defaults */
```

```ts [app/app.config.ts]
import { sharedUiConfig } from "@nuxfire/tokens";

export default defineAppConfig({
  ui: { ...sharedUiConfig }, // app-specific keys can follow the spread
});
```

### The @source gotcha

O pacote chega a cada app através de um link simbólico em `node_modules` (um workspace do Bun), e o Tailwind não examina `node_modules` procurando por classes CSS por padrão. Sem a linha abaixo, qualquer classe que exista **apenas** dentro de `index.ts` (por exemplo, uma variação em `compoundVariants` como `before:bg-primary/15`) renderizaria no DOM sem nenhuma regra CSS associada — quebrada silenciosamente, sem mensagem de erro. O arquivo `theme.css` já inclui essa correção:

```css
@source "./index.ts";
```

Se o `index.ts` incluir futuramente uma classe utilitária genuinamente nova — não utilizada anteriormente no código verificado do app —, essa diretiva é o que a mantém ativa.

## Brand accent — shared across all three apps

`flame` (vermelho, `primary`) e `fire` (laranja, `secondary`) são definidos uma única vez em `theme.css`, idênticos byte a byte em cada aplicativo. `ui.colors` mapeia `primary: 'flame'`, `secondary: 'fire'` em `sharedUiConfig`.

## Neutral scale — intentionally different per app

Diferente do tom de destaque da marca, a escala de superfícies neutras (`night-*`) **não** é compartilhada — cada app define a sua em seu próprio `main.css`, usando os mesmos nomes de tokens com tonalidades distintas:

- **`apps/app`** usa uma escala fria de cinza puro, idêntica a painéis corporativos de referência (estilo Linear) — este é o painel de trabalho e o console de platform admin, onde uma base neutra e o destaque de marca reservado para ações/destaques é o padrão em SaaS (GitHub, Linear, Vercel seguem a mesma convenção).
- **`apps/web`** e **`apps/login`** usam um cinza quente com toques acobreados — a identidade do site público da marca.

Mudar o tom base de uma aplicação nunca afeta as outras duas — edite apenas o bloco `--color-night-*` daquele aplicativo.

## Corner radius — one token drives everything

```css
:root {
  --ui-radius: 0.1875rem; /* 3px */
}
```

O Nuxt UI deriva toda a sua escala `rounded-*` proporcionalmente a partir dessa única variável (`--radius-lg: calc(var(--ui-radius) * 2)`, e assim por diante), de modo que cada card, botão, input, modal e badge se ajusta uniformemente em uma única edição — sem necessidade de sobrescrever componente por componente.

## Shadow policy

Superfícies estáticas (cards, seções, painéis) utilizam **zero sombras** — a separação visual vem de uma borda/`ring` de 1px, nunca de `box-shadow`. Camadas flutuantes (modais, menus dropdown, popovers, tooltips) mantêm sua sombra: elas flutuam sobre o conteúdo sem fundo fosco, de modo que a sombra é o único elemento de profundidade — esse é o comportamento padrão do Nuxt UI, mantido intacto.

## Component overrides (sharedUiConfig)

| Component | Override | Why |
|---|---|---|
| `UCard` | `bg-elevated` em vez de `bg-default` | A variante padrão deixava o card com a mesma cor da página (contraste 1:1, medido) — `bg-elevated` oferece uma elevação nítida. |
| `UAvatar` (neutro, sem imagem) | `bg-accented` em vez de `bg-elevated` | O fallback padrão compartilhava o fundo do próprio card, fazendo avatares sem foto em cards não terem fundo visível. |
| `UNavigationMenu` (vertical) | Ícones de 24px (eram 20px), linhas recolhidas em quadrado centralizado `size-11`, item ativo recebe `ring` colorido além do fundo | Proporciona uma área de toque quadrada nítida e um estado ativo com borda destacada. |
| `UTabs` | Variante `link` por padrão em vez de `pill` | Um bloco sólido de cor da marca soa pesado visualmente em comparação com o sublinhado usado nas telas de configurações. |
| `UTable` (`enterpriseTableUi`) | Cabeçalho pequeno, atenuado, em maiúsculas e com espaçamento entre letras | Alinha-se à convenção visual de tabelas usada por Linear/Stripe/Notion, em vez de um cabeçalho grande e pesado. |

`enterpriseTableUi` é entregue separadamente de `sharedUiConfig`, passado explicitamente pela prop `:ui` de cada `<UTable>` — props de instância sempre têm precedência.

## Accessibility — measured, not estimated

O mapeamento de superfícies claras/escuras em `theme.css` vem de medições reais de contraste com o app em execução (fórmula de luminância relativa do WCAG), e não de suposições. O mapeamento original do Nuxt UI mediu um card em **1.00:1** contra o fundo da página (invisível) e ícones inativos em **2.61:1** (abaixo do piso WCAG AA de 4.5:1). A escala atual de texto no modo escuro contra o fundo `#0d0d0d` atinge: 18.7:1 / 15.6:1 / 12.1:1 / 5.48:1 — todos os níveis superam o padrão AA, com o nível `dimmed` intencionalmente mais suave pois também alimenta placeholders.

## Rebranding checklist

- **Alterar a cor de destaque em todo o projeto**: edite as escalas `flame-*`/`fire-*` em `packages/tokens/theme.css`.
- **Alterar o raio dos cantos em todo o projeto**: edite `--ui-radius` no mesmo arquivo.
- **Alterar a aparência padrão de um componente**: edite `sharedUiConfig`/`enterpriseTableUi` em `packages/tokens/index.ts`.
- **Alterar apenas o tom neutro de uma aplicação**: edite a escala `--color-night-*` no `main.css` daquela aplicação — não em `packages/tokens`.
- **Customizar algo apenas para uma aplicação**: faça o spread de `sharedUiConfig` no `app.config.ts` da aplicação e adicione as propriedades após o spread — a última definição prevalece.

Cada token é uma propriedade personalizada CSS, nunca uma classe fixada no componente, servindo também como base ideal para um futuro editor de temas por locatário: sobrescrever um conjunto de variáveis `--ui-*`/`--color-*` em tempo de execução alcança todos os componentes sem esforço adicional.
