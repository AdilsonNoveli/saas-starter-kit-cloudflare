O Fireskills já vem dentro do repositório do Nuxfire. Não há nada para instalar: as skills (`fireskills/skills/`), os especialistas técnicos (`fireskills/specialists/`), a CLI (`fireskills/cli/`) e o contexto do projeto (`.fireskills/`) já estão no código que você baixou.

Esta página diz **o que digitar no agente da sua IDE** para cada coisa que você pode querer fazer. Cada etapa do fluxo tem a sua própria página nesta seção; a tabela abaixo aponta para elas.

---

## Como você fala com o Fireskills

Você não executa o fluxo por um terminal. Você **digita um prompt no chat do seu agente de IA** (o painel do agente da sua IDE, aberto na raiz do repositório). O prompt nomeia uma skill com um `$` na frente:

```text
Use $fireskill-01-inbox para registrar este texto imediatamente, sem perguntas, em specs/inbox/.
```

- `$fireskill-…` é uma **convenção de texto, não um comando da IDE**. Este repositório não registra as skills como slash commands: elas ficam como arquivos comuns em `fireskills/skills/<name>/SKILL.md`. O agente resolve o nome para esse arquivo.
- O repositório traz `AGENTS.md` e `CLAUDE.md` (que importa o `AGENTS.md`). Um agente que lê qualquer um dos dois é levado a `fireskills/SKILL.md`, que mapeia cada pedido para a skill e o especialista certos. Se o seu agente não lê esses arquivos, aponte a skill diretamente: `Leia fireskills/skills/fireskill-01-inbox/SKILL.md e siga.`
- **Os prompts e as respostas do agente estão em português do Brasil.** Os prompts oficiais (`fireskills/skills/<skill>/agents/openai.yaml`) são em português, e o contrato em `fireskills/skills/Spec.md` exige que toda pergunta, opção e artefato esteja em Português do Brasil. Os prompts desta página são citados literalmente.
- Depois do seu prompt, acrescente o seu conteúdo nas linhas seguintes (sua ideia, o caminho da spec, o diff). O prompt oficial é o texto inicial.
- As skills passam a vez umas para as outras sozinhas ("Transição automática: $fireskill-02-backlog → $fireskill-03-specify …"). Você continua respondendo na mesma conversa; não precisa digitar os comandos de novo.

## Antes do primeiro prompt: veja o estado do app

Dois comandos que você mesmo pode rodar, a partir da raiz do repositório:

```bash
bun run fireskill progress
node fireskills/skills/fireskill-setup/scripts/monitor_context.mjs --project . --check
```

- `progress` lista cada spec com seu estado, contagem de tarefas e gates. Numa cópia nova, sem specs, ele imprime `Summary	0 specs	0/0 tasks	0/0 items	0%`.
- O monitor compara os seus arquivos **não commitados e não rastreados** com os arquivos de contexto e imprime `Context monitor: CURRENT`, ou lista qual documento de `.fireskills/*` precisa de atualização. Depois do commit, ele volta a informar `CURRENT`.

Para entender o que é a aplicação e como ela é construída, leia (ou peça ao agente que leia) estes arquivos, nesta ordem: `AGENTS.md` → `fireskills/SKILL.md` → `.fireskills/PROJECT.md` → `.fireskills/STACK.md` → `.fireskills/RULES.md`. É o mesmo caminho que um agente novo segue, então um engenheiro novo e um agente começam com a mesma visão. Veja [Contexto do Projeto](/docs/fireskills/getting-started/project-context).

## O primeiro prompt (uma vez)

Digite isto na primeira vez, ou sempre que o contexto parecer desatualizado:

```text
Use $fireskill-setup para detectar o stack, consultar respostas confirmadas, adaptar as perguntas ao nível de conhecimento e monitorar pendências documentais.
```

Todas as outras skills de fluxo rodam o setup por você antes de começar, então você não precisa repeti-lo. Detalhes: [Etapa 0: Setup](/docs/fireskills/getting-started/step-setup).

| Ver o progresso de todas as specs | `Use $fireskill-progress para mostrar o progresso geral de todas as especificações. …` (ou `bun run fireskill progress`) | [Outros pontos de entrada](/docs/fireskills/getting-started/other-entry-points) |
| Conversar sobre uma spec, ou decidir o que guardar no banco de dados | `Use $fireskill-interviewer …` / `Use $fireskill-data-discovery …` | [Outros pontos de entrada](/docs/fireskills/getting-started/other-entry-points) |

As linhas que terminam em `…` continuam, no prompt oficial, com a frase `Orquestre transições automáticas com anúncio, execução e retomada na mesma conversa.` (o texto completo está na página de cada etapa).

## O fluxo num relance

```text
idea → inbox → backlog → spec → validate → tasks → TDD/BDD → implement → documentator → progress
        (1)      (2)      (3)      (4)       (5)      (6)        (7)          (8)
```

Três atos, três gates:

| Ato | Etapas | Gate | Pasta da spec depois |
|---|---|---|---|
| I — Definir | 1 inbox, 2 backlog, 3 specify, 4 validate | Definition Gate | `specs/draft/` → `specs/defined/` |
| II — Projetar e Provar | 5 tasks, 6 TDD/BDD | Plan Gate | `specs/planned/` |
| III — Entregar | 7 implement, 8 documentator | Delivery Gate | `specs/in-progress/` → `specs/review/` → `specs/completed/` |

As skills movem a spec entre as pastas por você, rodando `bun run fireskill transition <NNNN>-<slug> <folder>`. O identificador é o número da spec (`0001`) ou o nome completo do diretório (`0001-convite-de-membros-por-e-mail`).

## Regras que você deve conhecer antes de começar

- Uma pergunta por rodada, sempre numerada, sempre terminando com `Escrever outra resposta`, `Gere outras opções` e `Avançar`. Veja [Fluxo e Governança](/docs/fireskills/getting-started/workflow).
- Uma spec vive em um único arquivo: `specs/<state>/<NNNN>-<slug>/spec.md`. Não existem `plan.md` nem `tasks.md`.
- O agente carrega o especialista da área (UI, tRPC, Drizzle…) **antes** de tocar em código. Veja [Especialistas Técnicos](/docs/fireskills/specialists/overview).
- Deploy, exclusão de dados e outras ações irreversíveis sempre precisam da sua aprovação explícita. O fluxo nunca roda `bun run deploy` por conta própria.
- Quando o código e a documentação divergem, o código vence.
