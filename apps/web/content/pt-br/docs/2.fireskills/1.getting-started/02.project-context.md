O diretório `.fireskills/` é a memória de longo prazo do projeto. Os agentes o leem antes de perguntar qualquer coisa a você, então as decisões se apoiam em fatos commitados e não no histórico do chat. O diretório mantém o nome `.fireskills/` porque os scripts das skills leem e escrevem esse caminho.

---

## Os arquivos

| Arquivo | O que guarda | Atualizado por |
|---|---|---|
| `.fireskills/PROJECT.md` | Finalidade, história, capacidades e limites da aplicação. | Você e o `$fireskill-setup` |
| `.fireskills/STACK.md` | Tecnologias estruturais, cada uma com evidência em arquivo. | `$fireskill-aux-stack` |
| `.fireskills/RULES.md` | Regras confirmadas pelo time. | `$fireskill-aux-rules` |
| `.fireskills/DATABASE.md` | Tabelas, colunas e relações do banco de dados. | `$fireskill-aux-database` |
| `.fireskills/INTERFACE.md` | Mapa de telas e componentes (`@nuxt/ui` v4 e Vue SFC), com arquivos-fonte e consumidores. | O fluxo, a cada tarefa de UI |
| `.fireskills/DESIGNSYSTEM.MD` | Padrões visuais, padrões de CRUD e dashboard, estados. | Você |
| `.fireskills/PACKAGES.md` | Inventário de pacotes derivado dos manifests e lockfiles. | `$fireskill-documentator` |
| `.fireskills/USER-PROFILE.md` | Seu nível de conhecimento confirmado e as respostas já dadas no setup, para ninguém perguntar duas vezes. | `$fireskill-setup` |
| `.fireskills/LESSONS.md` e `lessons.json` | Lições aprendidas; veja [Governança e decisões](/docs/fireskills/skills/governance-and-decisions). | `bun run fireskill lesson …` |
| `.fireskills/SPECKIT.md` | Só quando o projeto tem `.specify/memory/constitution.md` (GitHub Spec Kit). Não existe no Nuxfire. | `sync_speckit_context.mjs` |

O texto que você escreve fora dos blocos reservados do framework (`<!-- specsfy:…:start -->` … `<!-- specsfy:…:end -->`) nunca é sobrescrito.

## O monitor de contexto

```bash
node fireskills/skills/fireskill-setup/scripts/monitor_context.mjs --project . --check
```

O monitor olha os arquivos que **você alterou e ainda não commitou** (`git diff`, staged e não rastreados) e imprime qual documento de contexto cada mudança exige. Ele ignora `_docs/`, `fireskills/`, os próprios arquivos de contexto e os arquivos de teste.

| Se você mudou… | Ele pede |
|---|---|
| `package.json`, `bun.lock` e outros manifests/lockfiles | `.fireskills/STACK.md` (`$fireskill-aux-stack`) |
| `package.json` | `.fireskills/PACKAGES.md` (`$fireskill-documentator`) |
| um caminho com `db`, `database`, `migrations`, `.sql` ou `drizzle.config.*` | `.fireskills/DATABASE.md` (`$fireskill-aux-database`) |
| `AGENTS.md`, `CLAUDE.md`, `.editorconfig`, configuração de ESLint/Biome | `.fireskills/RULES.md` (`$fireskill-aux-rules`) |
| código-fonte (`.ts`, `.vue`, `.js`…) em uma pasta chamada `app`, `api`, `components`, `lib`, `pages`, `routes`, `server` ou `src` | revisão do `.fireskills/PROJECT.md` e reconstrução do `docs/` (`$fireskill-documentator`) |

A saída é `Context monitor: CURRENT` quando nada é exigido, ou `Context monitor: PENDING` seguido de uma linha por documento. Opções: `--json`, `--paths <files…>` (verifica uma lista dada em vez do git), `--acknowledge-project-no-change` e `--acknowledge-rules-no-change` (registram que uma revisão não encontrou impacto).

O fluxo roda o monitor no início, depois de cada tarefa de implementação e antes do Delivery Gate. Uma linha `PENDING` bloqueia o fechamento da tarefa.

## Mantenha o contexto vivo

Você raramente edita esses arquivos à mão. Quando algo estrutural mudar, peça ao agente a skill correspondente:

```text
Use $fireskill-aux-stack para monitorar o stack e atualizar .fireskills/STACK.md sem perder dados existentes.
Use $fireskill-aux-rules para revisar mudanças e registrar regras em .fireskills/RULES.md preservando o conteúdo atual.
Use $fireskill-aux-database para monitorar persistência e atualizar .fireskills/DATABASE.md após mudanças de dados.
```

Elas acrescentam ao texto existente e não apagam regras ou linhas que você já escreveu.
