**Skill:** `fireskill-03-specify` · **Faz perguntas:** só quando o brief não basta (devolve para o backlog) · **Cria:** `specs/draft/<NNNN>-<slug>/spec.md`

## Quando usar

O brief da Etapa 2 está pronto, ou você já sabe exatamente o que quer e quer escrever a spec direto.

## O que digitar

```text
Use $fireskill-03-specify para iniciar uma spec numerada no diretório atual e consolidar seus requisitos. Orquestre transições automáticas com anúncio, execução e retomada na mesma conversa.
```

Acrescente embaixo o item de backlog ou uma descrição curta.

## O que o agente faz

1. Roda `fireskills/skills/fireskill-03-specify/scripts/iniciar_spec.mjs --title "<name>"`. O script aloca o próximo número e cria apenas `specs/draft/<NNNN>-<slug>/spec.md` a partir do template.
2. Lê a captura do inbox, o item de backlog, o seu pedido e arquivos reais do repositório que revelem restrições. Se não conseguir identificar problema, ator e resultado, volta para o `$fireskill-02-backlog` e retoma depois.
3. Preenche o template. Mantém a tabela de cabeçalho, os três atos e as 18 seções, numera os itens novos sem reutilizar IDs (`US-001`, `FR-001`, `NFR-001`, `AC-001`, `DEC-001`) e escreve cada requisito como um comportamento verificável.
4. Define **pelo menos três `AC` distintos** para a feature inteira e para cada `US`, `FR` e `NFR`. Um `AC` só conta quando declara o ID na sua linha `**Cobre**`.
5. Para uma entrega com tela (`Interface para pessoas: Sim`), preenche a seção 10 com stack, telas, fluxo de informação, menus, formulários e ações, composição, os componentes Vue e `@nuxt/ui`, estados e acessibilidade. Um CRUD descrito apenas como API e banco de dados não é aceito. Ele carrega `$fireskill-specialist-ux-design`, `-ui-design` e o especialista de interface da stack.
6. Se uma fonte fora do repositório foi consultada, guarda a evidência permitida em `research/` e a indexa na spec.
7. Autoverifica enquanto está em `Draft`:

   ```bash
   node fireskills/skills/fireskill-04-validate/scripts/validate_spec.mjs specs/draft/<NNNN>-<slug>/spec.md --allow-draft
   ```

8. Informa o caminho, o status, as contagens de `US`/`FR`/`NFR`/`AC`, as suposições, e passa a vez para o `$fireskill-04-validate`.

## O cabeçalho da spec (saída real)

```markdown
# Especificação integrada: Convite de membros por e-mail

| Campo | Valor |
| --- | --- |
| Formato | Specsfy/2.0 |
| ID | SPEC-0001 |
| Slug | 0001-convite-de-membros-por-e-mail |
| Status | Draft |
| Effort | 1 |
| Effort updated at | 2026-09-18 |
| Effort rationale | Estimativa inicial; revisar durante a descoberta. |
| Definition Gate | Pending |
| Plan Gate | Pending |
| Delivery Gate | Pending |
| Interface para pessoas | A definir |
```

O cabeçalho deve continuar sendo uma tabela de duas colunas (`Campo` / `Valor`). O slug é igual ao nome do diretório.

## As 18 seções

| Ato | Seções |
|---|---|
| I — Definir | 1 Problema e resultado · 2 Research e esclarecimentos · 3 Escopo e atores · 4 Princípios e restrições · 5 Histórias de usuário · 6 Cenários BDD de aceite · 7 Requisitos |
| II — Projetar e provar | 8 Plano técnico · 9 Modelo de dados · 10 Interfaces e contratos · 11 Estratégia TDD · 12 Plano de testes e rastreabilidade · 13 Validações · 14 Tarefas · 15 Ordem de execução |
| III — Entregar e validar | 16 Dependências, riscos e suposições · 17 Decisões · 18 Definition of Done |

## Effort

Dê à spec uma nota de dificuldade de 1 a 10 (raciocínio e execução necessários, não tempo):

```bash
bun run fireskill effort 0001 4 --reason "tabela + e-mail + mutation tRPC"
```

Saída: `0001-convite-de-membros-por-e-mail	Effort 4/10`. O identificador é o número da spec (`0001`) ou o `<NNNN>-<slug>` completo; um número desconhecido falha com `spec não encontrada`. Veja a [escala de Effort](/docs/fireskills/methodology/effort-scale).
