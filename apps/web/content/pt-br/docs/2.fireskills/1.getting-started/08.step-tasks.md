**Skill:** `fireskill-05-tasks` · **Faz perguntas:** não (volta para o backlog se faltar uma decisão) · **Altera:** as seções 14 e 15 do `spec.md`; move a spec para `specs/planned/`

## Quando usar

A spec tem `Definition Gate: Passed` e está em `specs/defined/`. O fluxo chega aqui sozinho depois da Etapa 4.

## O que digitar

```text
Use $fireskill-05-tasks para preencher tarefas rastreáveis com checklist PREP/EXECUTE/VERIFY/VISUAL/EVIDENCE/IMPROVE em specs/<estado>/<NNNN>-<slug>/spec.md. Orquestre transições automáticas com anúncio, execução e retomada na mesma conversa.
```

## O que o agente faz

1. Exige `Formato: Specsfy/2.0`, `Definition Gate: Passed` e `Status: Defined`. Roda o monitor de contexto e inspeciona a stack, os comandos e os caminhos reais (`layers/*`, `apps/*`) antes de escrever qualquer coisa.
2. Substitui **apenas** as seções `14. Tarefas` e `15. Ordem de execução` do mesmo `spec.md`. Nunca cria um `tasks.md`.
3. Escreve cada tarefa neste formato:

   ```markdown
   - [ ] T001 [TEST] [TDD] [US-001] Derivar teste Vitest do BDD da spec em layers/teams/shared/utils/abilities.test.ts — Refs: FR-002, AC-003 — Depends: none
   - [ ] T002 [CODE] [US-001] Implementar validação em layers/teams/server/trpc/teams.ts — Refs: FR-002, AC-003 — Depends: T001
   ```

   Tags permitidas depois do ID: `[P]` (pode rodar em paralelo), `[TEST]`, `[TDD]`, `[CODE]`, `[DOC]`, `[OPS]`, `[US-NNN]`, e `[MIGRATION]` junto com `[CODE]` ou `[OPS]`.
4. Dá a toda tarefa o mesmo checklist, nesta ordem:

   ```markdown
     - [ ] **PREP**: Confirmar escopo, IDs, dependências e baseline.
     - [ ] **EXECUTE**: Produzir a entrega no caminho declarado.
     - [ ] **VERIFY**: Executar a verificação focal adequada.
     - [ ] **VISUAL**: Conferir bordas, espaçamentos, margens, padding e tipografia do sistema; se não houver interface, registrar `Não aplicável` e o motivo.
     - [ ] **EVIDENCE**: Registrar comando, resultado e IDs nas seções 11–13.
     - [ ] **IMPROVE**: Registrar melhoria aplicada ou ausência justificada.
   ```

5. Aplica as regras que vêm da spec:
   - uma tarefa `[TEST] [TDD]` por `AC`, e toda tarefa `[CODE]` depende do seu predecessor TDD com um RED válido;
   - uma tarefa `[CODE] [MIGRATION]` separada sempre que o schema muda, apontando para um arquivo versionado em `apps/functions/src/database/migrations/` (gerado por `drizzle-kit generate`). O `VERIFY` dela registra dois comandos aprovados pelo `check_database_safety.mjs`: um aplica a migração no banco de **teste**, o outro consulta o estado das migrações;
   - uma tarefa `[DOC]` para `.fireskills/STACK.md` quando manifests ou estrutura mudam, e para `.fireskills/DATABASE.md` quando o banco muda;
   - para uma tela: tarefas para cada tela, menus, formulários e ações, numa subseção `#### Fase de interface`, e uma tarefa que atualiza o `.fireskills/INTERFACE.md`. Toda tarefa que escreve um `.vue` com componentes `U*` lista `$fireskill-specialist-nuxt-ui` no `PREP`.
6. Valida:

   ```bash
   node fireskills/skills/fireskill-05-tasks/scripts/validate_tasks.mjs specs/defined/<NNNN>-<slug>/spec.md --allow-draft
   node fireskills/skills/fireskill-05-tasks/scripts/validate_interface_tasks.mjs specs/defined/<NNNN>-<slug>/spec.md
   ```

   O segundo roda quando a entrega tem tela. Até três ciclos de correção.
7. Enquanto o `Plan Gate: Pending`, passa a vez para o `$fireskill-06-tdd-bdd` no modo `prepare` para escrever o primeiro teste que falha (veja a [Etapa 6](/docs/fireskills/getting-started/step-tdd-bdd)), e depois retoma: `Plan Gate: Passed`, `Status: Planned`, resultado escrito na seção 13, e `bun run fireskill transition <id> planned`.

Se a validação falha, a spec continua `Defined` com `Plan Gate: Failed`, e o agente informa o que a bloqueia.

## Resultado

Um `spec.md` em `specs/planned/<NNNN>-<slug>/` com a lista completa de tarefas, ordenada por dependência, e `Plan Gate: Passed`.
