**Skill:** `fireskill-07-implement` · **Faz perguntas:** não (vai para o `$fireskill-update-spec` se o escopo mudar) · **Altera:** código de produção, testes, os checklists e a evidência do `spec.md`, `.fireskills/*`

## Quando usar

A spec está em `specs/planned/` com `Plan Gate: Passed` e os testes que falham existem. Digite o prompt de novo a cada próxima tarefa, ou deixe o agente seguir em frente.

## O que digitar

```text
Use $fireskill-07-implement para executar o próximo item do checklist em specs/<estado>/<NNNN>-<slug>/spec.md com BDD, TDD e evidência. Orquestre transições automáticas com anúncio, execução e retomada na mesma conversa.
```

## O que o agente faz

**Antes da primeira mudança**

1. Exige `Status: Planned` ou `Implementing`, `Definition Gate: Passed` e `Plan Gate: Passed`. Se faltar um gate ou um RED, volta para o `$fireskill-05-tasks` e não toca em produção.
2. Se há uma tela, verifica se o plano tem tarefas para telas, menus, formulários, ações e componentes `@nuxt/ui`, e carrega o `$fireskill-specialist-nuxt-ui` antes de escrever qualquer `.vue` com componentes `U*`.
3. Confere o comando de teste base com o `check_database_safety.mjs`; sem um banco de teste separado, não roda nenhum teste que toque o banco.
4. Define `Status: Implementing`, `Delivery Gate: In Progress` e roda `bun run fireskill transition <id> in-progress`.
5. Escolhe a próxima tarefa pronta:

   ```bash
   node fireskills/skills/fireskill-07-implement/scripts/next_task.mjs specs/in-progress/<NNNN>-<slug>/spec.md
   ```

**Para cada tarefa** (marcada item por item, nunca em lote no fim)

1. `PREP`: confirma ID, tipo, referências, dependências, arquivos.
2. Carrega o **especialista da área** antes de tocar em código: `nuxt-ui` para `.vue`, `nuxt` para páginas e middleware, `trpc` para routers, `drizzle` para schema e migrações, `nuxt-authorization` para permissões, `openauth` para login, `cloudflare-workers` para Workers, `sst` para `infra/`. A tabela está em `fireskills/SKILL.md`.
3. `EXECUTE`: a menor mudança que deixa o teste TDD verde. Uma tarefa `[CODE]` sem o seu predecessor RED para. Para `[MIGRATION]`, cria primeiro o arquivo versionado, aplica-o no banco de **teste** e consulta o estado.
4. Roda o monitor de contexto; `PENDING` bloqueia a tarefa. Revisa o `.fireskills/PROJECT.md` em qualquer mudança de aplicação.
5. Depois de cada tarefa `[CODE]`, passa a vez para o `$fireskill-documentator` (veja a [Etapa 8](/docs/fireskills/getting-started/step-documentator)).
6. `VERIFY`: teste focal, suíte relacionada e verificações estáticas, só depois que o comando for `SAFE`.
7. `VISUAL`: para uma tela, compara o resultado renderizado com `.fireskills/DESIGNSYSTEM.MD` e `.fireskills/INTERFACE.md`: bordas, espaçamento, margens, padding, tipografia, alinhamento, overflow, foco, conteúdo curto e longo, nos viewports relevantes. Sem tela, escreve `Não aplicável` e o motivo concreto.
8. `EVIDENCE`: registra comando, resultado e IDs nas seções 11–13 (e o comentário JSON `specsfy:evidence` quando `Evidence Contract: 1`, verificado pelo `verify_evidence.mjs`).
9. `IMPROVE`: uma melhoria segura, ou "nenhuma melhoria necessária" com o motivo.

**Se o escopo mudar** (comportamento fora da spec, contradição de um `AC`, interface pública, dados ou segurança): ele para, anuncia e carrega o `$fireskill-update-spec`. Veja [Mudanças tardias](/docs/fireskills/getting-started/late-changes).

## O gate de conclusão

Quando todas as tarefas da seção 14 estão marcadas, o agente roda, e você pode rodar o mesmo:

```bash
# tests of the whole repository (from the repository root)
bun run test

# types (from apps/app)
cd apps/app
bun run typecheck
bunx vue-tsc --noEmit -p server/tsconfig.json
cd ../..

# copy of the context and documentation checks
node fireskills/skills/fireskill-setup/scripts/monitor_context.mjs --project . --check
node fireskills/skills/fireskill-documentator/scripts/build_documentation.mjs --project . --check
```

`bun run typecheck` não existe na raiz do repositório: é um script de `apps/app`.

Depois compara cada `AC`, `FR`, `NFR` e item da Definition of Done com a evidência atual, procura tarefas abertas, placeholders e testes pulados, e só então:

1. `Delivery Gate: Passed`, `Status: Reviewing` e `bun run fireskill transition <id> review`.
2. O `$fireskill-04-validate` faz o aceite final e move a spec para `specs/completed/`.
3. O `$fireskill-progress` mostra o panorama global.

Para obter um resumo que você pode colar num PR (ele só imprime, não escreve arquivo):

```bash
node fireskills/skills/fireskill-07-implement/scripts/render_delivery.mjs specs/review/<NNNN>-<slug>/spec.md --format markdown
```

## O que ele não fará sozinho

- `bun run deploy`. Para mudanças em `apps/functions` ou `layers`, um `sst deploy` real é a verificação que importa, e ele precisa da sua autorização explícita.
- Rodar um teste contra o banco de desenvolvimento, ou qualquer comando destrutivo no banco.
