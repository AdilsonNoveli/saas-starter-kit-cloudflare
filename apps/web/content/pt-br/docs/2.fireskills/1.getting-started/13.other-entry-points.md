Nem tudo começa no inbox. Cada bloco abaixo é um objetivo: o prompt para digitar e o que realmente acontece. Os prompts marcados como *oficiais* são o `default_prompt` da skill (`agents/openai.yaml`).

---

## Ver como as coisas estão

**Digite** (*oficial*):

```text
Use $fireskill-progress para mostrar o progresso geral de todas as especificações. Orquestre transições automáticas com anúncio, execução e retomada na mesma conversa.
```

Ou rode você mesmo:

```bash
bun run fireskill progress
```

Cada spec é impressa com o seu estado e as contagens de tarefas e itens. `--json` dá a saída para máquina, `--watch` imprime de novo quando uma spec muda. A skill também oferece `node fireskills/skills/fireskill-progress/scripts/progress.mjs .` (com `--slug <slug>` para uma única spec) e lê o monitor de contexto e o `build_documentation.mjs --check` para mostrar a documentação pendente. Ela não altera nenhum gate nem checkbox. Um valor de tokens é sempre rotulado `estimated`, a não ser que você forneça o uso medido.

## Conversar sobre uma spec

**Digite** (*oficial*):

```text
Use $fireskill-interviewer para conversar sobre a spec no estado atual e registrar apenas respostas confirmadas.
```

Funciona em specs em `draft`, `defined`, `planned`, `in-progress` e `review`, e direciona a conversa pela pasta (por exemplo, em `defined` procura ambiguidade que afete plano, dados, segurança ou testes). Registra as respostas confirmadas na seção certa e ajusta o Effort. Não aprova gates, não executa tarefas e não move a spec. Não entrevista para mudar uma spec `completed`.

## Decidir o que o produto precisa guardar

**Digite** (*oficial*):

```text
Use $fireskill-data-discovery para conversar em linguagem simples sobre o que o sistema precisa guardar e registrar apenas respostas confirmadas em DATABASE.md.
```

Pergunta em linguagem cotidiana ("O que você precisa lembrar sobre cada pedido, pessoa ou atendimento?", "Quem pode ver ou mudar essa informação?"), propõe uma forma simples de registrar cada item e pede a sua confirmação, e escreve em `.specsfy/DATABASE.md` só as respostas confirmadas. Não escolhe tecnologia. O backlog a chama automaticamente quando a ideia precisa de dados guardados.

## Começar de um documento de MVP

**Digite** (*oficial*):

```text
Use $fireskill-mvp-milestone-interviewer para importar o MVP como M01 e gerar backlogs e specs Draft somente para requisitos de desenvolvimento, sem criar Inboxes nem copiar o contexto de negócio.
```

**Exige um `MVP.md` na raiz do repositório** (não existe nenhum no Nuxfire de fábrica). A skill roda o `importar_mvp.mjs --root <raiz>` uma vez: ele cria `specs/milestones/M01.md` e, para cada item que é uma entrega de software, um item de backlog e uma spec `Draft` com `Definition Gate: Pending`. Visão, público, princípios e métricas ficam só no `MVP.md`. Depois ela entrevista cada item de backlog, perguntando apenas o que o MVP não respondeu.

Depois que o MVP for aceito:

```text
Use $fireskill-roadmap-milestone-interviewer para entrevistar a evolução pós-MVP e propor milestones sem alterar o núcleo aceito sem confirmação.
Use $fireskill-milestone-governor para analisar milestones, manter o índice derivado de specs e backlog e sugerir ajustes confirmáveis.
```

Você também pode atualizar o índice você mesmo: `bun run fireskill milestones sync` atualiza o `specs.md` e o progresso de cada milestone.

## Manter o contexto do projeto atualizado

**Digite** (*oficial*, um por arquivo):

```text
Use $fireskill-aux-stack para monitorar o stack e atualizar .specsfy/STACK.md sem perder dados existentes.
Use $fireskill-aux-rules para revisar mudanças e registrar regras em .specsfy/RULES.md preservando o conteúdo atual.
Use $fireskill-aux-database para monitorar persistência e atualizar .specsfy/DATABASE.md após mudanças de dados.
```

O fluxo as chama quando o monitor pede. Veja [Contexto do Projeto](/docs/fireskills/getting-started/project-context).

## Registrar e reaproveitar lições aprendidas

**Digite** (*oficial*):

```text
Use $fireskill-lessons para registrar uma lição aprendida com sinal, resumo, regra preventiva e origem em .specsfy/LESSONS.md, ou para consultar as lições confirmadas antes de planejar uma fatia.
```

Os comandos que ela usa (você pode rodá-los):

```bash
bun run fireskill lesson add --signal gate_fail --summary "Import relativo no schema" --rule "Importar schemas de layers pelo pacote @nuxfire/*" --source "0042-billing"
bun run fireskill lesson list          # confirmed lessons
bun run fireskill lesson list --all    # plus candidates and quarantined
bun run fireskill lesson status
bun run fireskill lesson prune         # removes expired candidates
```

`--signal` é um entre `ac_gap`, `surviving_mutant`, `spec_precision_gap`, `spec_deviation`, `gate_fail`; `--summary`, `--rule`, `--source` são todos obrigatórios. Uma lição começa como `candidate` e é promovida a `confirmed` automaticamente quando se repete em duas ou mais fontes distintas.

## Atacar uma spec, decidir algo arriscado, revisar uma mudança

Os prompts abaixo são os oficiais (`agents/openai.yaml` de cada skill).

| Objetivo | Digite | O que acontece |
|---|---|---|
| Encontrar premissas frágeis em uma spec (recomendado para Effort 7 ou mais, ou antes de aprovar um Definition Gate crítico) | `Use $fireskill-the-fool para atacar a spec specs/<estado>/<NNNN>-<slug>/spec.md com pre-mortem, steelman da posição oposta e auditoria de premissas não verificadas.` | Pre-mortem, o argumento mais forte contra a decisão, efeitos de segunda ordem, auditoria de premissas não verificadas. Devolve um relatório ordenado por severidade e probabilidade. |
| Decidir uma questão irreversível ou de alto impacto | `Use $fireskill-the-jury para decidir esta questão de alto impacto com um painel de 3 a 5 subagentes, rodada cega, rubrica explícita e veredito com divergência registrada.` | Formula uma pergunta decidível e uma rubrica de 2–4 critérios, cria um painel com papéis ortogonais (proponente, cético, integrador), uma **rodada cega**, deliberação, e depois um veredito vinculante com a divergência registrada. Exige um agente que possa criar subagentes. |
| Revisar um diff ou PR | `Use $fireskill-the-judge para revisar este diff ou PR com citações arquivo:linha, checagens locais primeiro, no máximo 5 nits e veredito APPROVE, COMMENT ou REQUEST_CHANGES.` | Roda primeiro os linters locais, o `vue-tsc` e o Vitest, cita `file:line` em toda afirmação, no máximo 5 nits, e devolve `APPROVE`, `COMMENT` ou `REQUEST_CHANGES`. |
