O estado de uma spec é expresso duas vezes: pela pasta em que ela está e pelo campo `Status` do seu cabeçalho. A CLI mantém os dois em sincronia.

---

## Mapeamento de estados

| Pasta | `Status` | Ato | Definido por |
|---|---|---|---|
| `specs/draft/` | `Draft` | I | `iniciar_spec.mjs` |
| `specs/defined/` | `Defined` | I → II | `$fireskill-04-validate` quando o Definition Gate passa |
| `specs/planned/` | `Planned` | II | `$fireskill-05-tasks` quando o Plan Gate passa |
| `specs/in-progress/` | `Implementing` | III | `$fireskill-07-implement` antes da primeira mudança em produção |
| `specs/review/` | `Reviewing` | III | `$fireskill-07-implement` quando o Delivery Gate passa |
| `specs/completed/` | `Complete` | III | `$fireskill-04-validate`, no aceite final |

---

## O comando de transição

```bash
bun run fireskill transition <NNNN>-<slug> <folder>
```

Por exemplo:

```bash
bun run fireskill transition 0001 defined
```

Saída real: `0001-convite-de-membros-por-e-mail	draft → defined	Defined`.

O que ele faz:

1. Encontra a spec pelo número (`0001`) ou pelo nome completo do diretório (`<NNNN>-<slug>`); um identificador desconhecido falha com `spec não encontrada`.
2. Aceita apenas as movimentações da tabela abaixo; qualquer outra falha com `transição inválida: <de> para <para>`.
3. Reescreve a linha `Status` do `spec.md` e move o pacote inteiro (com o `research/`) para a pasta de destino.
4. Recusa sobrescrever um destino existente.
5. Atualiza o índice de milestones em seguida (o mesmo que `milestones sync`).

O que ele **não** faz: **ele não lê nem verifica os gates.** Uma spec cujo `Definition Gate` está `Pending` pode ser movida para `defined`. Os gates são responsabilidade das skills, que só movem a spec depois que o gate delas passa.

| De | Destinos permitidos |
|---|---|
| `draft` | `defined` |
| `defined` | `draft`, `planned` |
| `planned` | `defined`, `in-progress` |
| `in-progress` | `planned`, `review` |
| `review` | `in-progress`, `completed` |
| `completed` | `review` |

O `bun run fireskill migrate` move specs do layout anterior (`specs/specs/`) para essas pastas, uma única vez.

---

## O que cada estado significa

- **Draft**: a spec está sendo escrita. Problema, atores, requisitos e cenários ainda estão sendo definidos.
- **Defined**: o Definition Gate passou. O escopo está travado para o planejamento.
- **Planned**: o Plan Gate passou. As tarefas existem e os testes falham pelo motivo certo (RED).
- **In progress**: implementação. Os especialistas são carregados, o código é escrito até os testes ficarem verdes (GREEN), as revisões visuais acontecem.
- **Review**: o Delivery Gate passou; o aceite final está pendente. Aqui você pode rodar o `$fireskill-the-judge` no diff.
- **Completed**: aceita. Evidência, documentação e Definition of Done estão registradas.

---

## Voltar atrás

Voltar atrás acontece pelo `$fireskill-update-spec`, que define o status e os gates que a mudança invalida (veja [Gates de Qualidade](/docs/fireskills/methodology/three-gates)) e depois usa as movimentações de volta permitidas acima.
