O Ato I transforma uma ideia em uma spec validada e termina no **Definition Gate**. Cada skill tem uma página passo a passo com o prompt exato para digitar; esta página é a referência.

| Skill | Faz perguntas | Cria ou altera | Página da etapa |
|---|---|---|---|
| `fireskill-01-inbox` | não | `specs/inbox/<AAAA-MM-DD-HHMMSS>-<slug>.md` | [Etapa 1](/docs/fireskills/getting-started/step-inbox) |
| `fireskill-02-backlog` | sim, uma por rodada, até 8 por área | `specs/backlog/<NNNN>-<slug>.md` (`BACKLOG-NNNN`) | [Etapa 2](/docs/fireskills/getting-started/step-backlog) |
| `fireskill-03-specify` | só voltando ao backlog | `specs/draft/<NNNN>-<slug>/spec.md` | [Etapa 3](/docs/fireskills/getting-started/step-specify) |
| `fireskill-04-validate` | só voltando ao backlog | o cabeçalho e a seção 13 da spec; move-a para `specs/defined/` | [Etapa 4](/docs/fireskills/getting-started/step-validate) |

## `fireskill-01-inbox`

Preserva o seu texto palavra por palavra, com um SHA-256 do original e uma análise preliminar dividida em declaração, inferência e a revisar. Recusa salvar se encontrar credenciais, tokens ou dados pessoais evidentes. **Não** inicia a próxima etapa sozinha. Script: `capturar_inbox.mjs --title --input`.

## `fireskill-02-backlog`

Procura duplicatas em inbox, backlog, specs e `docs/`, verifica a captura mínima (problema, pessoa, resultado, contexto), cria o item com o `iniciar_backlog.mjs` e aprofunda as decisões por perguntas numeradas. O arquivo de inbox é só referenciado, nunca movido nem alterado. Status: `Captured`, `Refining`, `Ready for specification`, `Promoted`. Telas acrescentam uma área `Interface`; informação guardada passa a vez para o `$fireskill-data-discovery`. Termina com um *Brief pronto para especificar* e passa a vez para o `$fireskill-03-specify`.

## `fireskill-03-specify`

Cria a spec a partir do template (`iniciar_spec.mjs`), preenche os três atos e as 18 seções, e define pelo menos três `AC` para a feature e para cada `US`, `FR` e `NFR`. Autoverifica com `validate_spec.mjs --allow-draft` e passa a vez para o `$fireskill-04-validate`. Estrutura: [A Spec Canônica](/docs/fireskills/methodology/canonical-spec).

## `fireskill-04-validate`

Roda o `validate_spec.mjs`, faz uma revisão semântica e devolve `READY` ou `NOT READY`. Em `READY`: `Definition Gate: Passed`, `Status: Defined`, `bun run fireskill transition <id> defined`, passa a vez para o `$fireskill-05-tasks`. Em `NOT READY`: `Definition Gate: Failed`, `Status: Draft`, e volta para o `$fireskill-02-backlog`, o `$fireskill-03-specify` ou o `$fireskill-update-spec`. Ela também faz o aceite final no Ato III. A sua verificação do repositório é:

```bash
node fireskills/skills/fireskill-04-validate/scripts/verify_repo.mjs .
```

que valida todas as specs do repositório e o contrato de toda skill `fireskill-*` (cada uma precisa de `SKILL.md` e `agents/openai.yaml`).
