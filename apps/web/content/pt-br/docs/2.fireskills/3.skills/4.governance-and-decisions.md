Além do fluxo linear, estas skills cuidam do contexto, das milestones e da qualidade das decisões. Os prompts para digitar estão em [Outros pontos de entrada](/docs/fireskills/getting-started/other-entry-points).

## Setup e mudança

| Skill | Finalidade |
|---|---|
| `fireskill-setup` | Reconcilia `.specsfy/*` e os blocos reservados de `AGENTS.md`/`CLAUDE.md`, pergunta o seu nível de conhecimento e os assuntos ainda sem resposta, roda o monitor. Toda skill de fluxo o carrega primeiro. [Etapa 0](/docs/fireskills/getting-started/step-setup) |
| `fireskill-update-spec` | Incorpora uma mudança a uma spec que já passou o Definition Gate e reabre só os atos afetados. [Mudanças tardias](/docs/fireskills/getting-started/late-changes) |
| `fireskill-interviewer` | Conversa sobre uma spec em `draft`, `defined`, `planned`, `in-progress` ou `review`; registra as respostas confirmadas e ajusta o Effort. Não aprova gates nem move pastas. |
| `fireskill-data-discovery` | Pergunta em linguagem cotidiana o que o produto precisa guardar e registra as respostas confirmadas em `.specsfy/DATABASE.md`. |

## Milestones

| Skill | Finalidade |
|---|---|
| `fireskill-mvp-milestone-interviewer` | Importa um `MVP.md` (na raiz do repositório) como milestone `M01` e cria itens de backlog e specs `Draft` para os requisitos de desenvolvimento. |
| `fireskill-roadmap-milestone-interviewer` | Depois que o MVP é aceito, entrevista a evolução e propõe milestones pós-MVP sem alterar em silêncio o núcleo aceito. |
| `fireskill-milestone-governor` | Mantém o índice derivado (`specs.md`) e os vínculos das milestones atualizados, e apenas sugere mudanças. |

## Manutenção do contexto

`fireskill-aux-stack` (`.specsfy/STACK.md`), `fireskill-aux-rules` (`.specsfy/RULES.md`) e `fireskill-aux-database` (`.specsfy/DATABASE.md`) acrescentam a esses arquivos sem apagar o que você escreveu. Veja [Contexto do Projeto](/docs/fireskills/getting-started/project-context).

## Lições aprendidas: `fireskill-lessons`

Transforma uma falha real em uma regra preventiva. O estado vive em `.specsfy/lessons.json` (de propriedade do motor) e `.specsfy/LESSONS.md` (playbook lido pelos agentes antes de escrever specs ou tarefas).

| Sinal | Significado |
|---|---|
| `ac_gap` | um critério de aceite não foi coberto ou falhou em produção |
| `surviving_mutant` | um teste continuou passando depois de uma mutação de lógica |
| `spec_precision_gap` | uma ambiguidade na spec levou a uma implementação errada |
| `spec_deviation` | a implementação divergiu do plano ou das convenções |
| `gate_fail` | uma verificação de gate falhou (typecheck, lint, Vitest) |

Uma lição é `candidate` quando registrada pela primeira vez, vira `confirmed` automaticamente quando se repete em duas ou mais fontes distintas, e `quarantined` se se mostrar um falso positivo.

```bash
bun run fireskill lesson add --signal gate_fail --summary "Import relativo no schema" --rule "Importar schemas de layers pelo pacote @nuxfire/*" --source "0042-billing"
bun run fireskill lesson list [--all]
bun run fireskill lesson status
bun run fireskill lesson prune
```

## Decisões e revisão

| Skill | Finalidade | Como funciona |
|---|---|---|
| `fireskill-the-fool` | Revisão adversarial de uma spec, plano ou decisão. Recomendada para Effort 7 ou mais, ou antes de aprovar um Definition Gate crítico. | Pre-mortem, o argumento mais forte da posição oposta, efeitos de segunda ordem, auditoria de premissas não verificadas. |
| `fireskill-the-jury` | Decisão colegiada sobre uma questão irreversível ou de alto impacto. | Cria um painel de 3 a 5 subagentes com papéis ortogonais, uma primeira rodada cega, deliberação, e um veredito vinculante que preserva a divergência. Exige um agente que possa criar subagentes. |
| `fireskill-the-judge` | Revisão de um diff ou pull request. | Primeiro os linters locais, o `vue-tsc` e o Vitest; toda afirmação cita `file:line`; no máximo 5 nits; veredito `APPROVE`, `COMMENT` ou `REQUEST_CHANGES` (blocker, should-fix, nit). |
