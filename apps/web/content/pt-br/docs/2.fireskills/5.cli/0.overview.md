A **CLI Fireskill** faz as partes mecânicas do fluxo: move specs entre estados, registra a nota de esforço, roda um linter rápido de spec, mostra o progresso, sincroniza milestones e gerencia lições aprendidas. O código dela está em `fireskills/cli/` e você a chama a partir da raiz do repositório:

```bash
bun run fireskill <command> [arguments] [options]
bun run fireskill --help
```

O `package.json` da raiz mapeia `fireskill` para `bun fireskills/cli/src/main.ts`. A CLI é derivada da CLI do Specsfy (licença MIT), reduzida ao motor de fluxo: não tem instalador, catálogo nem atualizador, porque as skills e os especialistas já estão no repositório.

## O que saber

- **No fluxo, as skills chamam a CLI por você.** Você a roda para olhar o estado ou para corrigir algo à mão.
- Todo comando aceita `--project <path>` (padrão: o diretório atual) e a maioria aceita `--json`.
- Os comandos de spec identificam uma spec pelo seu número (`0001`) ou pelo nome completo do diretório (`0001-convite-de-membros-por-e-mail`).
- A CLI é escrita em TypeScript com `commander` e precisa do `bun`. Numa cópia limpa, `bun install --cwd fireskills/cli` instala a dependência dela.
- As mudanças de estado são gravadas de forma atômica (um arquivo temporário, depois um rename).
