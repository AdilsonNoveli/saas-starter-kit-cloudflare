Todos os comandos rodam a partir da raiz do repositório como `bun run fireskill <command>`. Opção comum: `--project <path>` (raiz do projeto; o padrão é o diretório atual). A maioria dos comandos também aceita `--json`.

| Comando | Finalidade |
|---|---|
| `transition <id> <folder>` | mover uma spec um passo |
| `effort <id> <1-10> --reason "…"` | definir a nota de esforço |
| `validate <id> [--strict]` | linter rápido do `spec.md` |
| `progress [--json] [--watch] [--interval <s>]` | progresso das specs |
| `milestones sync` | atualizar o `specs.md` e o progresso das milestones |
| `test` | rodar os testes do projeto |
| `lesson add / list / status / prune` | lições aprendidas |
| `migrate` | mover specs do layout antigo |
| `config show / set` | configurações por projeto |

`<id>` é o número da spec (`0001`) ou o nome completo do diretório (`<NNNN>-<slug>`).

---

## `transition`

```bash
bun run fireskill transition <id> <draft|defined|planned|in-progress|review|completed>
```

Move o pacote da spec um passo e reescreve o `Status` (`Draft`, `Defined`, `Planned`, `Implementing`, `Reviewing`, `Complete`). Movimentações permitidas: `draft`→`defined`; `defined`→`draft`/`planned`; `planned`→`defined`/`in-progress`; `in-progress`→`planned`/`review`; `review`→`in-progress`/`completed`; `completed`→`review`. Outras movimentações falham com `transição inválida`.

Depois da movimentação, ele atualiza o índice de milestones (como o `milestones sync`). Ele **não verifica os gates**: as skills só movem uma spec depois que o gate delas passa.

```text
0001-convite-de-membros-por-e-mail	draft → defined	Defined
```

## `effort`

```bash
bun run fireskill effort <id> <1-10> --reason "<rationale>"
```

Define `Effort`, `Effort updated at` (timestamp ISO) e `Effort rationale`. Uma nota fora de 1–10 ou uma justificativa vazia é rejeitada. Saída: `0001-convite-de-membros-por-e-mail	Effort 4/10`.

## `validate`

```bash
bun run fireskill validate <id> [--strict] [--json]
```

Um **linter rápido**, não o Definition Gate. Ele reporta erro para: `Effort` ausente ou fora de 1–10, `Effort rationale` ausente ou curto demais, `Status` ausente, e qualquer uma de cinco seções não encontradas pelo título (contexto/problema, atores/histórias/requisitos/escopo, cenários/BDD/aceite, tarefas/fases, testes/evidência/validação). Avisa sobre a falta de um cenário BDD, a falta de uma lista de tarefas e os placeholders `[TODO]`, `[TBD]`, `[preencher]`, `[em aberto]`, `[descrever]`. `--strict` transforma avisos em erros. O exit code é 1 quando é inválida.

Ele não conta critérios de aceite, não verifica o contrato de interface, não altera gates nem move a spec. O gate é `node fireskills/skills/fireskill-04-validate/scripts/validate_spec.mjs <spec.md>`.

```text
Status: VÁLIDO (Aprovado no linter de specs)
Erros: 0 | Avisos: 0
```

## `progress`

```bash
bun run fireskill progress [--json] [--watch] [--interval <seconds>]
```

Uma linha de resumo e uma linha por spec, com as contagens de tarefas e itens:

```text
Resumo	1 specs	0/6 tarefas	0/55 itens	0%
0001-convite-de-membros-por-e-mail	Draft	0/6 tarefas	0/55 itens	0%
```

`--watch` imprime de novo quando uma spec muda; o intervalo padrão é mostrado pelo `config show` (0,75 s).

## `milestones sync`

```bash
bun run fireskill milestones sync
```

Atualiza os blocos derivados do `specs.md` (raiz do repositório) e de `specs/milestones/<ID>.md`. O texto fora dos blocos é preservado.

## `test`

```bash
bun run fireskill test
```

Roda `bun run test` a partir da raiz do projeto (o agregador Vitest `vitest.config.mts`) e devolve o exit code dele. Não escolhe um banco de dados: veja o [guard de segurança](/docs/fireskills/cli/governance-scripts).

## `lesson`

```bash
bun run fireskill lesson add --signal <signal> --summary "<text>" --rule "<text>" --source "<spec or PR>"
bun run fireskill lesson list [--all]
bun run fireskill lesson status
bun run fireskill lesson prune
```

`--signal` é `ac_gap`, `surviving_mutant`, `spec_precision_gap`, `spec_deviation` ou `gate_fail`; `--signal`, `--summary`, `--rule` e `--source` são todos obrigatórios. `list` mostra as lições confirmadas; `--all` acrescenta as candidatas e as em quarentena. `status` imprime as contagens (`0 confirmadas, 1 candidatas, 0 em quarentena`). `prune` remove as candidatas expiradas. Arquivos: `.fireskills/lessons.json` e `.fireskills/LESSONS.md`. Veja [Governança e decisões](/docs/fireskills/skills/governance-and-decisions).

## `migrate`

```bash
bun run fireskill migrate
```

Uma vez, move as specs do layout anterior (`specs/specs/`) para as pastas de estado.

## `config`

```bash
bun run fireskill config show
bun run fireskill config set --watch-interval <seconds>
```

`show` imprime `project` e `watch_interval` (padrão `0.75`). `set` altera o intervalo do watch.
