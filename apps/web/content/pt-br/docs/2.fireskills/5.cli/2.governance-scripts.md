São scripts das skills (em `fireskills/skills/`), rodados com `node`. O fluxo os roda por você; você também pode rodá-los.

---

## Monitor de contexto: `monitor_context.mjs`

```bash
node fireskills/skills/fireskill-setup/scripts/monitor_context.mjs --project . --check
```

Olha os arquivos que você alterou e ainda não commitou (`git diff`, staged e não rastreados; ele ignora `_docs/`, `fireskills/`, os arquivos de contexto e os arquivos de teste) e lista qual documento de `.fireskills/*` cada mudança exige. As regras e a tabela completa estão em [Contexto do Projeto](/docs/fireskills/getting-started/project-context).

A saída é `Context monitor: CURRENT`, ou `Context monitor: PENDING` seguido de uma linha por documento, por exemplo:

```text
- .fireskills/DATABASE.md via $fireskill-aux-database: persistência alterada (apps/functions/src/database/migrations/0001_x.sql)
```

Opções: `--json`, `--paths <files…>`, `--acknowledge-project-no-change`, `--acknowledge-rules-no-change`. O fluxo trata `PENDING` como um bloqueio para fechar uma tarefa e para o Delivery Gate.

## Guard do banco de dados: `check_database_safety.mjs`

```bash
node fireskills/skills/fireskill-setup/scripts/check_database_safety.mjs --project . --command "<command to check>"
```

Classifica um comando antes de o fluxo executá-lo. `SAFE` deixa rodar. Comandos destrutivos são classificados como `IGNORED` e nunca são executados, **mesmo que você aprove**:

- `drizzle-kit push --force`, `drizzle-kit drop`
- `migrate:fresh`, `migrate:refresh`, `migrate:reset`, `migrate:rollback`
- `db:wipe`, `schema:drop`, `prisma migrate reset`
- `DROP DATABASE`, `DROP SCHEMA`, `DROP TABLE`, `TRUNCATE`
- `RefreshDatabase`, `DatabaseMigrations` e equivalentes

Testes que tocam o PostgreSQL também precisam de um banco de teste diferente do que está nos secrets do stage (`DATABASE_HOST`, `DATABASE_NAME`…). Enquanto essa separação não estiver provada, nenhum teste assim roda. Os 131 testes Vitest existentes (billing, assentos de equipe, abilities) substituem o `useDB` e não tocam um banco de dados. Testes que de fato precisam de um banco usam uma transação revertida ou fixtures limitadas ao caso.

## Verificação do repositório: `verify_repo.mjs`

```bash
node fireskills/skills/fireskill-04-validate/scripts/verify_repo.mjs .
```

Valida toda spec em `specs/` com os scripts dos Atos I a III e verifica o contrato de toda skill `fireskill-*`: `SKILL.md` com um `name` correspondente, um `agents/openai.yaml`, menos de 500 linhas, e as contagens esperadas de skills base e auxiliares. Imprime `Specsfy verify: PASSED` ou `FAILED`.
