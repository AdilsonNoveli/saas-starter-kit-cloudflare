# Compatibility with GitHub Spec Kit

- Official source: [`github/spec-kit` repository](https://github.com/github/spec-kit).
- Verified against [upgrade guide](https://github.com/github/spec-kit/blob/main/docs/upgrade.md).
- Adaptation: read-only projection generated by `fireskill-setup`.

## Detection

The presence of `.specify/memory/constitution.md` activates integration. Setup reads this constitution and recursively traverses regular files in `specs/`, including `spec.md`, `plan.md`, `tasks.md`, contracts, data models, guides, research, and slice attachments.

## Specsfy Projection

Setup writes `.fireskills/SPECKIT.md`. The block delimited by `specsfy:speckit` indexes path, type, title, and SHA-256 for each source. Human notes outside the block remain untouched across executions.

The projection guides agents to inspect original files. It does not duplicate normative contents, convert features to native Specsfy format, or authorize implementation.

## Preservation and Coexistence

Setup never writes, moves, renames, or deletes files in `.specify/` or `specs/`. Existing artifacts remain governed by GitHub Spec Kit. A new feature may follow native Specsfy workflows without modifying prior features.

The constitution remains primary project governance. If a constitutional rule conflicts with `.fireskills/RULES.md` or Specsfy workflows, document both rules and request clarification before proceeding.
