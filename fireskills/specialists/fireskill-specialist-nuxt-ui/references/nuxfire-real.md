# @nuxt/ui in Nuxfire — What Actually Exists in the Codebase

Each statement below includes its concrete file evidence. If the codebase changes,
the code supersedes this document: re-read the referenced file before taking action.

## 1. Installation and CSS Pipeline

| Fact | Evidence |
|---|---|
| Dependency `@nuxt/ui` `^4.8.1` (installed: 4.11.0) | `apps/app/package.json`, `node_modules/@nuxt/ui/package.json` |
| Module loaded via `modules: ["@nuxt/ui", ...]` | `apps/app/nuxt.config.ts` |
| `<UApp>` wraps everything, with `ConfirmDialog` mounted once inside it | `apps/app/app/app.vue` |
| Mandatory order in CSS: `tailwindcss` → `@nuxt/ui` → `@nuxfire/tokens/theme.css` | `apps/app/app/assets/css/main.css` |
| Icons: `i-lucide-*` (`lucide` collection); custom SVGs via `nuxt-svgo` with prefix `icon`, resolved from `~/assets/icons` | `apps/app/nuxt.config.ts` (`svgo`) |
| Fonts via `@nuxt/fonts` (Montserrat/Google in `nuxt.config`; Geist declared in `theme.css`) | `apps/app/nuxt.config.ts`, `packages/tokens/theme.css` |
| Generated component themes (slots, variants) in `apps/app/.nuxt/ui/<component>.ts` | directory generated by `nuxt prepare` / `dev` |

`theme.css` comes **after** `@import "@nuxt/ui"` by deliberate design: overrides
must supersede Nuxt UI defaults. Inverting this order breaks theming.

## 2. Where Theme Resides (Single Source of Truth: `packages/tokens`)

- **`packages/tokens/index.ts` → `sharedUiConfig`**: `app.config.ts` snippet,
  spread into `ui: { ...sharedUiConfig }` (`apps/app/app/app.config.ts`).
  Active keys: `icons`, `colors`, `button`, `card`, `avatar`,
  `dashboardSidebar`, `navigationMenu`, `tabs`.
- **Semantic Colors**: `primary: "flame"`, `secondary: "fire"`,
  `success: "green"`, `info: "blue"`, `warning: "amber"`, `error: "red"`,
  `neutral: "night"`. The `flame`, `fire`, and `night` palettes are defined in
  `theme.css` (`@theme static`).
- **`packages/tokens/theme.css`**: palettes, `--font-sans`/`--font-mono`,
  `--ui-radius: 0.1875rem`, and mappings `--ui-bg*`, `--ui-border*`,
  `--ui-text*` for light mode (`:root`) and dark mode (`.dark`).
- **`@source "./index.ts";` in `theme.css`** is mandatory: the package enters the app
  via `node_modules` symlinks, which Tailwind does not scan by default. Without this line,
  classes present only in `index.ts` render to DOM without compiled CSS rules.
- **Do not redeclare tokens** in an app's local `main.css`: tokens defined in
  `theme.css` apply globally across all apps (`app`, `web`, `login`).

### tailwind-variants Rule that Caused Previous Bugs

**Variant** classes are applied after **slot** classes. A global `slots.root` is
silently discarded when the active variant defines the identical property
(this occurred with `bg-elevated` on `UCard`). Thus the card override in
`sharedUiConfig.card` is declared on the **variant**, not in `slots`. When
customizing a component globally, configure the variant it actively uses and
verify in the rendered DOM that the class applied.

## 3. Tables: `enterpriseTableUi`

- Exported by `@nuxfire/tokens` and passed via `:ui` (instance props supersede
  global configuration). Deliberately not wrapped in `sharedUiConfig.table`.
- Three call sites: `layers/admin/app/components/admin/AdminDataTable.vue`
  (extends with `EDGE_GUTTER` and `cursor-pointer` when row navigates),
  `apps/app/app/components/team-dashboard/TeamDashboardActivity.vue`, and
  `layers/admin/app/pages/admin/index.vue`.
- New table: `<UTable :data :columns :ui="enterpriseTableUi" />`. Need variations?
  Spread the object and append only the modified key (following the `AdminDataTable.vue`
  pattern: `{ ...enterpriseTableUi, td: enterpriseTableUi.td + " …" }`) rather than copying raw classes.

## 4. UI Patterns in Active Use

**Dashboard Layout** — `apps/app/app/layouts/dashboard.vue`:
`UDashboardGroup` > `UDashboardSidebar` (`collapsible`, `resizable`) with
`UNavigationMenu` (`orientation="vertical"`, `tooltip`, `popover`) in body and
footer, and `<slot />` for pages. Each page uses `UDashboardPanel` +
`UDashboardNavbar` (with `UDashboardSidebarCollapse` in the `#leading` slot).
Admin layout resides in `layers/admin/app/layouts/admin.vue`.
Footer navigation uses the **same** `UNavigationMenu` as the body — hand-written
buttons previously diverged from `navigationMenu` tokens.

**Modal with Form** — `layers/teams/app/components/TeamCreateModal.vue`:
`UModal v-model:open` with `#content` containing `UForm` > `UCard`
(`#header`/`#footer`), `UFormField name=…` + `UInput`, `zod` schema in
`:schema`, `reactive` in `:state`, `:validate-on="['input']"`, `useToast()`
(legacy; project standard is `useNotification()`), and `useTrpcClient()` for mutation.

**Confirmations** — do not mount per-page confirmation modals. Use
`useNotification().confirm({ title, description, color })` and await the
boolean result; the single `ConfirmDialog` lives in `app.vue`
(`apps/app/app/components/ConfirmDialog.vue`,
`apps/app/app/composables/use-notification.ts`).

**Shortcuts** — `defineShortcuts` in `apps/app/app/composables/use-dashboard.ts`.

## 6. What is NOT in Active Use Today (Do Not Assume Existence)

- `useOverlay()`: 0 usages in `layers/` and `apps/app/app/`. Exists in Nuxt UI and
  can be adopted, but confirmations already have a designated solution (see §4).
- `locale` on `<UApp>` and `@nuxt/ui/locale` locales: 0 usages. Project i18n is
  handled via `@nuxtjs/i18n` (en, pt-BR, es); bridging the two is a new decision,
  not an existing pattern.
- MCP Server `https://ui.nuxt.com/mcp`: not configured anywhere in the repository.
- Dependencies for **chat** recipes (Vercel AI SDK, `@comark/*`) and **editor**
  recipes (TipTap): absent from all project `package.json` files.
  `references/layouts/chat.md` and `editor.md` describe upstream Nuxt UI capabilities,
  not Nuxfire capabilities — adding them requires explicit approval.
- Raw palette classes (`text-gray-500`, `bg-red-600`…) in `.vue` files within
  `layers/` and `apps/app/app/`: 0 occurrences. Keep it that way.
