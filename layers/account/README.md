# `@nuxfire/layer-account`

The person's own account: profile and profile picture, appearance, other
sessions, account deletion, and the user MFA enrolment, challenge and recovery
codes. Extracted from `apps/app` by SPEC-0009 (Fase 3a) with no change to any
route, tRPC path or component tag.

## Activation

Core, not toggleable. Registered last in `layers.core` of the root `config.ts`:

```typescript
export const layers = {
  core: ["teams", "notifications", "admin", "account"],
  features: { kanban: true, billing: true },
};
```

## Migration history

The layer owns its own history since SPEC-0010: `drizzle.config.ts` (tracking
table `__drizzle_migrations_account`), `server/database/schema.ts` and
`migrations/0000_account.sql`, generated by `drizzle-kit generate` from this
directory. It creates `UserPreference`, `UserSession` and `EmailChangeRequest`,
each `userId` referencing `User` with `ON DELETE CASCADE`. The deploy loop in
`infra/utils/nuxt.ts` finds it without any edit, and the barrel
`apps/functions/src/database/schema.ts` re-exports the schema. The other tables
this layer reads and writes (`User`, `MfaRecoveryCode`, and the teams and
notifications rows removed by `deleteAccount`) belong to other histories.
Changing a table means editing the `0000_account.sql` init and resetting the
database, per the database change policy in `.fireskills/RULES.md`.

## Conventions that are not optional

- **Component folders stay nested.** The tag comes from the folder plus the
  file name, so `account/`, `avatar/` and `settings/` keep the names other
  layers render (`layers/admin`, `layers/teams`, `layers/billing`,
  `layers/kanban`, `layers/notifications`).
- **Other layers import the recovery-code functions by subpath**,
  `@nuxfire/layer-account/server/utils/mfa-recovery`, never through Nitro's
  auto-import. The pure half (generation, format, keyed hash) lives in
  `@nuxfire/crypto`.
- **`useDB()` in `server/utils/mfa-recovery.ts` stays the Nitro global**, so the
  tests stub it with `vi.stubGlobal`. The router and the routes import the
  Composition Root helpers explicitly: `~~/server/trpc/trpc`,
  `~~/server/utils/db`, `~~/server/utils/audit-log` and `~~/server/utils/auth`.
- **Rate limits go through the app's single wrapper**,
  `~~/server/utils/rate-limit` (the only place that ties `@nuxfire/rate-limit`
  to the NuxtHub KV), with the same keys and rules as before the move.
- **`server/trpc/account.ts` imports the root `config.ts` by relative path**:
  Nitro does not resolve the `#nuxfire/config` tsconfig alias.
- **`/account-settings/notifications` is a child page from
  `layers/notifications`**, nested under this layer's `account-settings.vue` by
  file name.
